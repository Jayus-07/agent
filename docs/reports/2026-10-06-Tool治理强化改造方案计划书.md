# Tool 治理强化改造方案计划书

> 日期：2026-10-06 ｜ 状态：待开工 ｜ 拍板：五项全包 / D5 新增 confirmation 帧 / 分级确认
> 关联：`docs/reports/2026-10-05-路由层企业级改造验收清单.md`（路由层已收口）、治理平面 M1-M7（`docs/2026-09-30-企业级治理技术债修复台账.md`）

## §1 背景与问题定义

Tool 层既有治理（契约 lock M1 / 错误七分类 M3 / 审批门 / 四层校验管线）骨架已企业级，但按 2026-10-06 逐项查码，存在五个缺口：

| # | 缺口 | 代码证据 | 用户可见后果 |
|---|---|---|---|
| G1 | 参数 Schema 不严：`minLength/maxLength/minimum/maximum/pattern` 零实现；`array` 类型声明了但 `PARAM_TYPE_CHECKS` 无对应项→运行时跳过类型检查；未声明键不拦 | `backend/skills/base.py:69-116`、`backend/orchestration/tool_schema.py:29-37` | 超长参数、越界数值、错误结构数组全部流入 Tool 内部才报错，报错粒度取决于各 Tool 自觉 |
| G2 | 意图契合门缺失：`_validate_selection` 只拦「非法」（候选外/域冲突），不拦「合法但次优」；单候选时模型拒绝调用仍 passthrough 硬执行首项 | `backend/orchestration/graph/tool_selector.py:270-286, 485-492` | 同域选错工具（如问分析却去爬数据）无拦截；模型明确认为候选都不合适时照样执行 |
| G3 | 无工具级限流/熔断：LLM 有代理限流（`infra/llm`），Tool 层零限流零熔断；同 capability 单请求可打满 supervisor 10 轮；上游持续 429/宕机时带重试继续打 | `backend/core/tool_runtime/executor.py`（仅预算/超时，无计数/熔断） | 上游被打挂、单请求重复调用浪费、故障放大 |
| G4 | 空数据/畸形放行：`{"results":[]}` 结构合法语义放行；text 模式只要非空且无失败前缀即通过；structured 输出只保证「是 dict」不校验结构 | `backend/skills/validation.py:282-356` | 「查到 0 条」被当正常结果长篇输出；截断 JSON/断裂 Markdown 流入 Reporter |
| G5 | 副作用确认非对话内：审批门强制（`TOOL_APPROVAL_MODE=required` 默认）但确认人是管理员；审批单 `detail` 自由文本无「操作预览/原因/影响范围」结构；用户在对话里只见一句「需要人工审批后执行」 | `backend/security/tool_approval.py`、`backend/tools/{email,export,data_collection,competitor,agently}.py` | 发起用户无预览无确认交互；影响范围不透明 |

**目标形态一句话**：在既有「参数校验→意图选型→执行→结果校验→副作用审批」链路上补齐五道闸（D1-D5），全部复用扩展既有落点、声明式默认零行为变化、三态开关灰度。

## §2 总体设计

```
用户 query
   │
   ▼
RoutingEngine（domain→intent→capability 候选）          ← 已有，未知意图→clarify
   │
   ▼
tool_selector：FC 决策
   ├─ D2 意图契合门   fit: match|no_match（no_match 一律 clarify，含单候选）
   ├─ 参数校验        ← 已有三项硬校验
   └─ D1 Schema 强化  minLength/maxLength/min/max/pattern + array 补查
   │
   ▼
SafeToolExecutor（唯一扩展落点，不新建层）
   ├─ D3a per-capability 单请求计数（默认≤3）+ 同参指纹去重 30s TTL
   ├─ D3b 单请求总调用上限（默认≤12）
   ├─ D3c per-tool 滑动窗口熔断（跨请求）
   └─ 已有：请求预算门 / 双层超时 / 有界重试
   │
   ▼
Skill 边界四层校验
   └─ D4 空数据/畸形收口：empty_result 声明 + 业务空检测 + 降级显性化
   │
   ▼
副作用工具（5 个）
   └─ D5 确认升级：impact 结构化预览 → 对话内 confirmation 帧
        ├─ risk_level=low/medium：发起用户对话内确认即执行
        └─ risk_level=high：用户确认 + 管理员审批双门
```

**设计原则**（遵守 AGENTS.md 铁律）：
1. **复用扩展不新建**——只动 5 个既有落点：`tool_schema.py` / `tool_selector.py` / `core/tool_runtime/executor.py` / `skills/validation.py` / `security/tool_approval.py`；不新增治理层、不加 Agent。
2. **G2 单一事实源**——一切新声明（长度/范围/intent_hints/empty_result/risk_level）只写在 `capabilities.yaml`，lock 生成器（`gen_tool_contract_lock`）同步派生新字段（不参与 content_hash，同 `display_name` 先例），禁止第二处手抄。
3. **默认零行为变化**——D1/D4 全部声明式：capability 不声明新键 = 行为与今天完全一致；D3 上限走 env 可调且默认值宽松；D2/D5 走三态开关默认 off。
4. **三态开关先例**——风险项（D2/D5）`off/audit/enforce`（同 `PROMPT_RELEASE_RAGAS_GATE_ENABLED` 先例），audit 只记录不拦截，误拦率达标后再 enforce。

## §3 改造项详情

### D1 参数 Schema 强化

| 项 | 内容 |
|---|---|
| 目标 | 参数校验从「类型+必填+enum」扩展为标准 JSON Schema 约束子集 |
| 设计 | `capabilities.yaml` params_schema 支持 5 个标准键：`minLength`/`maxLength`（string）/`minimum`/`maximum`（number）/`pattern`（string 正则）；`PARAM_TYPE_CHECKS` 补 `array: (list, tuple)`；`validate_params()` 增加对应检查（bool-int 特判语义保持） |
| 落点 | `backend/skills/base.py::validate_params` + `PARAM_TYPE_CHECKS`；`backend/orchestration/tool_schema.py` 视图透传（FC 侧模型可见约束）；`backend/scripts/gen_tool_contract_lock.py` 派生新键进 lock |
| 开关 | 无需开关（声明式：不声明不生效） |
| 兼容性 | 存量 17 capability 零声明零变化；`array` 补查是修 bug，需全量回归确认无存量误拦（如有则该能力先显式声明 type 修正） |
| 验收 | 新增单测覆盖 5 键 × 通过/拒绝 ×边界；`test_registry_consistency` 等四件套全绿；lock 重生成 IN_SYNC；planner 评估不回归 |
| 回滚 | revert 即可，无数据迁移 |

### D2 意图契合门

| 项 | 内容 |
|---|---|
| 目标 | FC 决策从「只拦非法」升级为「非法必拦 + 契合度分级」；消灭单候选 passthrough 硬执行 |
| 设计 | ①FC system prompt 要求模型输出 `fit: "match"\|"no_match"` + 一句话理由（`fit_reason`）；`no_match` 时**不分单多候选一律 clarify**（复用 `_clarify_selection`，新增 reason=`fc_no_match`）；②`capabilities.yaml` 每能力新增可选 `intent_hints: {applies: [...], not_applies: [...]}`（各 2-3 条），拼入 FC prompt 作选型依据；③副作用工具（risk_level 非空）进审批门前加意图对齐预检：query 不含该操作诉求语义时直接不建审批单，降级为 clarify |
| 落点 | `backend/orchestration/graph/tool_selector.py`（FC prompt + 解析 + 单候选分流）；`backend/orchestration/router/capabilities.yaml`；`backend/scripts/gen_tool_contract_lock.py` |
| 开关 | `TOOL_INTENT_FIT_GATE` = off（默认）/ audit / enforce |
| 兼容性 | off 态零变化；audit 态只记 `agent_tool_fit_reject_total{capability, verdict}` 指标不改行为；enforce 后 no_match 走 clarify（用户多一轮问答，不是失败） |
| 验收 | audit 态跑 `pr_smoke` + `ci_golden` 评测集，no_match 误报率 <5% 才允许 enforce；e2e 新增「同域选错工具」「模型拒绝候选」两条 F-* 用例锁行为；`tests/orchestration/graph/` selector 用例扩展 |
| 回滚 | 开关回 off；FC prompt 变更独立提交便于 revert |

### D3 调用预算与熔断

| 项 | 内容 |
|---|---|
| 目标 | 单请求重复调用有界、同参不重复打、上游故障不放大 |
| 设计 | ①**per-capability 计数**：request_context 增加 `tool_call_counts`，executor `run()` 入口 +1，超 `TOOL_CALL_CAP_PER_CAPABILITY`（默认 3）返回结构化错误封套 `{"status":"failed","error":{"code":"tool_call_budget_exhausted"}}`（走 business_error 七分类），不静默；②**同参去重**：capability+参数稳定序列化指纹，进程内 TTL 30s 结果缓存（收编旅游页 Tool 缓存为治理层通用能力，命中标记 `cache_hit` 不重复计次数）；③**总调用上限**：`TOOL_CALL_CAP_PER_REQUEST`（默认 12），超限该 step 标 failed 并发 `SUPERVISOR_TOOL_BUDGET` 风格 alert；④**熔断器**：per-tool 滑动窗口（60s 内 ≥`TOOL_BREAKER_MIN_CALLS`=5 次且失败率 ≥80% → open 30s），open 期快速失败 `provider_error` 不打上游，半开单次试探，成功关闭；状态暴露 `agent_tool_breaker_state{tool}` gauge |
| 落点 | `backend/core/tool_runtime/executor.py`（计数/去重/熔断全部在治理层 run 管线内）；`backend/observability/metrics.py`（新 counter/gauge） |
| 开关 | `TOOL_CALL_BUDGET_ENABLED`（默认 **on**，纯增量）/ `TOOL_BREAKER_ENABLED`（默认 **on**）；阈值 env 可调 |
| 兼容性 | 默认上限（3/12）高于现存所有合法 DAG 的实际调用数（需先跑评测集实测 P99 调用分布定标，写入实施批）；去重指纹排除带时间戳参数（同 tool_approval 指纹纪律：detail 只含稳定字段） |
| 验收 | 单测：计数超限/去重命中/熔断三态迁移（closed→open→half-open→closed）；e2e 故障注入新增「上游持续 429 → 熔断 open → 恢复」；实机 `agent_tool_calls_total` 与计数一致性对账；39 Tool 全量回归零行为变化 |
| 回滚 | 开关回退即关；无持久化状态（熔断窗口进程内存态，重启即清） |

### D4 空数据与畸形收口

| 项 | 内容 |
|---|---|
| 目标 | 「查到 0 条」不再被当正常结果编造输出；降级对用户可见 |
| 设计 | ①`capabilities.yaml` capability 新增可选 `empty_result: {expected: bool, action: "degrade"\|"fail"}`；`expected:false` 时 `validate_semantics` 按声明结果键（`results/items/list/data` 优先级探测）判业务空：`degrade`=产出显式「未查到数据」语义标记给 Reporter（禁止编造内容，Reply 注明原因），`fail`=ValidationFailure 进失败链路；②text 输出可选 `min_length` 声明（报告类），低于阈值判畸形；③**降级显性化**：executor `fallback_used` 事件冒泡到 done 帧 `reply_source` 语义码（并轨《回复呈现规范提案》，不单做前端） |
| 落点 | `backend/skills/validation.py::validate_semantics`；`backend/agents/reporter/`（空结果话术）；done 帧扩展点与 reply_source 提案共用 |
| 开关 | 无需开关（声明式）；`empty_result` 不声明的 capability 零变化 |
| 兼容性 | 首批只为 3-5 个真实会空的 capability 声明（`travel.poi_search`、`sql.query`、`web_search` 等），回放评测集确认话术改善且无假拦截；「查不到」vs「查不了」口径沿用现状（NOT_FOUND vs UPSTREAM_UNAVAILABLE） |
| 验收 | 回放评测集对比空结果回复（从编造→明确告知）；`semantic_validation_total{layer, result}` 指标复用观测；e2e 新增空结果用例 |
| 回滚 | 删除 yaml 声明即回 |

### D5 副作用确认升级（拍板：新增 confirmation 帧 + 分级确认）

| 项 | 内容 |
|---|---|
| 目标 | 发起用户在对话内看到「操作预览/操作原因/影响范围」并确认执行；分级风控 |
| 设计 | ①**impact 结构化**：审批单新增 `impact` JSONB 字段 + 三段式 schema：`{preview: 做什么, reason: 为什么（LLM 从 query 生成）, impact: {target 对象, scope 范围, volume 预计量级, destination 落点}}`；5 个副作用工具统一填写，缺失 fail-fast（副作用工具不填 impact 视为契约缺陷，启动期 lock 校验拦截）；②**风险分级**：capabilities.yaml 副作用能力新增 `risk_level: low\|medium\|high`（**未声明默认 high**，fail-safe）；分级策略：low/medium = 用户对话内确认即执行；high = 用户确认后仍需管理员审批（双门）；③**confirmation SSE 帧**：`event_schema.py` 契约新增 `confirmation` AUX 帧（中段出现，载荷 `{confirmation_id, tool_name, action, risk_level, preview, reason, impact, expires_at}`），**帧后本轮收口**（done，reply 注明等待确认）——SSE 流内不挂起等确认；用户确认/取消走下一轮消息携带 `confirmation_id`（参照客服域 `uq_cs_confirmations` 语义指纹模式：confirm/cancel 判重、exclude 自身、TTL 过期）；④确认即执行 = 对 `consume_approved` 的对话内通道：low/medium 用户确认写审批单 approved（reviewer=发起人，来源标记 `user_confirm`），同指纹放行；high 用户确认只把单据置 `user_confirmed` 待管理员终审 |
| 落点 | `backend/orchestration/graph/event_schema.py` + `backend/shared/`（ConfirmationPayload 契约）；`backend/security/tool_approval.py`（impact 字段 + user_confirm 通道）；5 个副作用 Tool（impact 填充）；`backend/skills/base.py`（副作用前置拦截点改产出 confirmation 帧）；前端 `frontend/src` 新增 ConfirmationCard（参照 HandoffCard 先例：AUX 帧渲染 + 点击埋点） |
| 开关 | `TOOL_CONFIRM_CARD_ENABLED` = off（默认）/ audit / enforce；off 态维持现状「需要人工审批后执行」话术走管理员审批 |
| 兼容性 | confirmation 是 AUX 帧新增，中段任意位置出现不破坏帧序（`tests/test_sse_event_schema.py` 回归门必过）；存量审批单无 impact 字段——只约束新单，存量按 detail 展示；` clarification` 帧语义不动 |
| 验收 | event_schema 回归门全绿；前端 `npx tsc --noEmit` + 组件测试；e2e：low 风险确认即执行全链 / high 双门链 / 取消 / TTL 过期 / 重复确认判重 五条；审计核对 `ai.tool_approval_requests` reviewer 来源标记 |
| 回滚 | 开关回 off（帧不再发出，前端卡片自然不渲染）；approval 表新增列可空，回滚无迁移风险 |

## §4 实施计划

```
批次一 D3 预算+熔断 ──► 批次二 D1 Schema + D4 空数据 ──► 批次三 D2 意图门 ──► 批次四 D5 确认升级
（纯增量，先行）        （声明式默认兼容）                （动 FC prompt，         （动 SSE 契约+前端，
                                                          audit→enforce）          工作量最大）
```

| 批次 | 内容 | 前置依赖 | 验收门 |
|---|---|---|---|
| 一 | D3 四件（计数/去重/总上限/熔断）+ 指标 | 评测集实测调用分布 P99 → 定标上限 | 单测 + e2e 故障注入 + 39 Tool 回归零变化 |
| 二 | D1 五键 + array 补查 + lock 派生；D4 empty_result 声明 + 首批 3-5 能力 | 批次一合入（executor 指纹设施复用） | 四件套 + lock IN_SYNC + planner 评估 + 空结果回放对比 |
| 三 | D2 FC prompt + fit 解析 + intent_hints + 高风险意图预检 | 批次二合入（yaml 扩展机制就绪） | audit 跑 `pr_smoke`+`ci_golden` 误报率 <5% → 才允许 enforce |
| 四 | D5 impact schema + 分级 + confirmation 帧 + ConfirmationCard | 批次一合入（审批单/指纹设施就绪） | event_schema 回归门 + 前端 tsc/测试 + e2e 五条链 |

每批独立提交、独立可回滚；批次三/四合入前须实机走查（容器 rebuild 后实机验证，遵守「引用闭环+单测绿 ≠ 路由真跑通」教训）。

## §5 验收与观测

**新增指标**：
- `agent_tool_fit_reject_total{capability, verdict}`（D2 audit/enforce 拦截）
- `agent_tool_call_budget_total{capability, reason=per_cap\|per_request\|dedup_hit}`（D3）
- `agent_tool_breaker_state{tool}` gauge（0=closed 1=half-open 2=open）（D3）
- `agent_confirmation_total{tool, risk_level, action=confirmed\|cancelled\|expired}`（D5）

**e2e 新用例**（`datasets/e2e/cases.jsonl` F-* 惯例）：同域选错工具 / 模型拒绝候选 / 上游持续 429 熔断 / 空结果话术 / 确认即执行 / 双门审批 / 确认过期。

**实机验证场景**：批次一后打上游断网观察熔断开启与恢复；批次四后本机跑 low/high 两条副作用链核对审批单审计字段。

## §6 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| D2 误拦（该调不调） | audit 三态先行，误报率 <5% 才 enforce；no_match 落 clarify 不是失败，用户可重述 | 开关回 off |
| D3 上限定低误伤合法 DAG | 实施批先实测调用分布定标；上限 env 可调；超限走结构化错误可观测 | 开关回退 |
| D5 契约变更破坏前端 | AUX 帧不进终帧序；event_schema 回归门 + 前端灰度（off 不发帧） | 开关回 off，存量列可空 |
| 全局 | 所有改动声明式/开关式，默认零行为变化 | 每批独立 revert |

## §7 开关汇总

| 开关 | 默认 | 建议 enforce 时机 |
|---|---|---|
| `TOOL_CALL_BUDGET_ENABLED` | on | 直接生效（上限定标后） |
| `TOOL_BREAKER_ENABLED` | on | 直接生效 |
| `TOOL_INTENT_FIT_GATE` | off | audit ≥1 周 + 误报 <5% |
| `TOOL_CONFIRM_CARD_ENABLED` | off | 前端上线后 audit ≥3 天 |

无不可逆数据迁移；全部开关回退即回到现状。
