# 客服域迁移批次报告 —— B1（无界挂起修复）+ B2（评测 CLI 补 cs）

> 日期：2026-09-29 ｜ 基线：cc55ebb（B0 三文档）｜ 计划：`docs/reports/2026-09-29-客服域迁移执行计划-差异与批次.md`

## B1：消除投诉路径无界挂起（差异点 D1）— 提交 8b0546e

**问题（审计 §7.2）**：`complaint_service._llm_assess` 用 `config={"timeout"}` 限时——该参数在当前 ChatOpenAI 版本实测不生效（仓库三处注释在案，supervisor L3 已因此改线程级限时，唯独此处漏改）；且 complaint/query/handoff 三个专家节点调 `run_expert_safely` 未传 `timeout_s`（knowledge/action 有 60s）。规则 0 命中走 LLM 兜底时，投诉路径存在无界挂起窗口。

**改动（四文件 + 两测试，纯加固无行为分支）**：
1. `backend/customer_service/service/complaint_service.py`：`_llm_assess` 换 `sync_call_with_timeout(llm.invoke, CS_COMPLAINT_LLM_TIMEOUT_MS/1000, ...)`——与 supervisor.py L3 同款范式；超时抛 `TimeoutError` 被 except 捕获 → 返回 None（确定性回退规则结果，语义不变）。
2. `backend/customer_service/experts/{complaint,query,handoff}.py`：三节点补 `timeout_s=CS_EXPERT_TIMEOUT_S`（与 knowledge/action 同口径，默认 60s），专家内任一环节挂起时整节点有上界；THREAD_ISOLATED 超时走 `status=timeout`，三节点后处理均 `.get()` 安全访问（已核）。

**回归测试**：
- 新增 `test_llm_cascade.py::test_llm_hang_returns_none_within_timeout`：LLM 挂死（sleep 2s）+ 超时压到 300ms → 断言 1.5s 内返回 None；
- 新增 `tests/customer_service/test_expert_node_timeout.py`：三节点参数化——`execute_*` 挂死 + 限时压到 0.3s → 断言 1.5s 内 `status=timeout` 且进入 `expert_history`（Supervisor 循环检测依赖）。

**验证证据**：定向 5 文件 54 条全绿；**CS 域全量 `pytest tests/customer_service/` 1016 passed / 0 failed（610s）**。

**回滚**：revert 8b0546e（无开关——纯上界加固，不改变正常路径行为）。

## B2：评测 CLI choices 补 "cs"（差异点 D2）— 提交 b428da7

**问题（审计 §4.3/§8.8）**：`backend/evaluation/cli.py` 位置参数 `module` 的 argparse choices 缺 `"cs"`，而 runner 注册表已注册（`runners/cs.py` register_runner("cs", needs_live=False)）——CLI 跑 cs 模块直接 argparse 报错，评测门禁只能绕行 pytest/编程式调用。

**改动**：choices 插入 `"cs"` + help 注明 offline sanity / --live 两档语义。runner 与数据集零改动。

**验证证据**：
- CLI 实跑 `python -m backend.evaluation cs`（offline）：**320/320 通过（smoke 8/8 + core 312/312，阈值 95%/85% 达标）**，报告落 `data/eval_runs/`（gitignored）；
- 门禁测试 `test_cs_runner_v2.py + test_cli_registry_bootstrap.py`：3 passed。

**回滚**：revert b428da7。
