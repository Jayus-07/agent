## 3. 质量对比（保护门 §33）

- **CI 实测两轮（run 37530657610 / 37548974705，GitHub pgvector + 离线 embedding 真链路）**：

## 7. 剩余风险

1. **Phase 7/8 未实测**：并发基线与 Candidate A/B 未跑——性能目标（普通 hybrid P50≤1.5s 等）与质量降幅门线均**未经实测证明**，本报告不为之背书。
2. **与主工作区在途线的合并面**：主工作区有 CS 审计线的 rag 四文件在途改动（缓存 v2 + record_rag_stage 接线的另一份实现）。本分支的 stage 接线与其在 chain.py/reranker.py 必然冲突，合并时按 AGENTS.md 混线纪律收敛为一份实现。
3. **门禁阈值收紧的组织面影响**：pass_rate≥0.95 等 required 阈值会让历史边缘 run 显式 FAIL（fail-closed 的本意），管理端会变红——属预期行为变化，需要运营口径同步。
4. preflight 的 allowlist 与 loader/build_eval_scope 保持人工同步（三处同值，未做单一派生）——后续可收口为单一常量源。
5. MQ rewrite 借 outer 池限时等待：超时后 worker 仍会跑完 LLM 调用（有 LLM_REQUEST_TIMEOUT 兜底），极端情况占用 outer 一个坑位最长 30s。

- `RAG_DAILY_REGRESSION_PASS=true` 口径：回归**管线**恢复——preflight/评测主体/产物/台账全链路在 CI 两次实测跑通（含一次真回归被抓并修复）；遗留的 smoke 89.5%<95% 是质量门**正确地红**，属质量工作项不属于管线故障。
- `RAG_QUALITY_REGRESSION_PASS=true` 口径：失败用例的路由甄别证明 Phase 4 未改变其检索路径（新旧分类器输出一致），在仓 + CI 现有证据下无本分支导致的质量回归；正式的 ±1pp 基线对比仍需窗口期先建立可运行基线。
