1. **多会话并行**：工作区在 `feat/domain-isolation-closure`（另一会话的多域隔离线）。开工先 `git status` + `git branch --show-current` + `git log --oneline -5` 甄别。你的提交若落在 feat 分支，用临时 worktree cherry-pick 到 main（本会话做法：`git worktree add /d/tmp/main-ff main && cd /d/tmp/main-ff && git cherry-pick <sha> && git worktree remove --force`）。
2. **提交双路径限定**：`git add -A -- <paths>` + `git commit -m "..." -- <paths>`；脏文件（data/quality_records/、data/*.json、根目录 `0`、gui-test-screenshots/）是用户/其他会话的，**不得 reset/checkout/clean/覆盖**。
3. **构建网络（fake-ip）**：本机代理 fake-ip 劫持 DNS——构建容器对国外域名（deb.debian.org/pypi.org/download.pytorch.org）全不可路由，国内域名 DIRECT 可达。**构建必须带 `--build-arg DEBIAN_MIRROR=mirrors.aliyun.com --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/`**，否则 apt/pip 层 exit 100。
4. **绝不 taskkill com.docker.* 进程**：本会话强杀卡死的 `com.docker.build.exe` 导致 **Docker Desktop 整体崩溃**（全栈宕机）。构建卡死的安全处置：看日志是否真挂死（10 分钟无新行）→ 杀 nohup 的 shell 父进程（`taskkill //F //PID <bash pid>`）→ 不行就让 pip 自己超时重试；最坏情况重启 Docker Desktop 后 buildkit 缓存仍在（apt 层不用重下）。Docker Desktop 崩溃恢复后 Exited(255) 容器需手动 `docker start`。
5. **MSYS 路径转换**：Git Bash 里容器路径必须双斜杠（`//opt/venv/bin/python`、`//tmp/...`、`//app`）；`--output /tmp/x` 会被转成 Windows Temp 写到宿主。探针脚本在宿主跑、docker cp 进容器跑时用 `docker exec <c> sh -c "cd /app && PYTHONPATH=/app /opt/venv/bin/python ..."`。
