### A1 市内公交候选（验收 #41，估 0.5~1 天）

**需求**：行程相邻两点之间，除现有「驾车/步行」主路线外，提供**公交/地铁方案作为候选参考**。

**现状与关键事实（已核实）**：
- 腾讯路线 API 四模式全支持：`infra/lbs/api.py` ROUTE_MODES = ("driving", "walking", "bicycling", "transit")，route 入口已带 mode 参数。
- `tools/travel/live_map.py::live_leg` 注释明确：transit **不作默认路线**——腾讯公交结果是「步行+地铁+公交」多段拼接，duration 含候车时间，与打车/自驾口径混用会让行程单前后不一致。**这是设计边界不是缺陷**。
- 主路线计算：`travel/services/transit_service.py::estimate_leg`（远期日期强制本地估算，is_estimate 语义冻结）。

**设计边界（遵守）**：
1. 公交是**候选展示**，不改主路线口径、不重排时间轴、不动 is_estimate 语义；
2. 每段 TransitLeg 增加 `transit_option`（可选字段，向后兼容）：{duration_min, distance_m, summary（如「地铁1号线 → 步行 300m」）, is_estimate}；腾讯失败/远期日期 → 字段缺省，前端不显示；
3. 前端行程 legs 的「换一条路线」或展开区展示公交候选（复用 M2 换一家的交互风格）；不阻塞主时间轴渲染。

**实施提示**：`infra/lbs/api.py` route 函数透传 mode="transit"（entry 已支持）；`tools/travel/live_map.py` 新增 `live_leg_transit()`（共享缓存，pcache.build_key 加 mode）；`transit_service.schedule_day` 主循环**不变**，公交候选在 legs 组装处旁路补充（best-effort，失败静默跳过——与 prefetch_day_legs 同款纪律）。

**验收**：实机规划一次（短途段），行程 legs 展开可见公交候选且主时间轴口径不变；接口失败时行程照常（降级无候选）；单测：transit 响应解析/失败降级两例；`tests/travel/` 全绿 + 实机走查截图归档 D:/tmp/travel-a2/。

### A2 分类候选表 UI（验收 #10，估 1~1.5 天）

**需求**：旅游页左栏提供「景点/美食/酒店」分类候选列表 + 一键换入（换入走既有代发草案管线，落 canvas_replace 决策留痕）。

**现状与关键事实（已核实）**：
- 候选池在后端 state（poi_service.retrieve_candidates 产出，带 category/rating/reason/source），**目前没有独立下发前端的端点**——前端只拿到「换一家商户 preview」（tool.result preview）与 RationaleCard 说明文字。
- 前端已有可复用件：TaskSidebar（travel 模式=历史规划列表，page.tsx:219）；「换一家」弹层交互（ItineraryView.tsx，含 #102 旧版标记）；决策留痕 recordTravelDecision（src/api/travel.ts）。
- 候选数据新鲜度口径：候选池随重排失效（跨轮基底自愈已修）；候选表必须带 plan_version 标记（复用 #102 的旧版标记模式）。

**设计要点**：
1. 后端新增 `GET /api/travel/candidates?conversation_id=`（从最新行程版本关联的候选池取——注意候选池不在 plan_store 里，核对 graph_state.candidates 的持久化通路；若 checkpoint 不可达则返回空列表+提示，**不伪造**）；响应按 category 分组 + 每项 {name, rating, reason, source, poi_id}；权限对齐 plans 端点（user_id scope）。
2. 前端左栏（TaskSidebar travel 模式或其下方）加候选区：四类 tab（景点/美食/酒店，交通无候选数据不显示）+ 列表 + 「换入」按钮；换入 = recordTravelDecision(canvas_replace) + chatRef.send 代发（与画布换一家同一条管线，零新逻辑）。
3. 换入按钮在草案生成中/禁用态（generating）时置灰；候选表标题带当前 plan_version。

**验收**：实机出单后左栏可见分类候选；换入一家 → 草案卡出现 → 应用 → decision 落 canvas_replace（GET /api/travel/decisions 核对）；空候选/旧版本场景如实展示。tsc 0 错 + vitest travel 组件绿 + 后端候选端点单测。
