### 2.2 依赖方向（单向，无环）

```
slot_filler.py（节点+兼容入口）──→ agents/requirement_agent.py ──→ services/requirement_service.py
        │                                    │                          ↑
        ├──→ core/intent_signals.py          └── poi_seed / models.brief ┘（agents→services 合法向下）
        └──→ graph_state / config.travel（现状不变）
orchestration 层 lazy import ──→ travel.slot_filler（经 re-export，路径不变）
```

- **agents → services 单向**：`KNOWN_MAJOR_CITIES` 与 `filter_city_names` 是 merge_brief（service）与抽取器（agents）的**共享件**，放 service 层（下层），agents 向下引用——避免 service→agents 反向。
- service.fingerprint **包装** `graph_state.brief_fingerprint`（G2：不复制指纹逻辑，单一事实源不变）。

### 2.3 三个关键边界裁决（需确认）

1. **is_avoid_patch_query 不进 core/intent_signals.py，真身留在 slot_filler.py**。原因：它内部调用 `extract_avoid`（avoid 抽取，将在 agents 层）——搬进 core 会造成 core→agents 反向依赖，违反 Phase 1 底座纪律（core 只被上层 import）。它是"抽取+信号优先级"的复合判定，不是自包含信号；Phase 5 pending-approval 收编时随 avoid 通道一起归位。**迁移范围 = 三分之二**（is_new_run / is_cancel 进 core，自包含零依赖）。
2. **extract_brief 兼容组合器留在 slot_filler.py**：`extract_brief(message, previous) = agent.extract_fresh_brief(...) + service.merge_brief(...)`——旧测试（test_p0_mvp/test_scenarios 直接调它）零改动，组合逻辑一眼可见。
3. **节点名与节点注册完全不动**：`travel_slot_filler` 节点名、graph_builder import 路径、test_agent_inventory 断言全部原样；Phase 2 只换实现住址与职责边界，不换门牌。

### 2.4 LLM 扩展接口（惰性预留，不接配置）

```python
class RequirementAgent:
    def llm_supplement(self, message: str, missing_slots: list[str]) -> dict | None:
        """预留扩展位（Phase 2 冻结：确定性优先，禁止任何 LLM 调用）。
        未来接入时：仅当规则层 required 槽缺失/低置信才允许触发；单 run ≤1 次；
        禁止重试；失败必须回落规则结果+追问；LLM 不得写业务状态。
        当前恒返回 None，等价于「无 LLM」，提取流程不调用本方法。"""
        return None
```

不加 `TRAVEL_REQUIREMENT_LLM_ENABLED`（用户明令）；不 import 任何 LLM 客户端；契约测试静态断言模块无 langchain/openai/deepseek/httpx import + 抽取确定性（同输入两次结果逐字段相等）。

### 2.5 Memory 边界（Phase 2 零扩展）

- 预填/回写代码留在节点体，时机与软失败纪律逐字不变；**preferences 表 schema 零变更**。
- 边界即契约：长期 memory 只存稳定偏好（origin/preferences/pace/diet 四类，现状已如此）；**一次性 TripBrief 字段（destination/days/start_date/budget_cny/must_go/avoid/lodging）绝不进入 upsert**——契约测试用 spy store 行为断言（§四.3）。
