## 修改内容

### A1 市内公交候选（#41）

- **契约**：`travel/models/itinerary.py` 新增 `TransitOption`（duration_min/distance_m/summary/is_estimate）；`TransitLeg.transit_option` 可选字段（缺省 None=无候选，向后兼容旧 checkpoint）。
- **取数**：`tools/travel/live_map.py` 新增 `live_leg_transit()`（共享 `_LEG_CACHE`，缓存键加 mode 维度防主路线/候选混键）+ `peek_leg_transit()`（只读缓存，排程组装处专用，绝不在组装循环等网络）。`infra/lbs/api.py::direction` 归一化补 transit 段结构（mode/lines：vehicle/title/上下车站/站数——实测腾讯 transit steps 与 driving 结构不同，无 instruction，线路信息在 `lines[]`）。
- **排程旁路**：`transit_service.schedule_day` 主循环不变，legs 组装处 best-effort 附加（远期日期 is_far_trip 拦截/miss/异常一律无候选）；`prefetch_day_legs` 并发预热 transit 段（与主路线同池同预算纪律；**实机 bug 修复：prefetch_legs 复用给 transit 时缓存命中检查必须用 transit 键维度，否则被主路线 main 键误判「已有缓存」全部跳过——容器内复现 prefetch 0.46s 空 Return 后修复**）。
- **前端**：LegRow 交通段「公交 ▴」展开钮 + 展开区乘坐摘要（如「步行 738m → 地铁1号线（东街口 → 南门兜） → 步行 975m 约35分钟（含候车，供参考）」），不阻塞主时间轴。
- 提交：A1 代码被并行会话收编进 `472e736`+`e1621c8`（内容经逐文件核对为最终版，含两处实机修复）；本会话补交走查脚本（随后续 docs/脚本提交）。
