# 爬虫语料 → RAG 入库全流程手册（2026-10-04 实测沉淀版）

> 覆盖：travel-crawler 爬取 → 清洗 → 人工确认 → 装配 → 上传 → 索引 → 检索验证
> 每一步都有实机踩坑记录，坑与处置见 §6。

## 0. 全流程总览

```
┌─ 阶段① 爬取 ─────┐  ┌─ 阶段② 确认 ──┐  ┌─ 阶段③ 装配 ────┐
│ travel-crawler GUI│→│ 待确认表格     │→│ polish 抛光      │
│ 自动发现/手动队列  │  │ 人工勾选入库   │  │ prune 复审       │
│ robots门/相关性闸门│  │ (质量把关点)   │  │ build 两份合档    │
└──────────────────┘  └───────────────┘  │ SPEC_CHECK 自检  │
                                          └────────┬────────┘
┌─ 阶段⑥ 验证 ─────────┐  ┌─ 阶段⑤ 索引 ─┐  ┌─ 阶段④ 上传 ────┐
│ chunks 接口非空       │←│ Celery 队列   │←│ Bearer+X-API-Key │
│ retrieve 检索四连     │  │ worker 11 步  │  │ kb_id+department │
│ FINAL PASS 判定       │  │ /readyz 权威  │  │ 指纹/墓碑规避     │
└──────────────────────┘  └──────────────┘  └─────────────────┘
```

## 1. 阶段① 爬取（travel-crawler GUI，人工触发）

**启动**：`travel-crawler\dist\travel-crawler\travel-crawler.exe`（或开发态 `python main.py`）。

**旅游语料**（文档采集页）：
- **自动发现模式（推荐）**：城市名（如「杭州」）+ 勾选「自动发现」→ 开始。worker 自动三段：
  1. 维基导游城市档（游客视角全页，category=city）
  2. 维基百科城市条目档（概述+旅游章节摘录，category=city）
  3. 百科旅游章节锚定发现 POI → 逐个抓（按来源章节自动 attraction/food）
- **手动模式**：多行 URL 队列（维基词条 URL），城市+类目下拉选择。
- 每页自动过四道闸：**robots 门**（拒爬跳过）→ **相关性闸门**（跑题丢弃，
  `config.json keep_titles` 白名单捞误杀如「于山」）→ **150 字过短跳过** →
  **模板行清洗**（[编辑]/消歧义/Unihan/重定向/引用角标）。
- 文档模式间隔 2~5s（无风控）；电商模式间隔 20~40s、日 40 次/账号（拍板口径）。

**电商语料**（商品采集页，独立分支）：
- 「账号」页扫码登录（滑块/登录窗口置顶抢焦点，人工在环）→ 单抓或清单批量 →
  风控锁定/切号逻辑按拍板口径 → 待确认表格（类目列手填）。

## 2. 阶段② 人工确认（质量把关点，唯一人工环节）

- 抓取结果全部进「商品采集」页待确认表格——**不直接落盘**，逐行看：
  - 相关性闸门的灰区漏网（如「市树」）在此勾掉
  - 类目列填写（导入选品池用，旅游语料跳过）
- 「入库选中」或「入库全部」→ md 写入 `data/export/docs/`
  （文件名 = `城市-类目-标题.md`，日期在文件内容里）
- 全程记录 crawl_log（fetched/failed/too_short/irrelevant/robots_blocked），
  历史全保留，导出页可清。

## 3. 阶段③ 清洗与装配（CLI，三条命令）

```bash
python scripts/polish_docs.py            # 全库抛光（幂等可重跑）
python scripts/prune_docs.py             # 相关性复审（跑题→docs_noise 隔离，不删）
python scripts/build_city_guide.py 杭州      # 精编攻略（一城一档）
python scripts/build_specialty_guide.py 杭州 # 特色指南（美食+特产全量详情）
```

- **polish**：kv 管道行→中文冒号、模板行剔除、坐标前缀剥离、方言罗马音删除。
- **prune**：标题或正文前 1500 字不含城市名 → 移入 `docs_noise/`（可捞回）。
- **build_city_guide**：素材=城市档×2 + 景点/美食词条（cap 800 字/条 + 表格子条目）；
  结构=单 H1「{城市}旅游指南」/## 城市概览置顶/必逛景点/必吃美食/交通与实用信息/避雷贴士；
  **内建 SPEC_CHECK 自检**（H1 唯一/概览置顶/H2≥3/字数/### 完整），PASS 才算产出。
- **build_specialty_guide**：美食 11+特产 4 全量词条（含噪音区 CRAFTS 捞回），
  专接「特色的详情」类查询；与精编攻略互补（概览 vs 详情）。
- 两份产物落在 `data/export/`，各自 {城市}旅游攻略.md / {城市}特色指南.md。

## 4. 阶段④ 上传（upload_and_verify.py）

```bash
python scripts/upload_and_verify.py 杭州
```

- **认证**：`/api/auth/login`（uitest_ragadmin）拿 Bearer + agent 项目 .env 的
  `API_KEY` 作 X-API-Key——**双头缺一 401**。
- **请求**：`POST /api/rag/upload`，multipart `file` + 表单 `kb_id=travel`、
  `department=warehouse`（travel 库既有惯例，doc_type/business_domain 由管线自动抽取）。
- **三个坑与规避**：
  1. 幂等去重按文件指纹短路 → 生成器更新行带 `%Y-%m-%d %H:%M` 时间戳，重生成必变指纹；
  2. 软删墓碑：级联删除后的同名文件不复活 → 需物理删 registry 行再传（或换文件名）；
  3. **新文件名 = 新 doc_id，最干净**（特色指南即此路径）。

## 5. 阶段⑤⑥ 索引就绪与验证（全自动 + 内建验证）

- 上传后 app 投 Celery `rag_index` 队列 → rag-index-worker 11 步：
  load → parser → ocr → semantic_chunk → metadata → metadata_extract →
  question_gen → table_describe → embedding → vector_write → bm25_write
- worker 写共享卷 → rag-service 收发布通知热刷新。
- **就绪权威信号 = rag-service `/readyz` 200**（BM25 与向量集合一致性闸门放行）。
- upload_and_verify.py 内建验证：
  1. chunks 接口（`GET /documents/{doc_id}/chunks`，2026-10-04 已修为读 chunk_store）
     —— 块数>0 且全非空；
  2. 检索四连：`POST /retrieve` 带 `system_subject`（缺则 500），
     每问断言关键词命中；
  3. `FINAL PASS` 判定输出。

## 6. 坑与处置速查（全部实机踩过）

| 症状 | 根因 | 处置 |
|---|---|---|
| 上传后检索 503 | 同名重传 BM25/向量代次差（时序断层） | **再传一次同文件自愈**；等 /readyz |
| 上传 ok 但永远不索引 | 软删墓碑（deleted 行阻止同名复活） | 物理删 `doc_registry` 行再传 |
| 重传秒回 duplicate_of | 幂等按文件指纹短路 | 内容变指纹（时间戳）或换文件名 |
| chunks 接口全空 | ①remote 读错库（已修）②**BuildKit 缓存：Image Built ≠ 新代码进容器** | `--no-cache` 重建；`docker exec grep //app/...` 核对容器内版本 |
| 检索 500 | 缺 `system_subject`（权限显式化新契约） | 请求体补 `system_subject` |
| 检索 401 | 缺 X-API-Key | Bearer + X-API-Key 双头 |
| doc_type 分错 | 文件名无「旅游/攻略」关键词 | 文件名带关键词（如「特色旅游攻略」） |
| 抓回来跑题条目 | 章节锚定的灰区（撞名词目） | 相关性闸门自动丢 + 待确认人工勾 + prune 复审 |

## 7. 一页速查：新城市上线全命令

```bash
# ① 爬取+确认（GUI，人工 ~10 分钟）
travel-crawler.exe → 文档采集 → 勾「自动发现」→ 城市=泉州 → 开始
                    → 待确认表格 → 入库全部
# ② 清洗+装配+上传+验证（CLI，自动 ~5 分钟）
python scripts/polish_docs.py
python scripts/build_city_guide.py 泉州
python scripts/build_specialty_guide.py 泉州
python scripts/upload_and_verify.py 泉州     # 内建 FINAL PASS 判定
```

电商选品线（独立分支）：扫码登录 → 单抓/批量 → 确认入库 → 导出 CSV（增量）
→ agent 管理端「选品漏斗→表格导入」。
