你是本仓库（电商 RAG + Multi-Agent 平台，内含智能客服子系统）的执行会话。目标：按两份已拍板的设计文档推进改造，优先级：**Phase 0（平台止血）未有人做则先做它，否则做 Phase 1（知识供给侧企业化）中与其无重叠的子集**。

4. `docs/reports/2026-10-03-生产就绪修复实施计划.md`——施工书（41 任务卡，Phase 0 止血，含决策门 D1-D7）
5. `docs/reports/2026-10-03-智能客服企业级演进分析.md`——本次蓝图（四阶段路线 + §9 验收项矩阵 C1-C27 + 通用门 G1-G4）

## 二、开工前置检查（先查再动，结果写进基线快照）

1. `git status` + `git log --oneline -10`：记录工作区基线；识别其他会话未提交的线——**绝对不碰、不收编、不回退他人文件**（历史上发生过并行会话代为提交 258 个文件的事故）
2. 甄别施工书执行状态：在 `git diff` 与工作区中检索 P0 相关改动（索引收敛 Job / 监控栈 / TTFT 修复），判断 Phase 0 是否已有会话在做
3. `docker ps -a`：容器健康与版本对账（app 容器构建身份 vs HEAD vs lock）
4. 数据库基线复核（**一律 5433**，`docker port agent-postgres-1` 确认）：跑评审报告 N.2 的 SQL，确认索引覆盖率/拒答率/TTFT 基线是否仍成立（评审时点值：13.1% / 63.5% / 失效）

## 三、执行范围（决策树）

**若 Phase 0 无人开工**：先执行施工书 Phase 0-2（索引收敛 Job、804 积压处置、监控救活、TTFT 修复）。理由：这是拒答率 63.5% 的根因，Phase 1 的验收依赖它。注意：涉及决策门的动作（如 D1 = 799 份测试垃圾清理属不可逆操作）必须停下来向用户确认，不自作主张。

**若 Phase 0 已有会话在做**：做 Phase 1 中与其无重叠的子集，按此顺序（每完成一项即路径限定提交）：

1. **C12 AI 身份告知**：最小改动先热身——开场消息 AI 标识 + 转人工入口常驻
2. **C1/C2 知识生命周期**：draft→in_review→published→deprecated 状态机（fail-closed：未过审核不得 published）+ expires_at 过期 + 流转审计
3. **C7/C8/C10 评测三件套**：意图分诊黄金集 300 条、转人工时机集 50 条、词表变更评测门（热更自动触发评测，坏变更可拦截）
4. **C3/C4 FAQ 双轨**：FAQ 表（question/variants/answer/审核状态/有效期）+ 三段式检索（FAQ 命中直返答案不进 LLM，trace 打 faq_hit 标记，直答 TTFT P95 ≤500ms）
5. **C11 PII 脱敏**：手机号/地址/姓名进 LLM 前占位符替换、回复时还原，脱敏率 100%

C5（FAQ 占比报表）/C6（缺口管道）/C9（拒答定标）与索引修复强耦合，**等 Phase 0 完成后再做**，本次不做。

## 四、子 agent 使用规则（重要）

- **可以并行**（fan-out 提效）：只读侦察、现状盘点、代码审计、文档核对、测试运行
- **必须串行**（主会话单写者）：一切代码修改与 git 提交——子 agent 只读不改；子 agent 结论须主会话复核后才能作为修改依据
- 写操作前先读后写：改前 git diff 确认范围，最小改动，不顺手重构

## 五、红线（违反即返工）

- 不改 `builder.py` 手写节点；域图/Skill 节点走自动发现
- 提交必须双重路径限定：`git add -A -- <paths>` + `git commit -m "..." -- <paths>`；误提交回退只用 `git reset <base>`（mixed），绝不用 `--hard`
- 局部跑 pytest 必须加 `--no-cov`（否则全绿也 EXIT=1）
- 业务代码禁止直接 `os.getenv`；改 Tool/Skill 签名必须 `python -m backend.scripts.gen_tool_contract_lock` 重新生成 lock 随变更提交
- 任何会话跑全量 pytest 期间：不改代码、不动容器（并发冻结纪律）
- 数据库连接显式 5433；见 `localhost:5432` 先怀疑连错库
- 决策门事项（数据清理、SLO 定值、开关默认值变更）必须问用户
- 阶段完成立即提交，不留大批量工作区改动过夜

## 六、验收标准（每个完成的 C 项逐项自验）

- 按演进分析 §9 验收矩阵的口径/目标值/测量方法自验，逐项留证（SQL 输出/截图归档）
- 通用质量门 G1-G4 全过：G1 相关 pytest 全绿（--no-cov）；G2 契约 lock 无漂移；G3 实机留证（不只跑单测）；G4 验收结论七行证据格式：**修改内容 / 影响文件 / 验证命令 / 测试结果 / 未验证项目 / 已知风险 / 回滚方式**
- 回归测试：新功能必带测试，只 mock 外部边界，强断言，必须真实运行

## 七、交付物

1. 代码 + 回归测试，路径限定小步提交（Conventional Commits：feat/fix/refactor/test/docs/chore(scope)）
2. 阶段报告落盘 `docs/reports/<日期>-<主题>.md`，含验收矩阵逐项打勾与证据
3. 若行为变更：同步 AGENTS.md 口径与对应顶级文档
4. 实机验证后更新容器（重建走 devctl.bat / docker compose，脚本化加 `/y`）
