## 二、问题清单

### F-1（P1，上线阻断）旅游页「生成行程」100% 失败，弹开发者向原始报错
- 现象：填好目的地点「生成行程」→ 页面顶部红色横幅 `Converting circular structure to JSON --> starting at object with constructor 'HTMLButtonElement' | property '_reactFiber$...' -> FiberNode ...`；请求从未发出（后端日志零 travel 请求）。截图 `u12_travel_result.png`。
- 根因：`frontend/src/app/travel/page.tsx:731` `onClick={p.onSubmit}` 把 MouseEvent 作为第一个参数传给 `submit(messageOverride?: string)`（:201），`messageOverride ?? composePlanMessage(...)` 短路成 message=MouseEvent → `JSON.stringify({message: MouseEvent})` 在 fetch 前抛循环引用 TypeError，被 catch 后 setError 展示原始报错。
- 修复：一行改 `onClick={() => p.onSubmit()}`。全仓 grep 确认同模式仅此一处。
- 影响：旅游规划表单主入口完全不可用（右侧「旅行助手」抽屉与灵感卡走显式字符串参数，不受影响——未逐一实测）。

### F-2（P2）客服端工单管理页对 agent 坐席裸露技术错误文案
- 现象：agent 坐席打开 /cs/tickets → `GET /api/cs/tickets/admin/list` 403 → 页面红色横幅直书「listTickets failed: 无权执行此操作。」（截图 cs_tickets.png）。
- 问题：①接口权限（admin/list 拒绝 agent 坐席）与页面入口不匹配；②前端把 `listTickets failed: ...` 开发者文案直接展示给用户；③列表恒空。
- 建议：后端按坐席角色收敛可见工单或前端隐藏入口；错误横幅换用户向文案。

### F-3（P3）新会话必现 `GET /api/memory/sessions/{id}/context` 404
- 每次新建会话（/agent、/travel）出现 2~3 次 404（后端 `memory.py:109` 路由存在，语义=新会话尚无上下文记录）。前端已静默容忍不影响功能，但属于用 404 表达空态，网络面板噪音大。建议后端空上下文返 200+空对象或前端降噪。

### F-4（P3）客服端统计页质检日报板块 403 静默降级
- /cs/stats 主统计渲染正常，但 `GET /api/cs/ops/qa/reports` 对 agent 坐席 403 ×2，页面显示「暂无日报数据」空态，无权限提示。与 F-2 同类：入口可见性与接口权限不对齐。

### F-5（P3，未能稳定复现）用户端 travel 页偶发 `GET /api/budgets/me` 401
- 一次出现在 /travel 场景；带新 token 经 BFF 复测 200（预算数据正常返回）。疑似登录瞬间旧 token 竞争，观察项。
