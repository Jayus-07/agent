## 2. 关键机制（现行调用链口径）

### A. 授权（backend/rag/authz.py 唯一裁决出口）
- 四个裁决点：`can_read_document / can_search_kb / can_upload_to / can_manage_document`。
- **admin 口径（钉死测试）**：跨部门读+管理全部**非 test 库**（ROLE_DATA_SCOPE=admin=all 的既有
  语义延伸到文档敏感级）；`permission_scope` 对 admin 不设限；audience=test 库对任何主体不可见。
- 授权异常 → `RagAuthorizationError` → 403 fail-closed，绝不退化为无过滤检索；
  未声明主体在 HTTP 面按空集拒绝（None 仅限服务端内部直调旧行为）。
- 上传 department 只认主体自身部门（admin 可代传任意合法部门），KB ∈ 主体可见集；
  请求体自报部门/KB 只能收窄不能作为授权依据。
- 列表/详情/chunks/pending/统计/KB 列表全部按授权范围过滤，registry `search/list_pending_review`
  新增 `kb_scope/visible_scopes` SQL 下推（**total 与行集同口径**）。
- SSE 订阅绑定上传者（进程内 `_progress_owners` + Redis owner 字段，admin 可代查）；
  done/duplicate 事件 doc 经 `sanitize_doc_row`（file_path/chunk_ids/minhash_sig 不出边界），
  响应 metadata 走白名单。

### B. 候选版本模型与发布协议
- **暂存不可变**：上传写 `{RAG_TMP_DIR}/staging/{upload_id}.{generation}.{ext}`，流式 SHA256；
  Worker 只读暂存；`os.replace` 到正式路径只发生在发布提交点之后。
- **运行记录** `rag_index_runs`（067 迁移；registry 惰性补列 `active_generation`）：upload_id 主键、
  generation 候选代次、base_generation 发布基准、状态机 claimed→indexing→publishing→published/
  failed/superseded（**终态一次写**）。
- **候选隔离**：chunk/doc 向量写 generation 专属 collection（`{main}::cand:{gen}`，id 内嵌
  generation 多代次互不覆盖）；chunk_store 走内存缓冲；BM25 构建
  `{BM25_INDEX_DIR 的同级}/staging-{gen}`，语料 = 主 ∪ 候选 − 旧 chunk_ids（canonical 语义不变）。
- **发布顺序**（全部幂等可续跑）：registry 条件 upsert（`register_published` CAS，**提交点**）→
  候选向量整体晋级主 collection（UPDATE collection）→ BM25 快照切换+PUBLISHED 指针 →
  源文件 replace → chunk_store 翻新 → 财务旧版批量 `is_latest=False`（版本快照保留）→
  旧 chunk 按旧 id 精确删 → doc_version+1 → run=published。
  提交点前失败=候选清理+failed（旧版零触碰）；提交点后失败=保持 publishing 等重投续跑。
- **并发语义**：同逻辑文档任意时刻至多一个发布者——CAS 输者明确 superseded；
  同键同内容重试=同一任务（附着，`duplicate_of` 标记）；同键不同内容=409；无键=每次新任务。
- **崩溃恢复**：Worker 硬杀 → acks_late/tasks 租约重投 → 按运行记录状态续跑，重试不得重复发布
  （published 短路、CAS 兜底）；启动清理跳过非终态运行持有的暂存文件。

### C. BM25 身份与在线刷新
- 条目身份 = doc_id（+vector_id），**basename 匹配废除**（跨 KB 同名互删根源）；
  `META_VERSION 2→3` 触发一次 canonical 重建（生产构建器与 b04d81f 相同：从向量快照全量重建）；
  一致性对账口径改 `{doc_id: chunk_count}`。
- **PUBLISHED.json 发布指针**（build/switch 统一维护，最后写）；检索入口每请求 O(1) 代次检查
  （读指针 JSON，不加载 pickle）→ 代次变化 → 加载新快照并**一次性整组替换**
  `pipeline.bm25 / person_index / lc_chain.bm25 / lc_chain.person_index /
  chunk_retriever_base.{bm25,person_index}`（修复旧实现只换 pipeline.bm25 的半更新）。
- 加载失败 → 保留旧快照 + `is_index_stale` 显式标记（/rag/search 响应 `index_status:"stale"`），
  不静默谎报新版本可检索；发布后 Redis pub/sub 通知加速（漏通知由版本检查兜底）。
- runtime 模式 bundle 版本不符 → 自动 canonical 重建一次（真缺失/损坏仍拒绝启动）。

## 4. 实测发现并当场修复的缺口（非预想清单内）
1. 幂等重放附着**已失败**任务 → SSE 永无终态（`84a7338` 守卫 + duplicate 重发）；
2. PG 幂等账本以裸 `ValueError` 表达冲突未被映射 409（`322f34d`）；
3. remote 代理缺 `is_index_stale` 属性导致 /rag/search 异常路径假阳性（`3eb7451`）；
4. KBRouter 猜错库时放宽重试锁死错误 kb → 三级兜底（`db203dc`，授权由 keep-set 强制）。
