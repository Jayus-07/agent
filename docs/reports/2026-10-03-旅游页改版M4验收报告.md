## 修改内容

**G1 用户决策后端留痕**（migration **072**，071 已双占用顺延）：
- 新表 `travel_decision_audit`（agent_memory 库，`backend/sql/migrations/072_travel_decision_audit.sql`；`scripts/init_db.py::MIGRATION_TARGETS` 已登记 `memory`，init_db --check 体检 rc=0，db-migrate 实跑 `applied`）。
- `travel/core/decision_store.py`：完全照 plan_store 先例——运行时幂等建表双保险、`DECISION_TYPES` 白名单（apply_draft/discard_draft/canvas_replace/tier_switch/budget_negotiate）、读写强制 user_id scope、**软失败**（写失败返回 0 绝不挡 UI）。
- 端点（`app/api/routes/travel.py`，均 `require_identity`）：`POST /api/travel/decisions`（身份/时间戳服务端取，不信任请求体自报；写失败返回 `{"status":"skipped"}` 而非 5xx——审计旁路不是业务门禁）+ `GET /api/travel/decisions?conversation_id=`（决策链新→旧；越权=空列表）。v1 只落库+查询，管理端页不做（拍板口径）。
- 前端五类决策点全部改「先打后端再更新本地」（`recordTravelDecision` 前端同样软失败吞错）：草案应用/放弃（`TravelChatDrawer.applyPending/discardPending`，带触发该草案的 client_run_id）、画布确认替换（`page.handleRequestReplace`，payload 带 day_index/item_title/candidate_name）、档位切换（`page onTierChange`，tier_from→tier_to+话术）、删减协商——缺口卡新增三条快捷协商 chips（`ItineraryView onNegotiateBudget`：「去掉第 N 天」「改成 N-1 天」「预算调到 ¥floor」，复用 M2-h chip 交互；这是必要接线：v1 缺口卡纯文案没有可挂的决策事件）。

**G2 消息↔trace 打通**：`TravelChatDrawer.send()` 既有 clientRunId（`client-<ts>-<rand>`）随请求体上行；`streamTravelPlan/planTravel` 加可选 `clientRunId`；表单通道（page.submit）同样生成并携带。后端 `TravelPlanRequest` 加可选 `client_run_id`，trace 创建后**立即**写 `trace.tags["client_run_id"]`（非收口时——失败轮次同样可审计）。

**G3 修改来源归因**：`send()` 加可选 `source` 参数（类型 `TravelSource`），各调用点带上：RationaleCard/ToolProcessRows 的 onAsk=`card_action`、画布就近唤醒+确认替换=`canvas_action`、档位切换=`tier_switch`、缺口卡协商=`budget_negotiate`、手打/chips/追问=缺省 manual；排队槽与「重新回答」经 ref 保留原始归因；请求体可选 `source` → `trace.tags["travel_source"]`（原样透传不校验枚举，前端口径演进不破后端）。聊天界面不加 trace 入口（拍板：仅管理端/库可查）。

## 实机验收（Playwright + PG 实查，截图 `D:/tmp/travel-m4/`）

- **G1 决策链**：`GET /api/travel/decisions?conversation_id=` 返回留痕记录，五类全部实机落库——tier_switch（economy→comfortable 及回切，带话术 payload）、apply_draft（带 client_run_id）、discard_draft、budget_negotiate（带协商话术）、canvas_replace（payload 带 day_index=1/item_title=午餐/candidate_name=周麻婆…，source=canvas_action）。
- **G2/G3 trace.tags**：`trace_summary.tags` 实查五轮归因全对——`manual`（表单首规划）/`card_action`（商户卡代发轮）/`canvas_action`（换一家确认代发轮）/`tier_switch`/`budget_negotiate`，每轮均带 `client_run_id`。

## 未验证项目

## 已知风险

- 排队槽消息在页面刷新后丢失为 M2-f 既有行为（非本线引入）；M4 的排队归因（queuedSourceRef）同样不跨刷新。
- 「换一家」候选仍来自 preview 缓存（M2 已知口径）；card_action/canvas_action 实机链路依赖商户检索返回非空 preview（依赖高德配额），本轮在全新会话验证通过。
- decision_store 幂等建表与 migration 072 并存：migration 为权威 DDL，运行时建表仅为漏跑兜底（与 plan_store 同模式）。

## 回滚方式

`git revert <本笔提交>`（单笔；前端向后兼容字段与后端可选字段可独立回滚）。表 `travel_decision_audit` 为增量新表，回滚代码即可不停服；如需清表 `DROP TABLE travel_decision_audit;`（agent_memory 库）。db-migrate 镜像如需回退：`docker compose build db-migrate` 随代码回退重建。
