### 关键事实：ToolStatus.DEGRADED 是死状态

全仓 grep：**零生产者**。`ToolResult.ok` 把 DEGRADED 视为成功（models.py:64），但 BaseSkill 成功门只认 `is SUCCESS`（base.py:557）——若未来出现 DEGRADED 结果会掉进失败分支被置 `output=None`（降级但仍可用的数据在 Skill 层被丢弃），且 SSE log 帧无 degraded 分支。降级语义目前实际存活于：RAG 链内部（rerank_degraded/gate passthrough/vector_degraded）、`ToolResult.fallback_used`、travel 域 data_status。本轮处理：BaseSkill 成功门放行 DEGRADED+携带数据并标 degraded=true（STOP A 顺带，语义对齐 models.py 注释），SSE log 帧补 degraded 分支。

## 3. SkillAdapter 问题（P0-1，STOP A）

`orchestration/workflow/skill_adapter.py:35-37` `_extract_output` 只取 `step_results[step_id].get("output", {})`：

- BaseSkill 失败时 sr={status:failed, output:None, tool_status, criticality, error, error_code...} → 适配器返回 `{}` → WorkflowExecutor 看到正常 return → **step success**。
- `if not output: logger.warning` 只告警不放行语义——空 dict 照样当成功返回。
- `call_sql` raw 模式虽上抛 ValueError（不假成功），但丢失 tool_status/error_code 结构，三条路径 parity 断裂。
