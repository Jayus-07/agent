## 3. 需求分析设计

### 3.1 意图分类（★新增，P0）

| 意图 | 规则信号（词典/正则优先） | LLM 兜底 | 出口 |
|---|---|---|---|
| 找目的地 | 无城市 + 「去哪/推荐/短途/周末」 | 候选不确定时 | 城市推荐 |
| 找灵感 | 有城市 + 无「做行程/规划」动词 + 槽位缺 | 同上 | 灵感层 |
| 直接规划 | 「做行程/规划/安排 + 天数」或槽位齐 | 同上 | 直通规划链 |
| 单纯问答 | 「好玩吗/怎么样/值得去吗/有什么吃的」疑问句式 | 同上 | 知识直答 |
| 修改已有 | 会话已有行程 + 「换/改/去掉/加一天」 | 同上 | v2 版本链 |

实现原则：规则词典先行（零成本、可测试），LLM 兜底仅在规则不确定时触发（一次分类调用，与灵感生成的结构化调用合并设计，见 §3.2）；分类失败默认按「找灵感/缺槽」走（最保守出口）。

### 3.2 LLM 调用预算（回应 GPT #9）

| 轮次 | 调用 | 内容 |
|---|---|---|
| 灵感轮 | **≤1 次结构化生成** | 输入=锚定后的灵感摘要+当前 brief；输出 JSON：`{推荐方向[], 下一问(含默认建议), 默认假设[]}`——一次产出启动卡与追问所需全部素材 |
| 规划轮 | 0 次新增 | 规划链本身零 LLM（既有约束不破） |
| 交付轮 | 沿用现状 | 行程亮点由 reporter 从规划结果生成，不新增调用 |
| 意图兜底 | 0~1 次 | 与灵感生成同轮合并或规则置信度足够时为 0 |

### 3.3 「条件足够」新口径（回应 GPT #8）

| 槽位 | 旧口径 | 新口径 |
|---|---|---|
| destination | 必填，缺则追问 | 必填不变（探索型经推荐补齐） |
| days | 必填，缺则追问 | **可空**：给「2 天精华 / 3 天慢游 / 自填」一步选择；用户不选则出通用行程 |
| budget_cny | 必填，缺则追问 | **可空**：标记「未设上限」，预算 Tool 照算并标注 |
| start_date | 可空 | 可空；但**空日期 ⇒ 通用行程**：不查实时班次/票价/天气实况，交付卡明示「通用参考，选定日期后可刷新」 |

## 4. Tool 职责矩阵（每个 Tool 解决什么问题）

### 4.1 数据源分层（回应 GPT #7：灵感与事实分离）

| 层 | Tool/数据源 | 解决的问题 | 触发条件 | 事实边界 |
|---|---|---|---|---|
| 意图层 | 意图分类（规则+LLM 兜底） | 用户这轮想干什么 | 每轮入口 | — |
| 条件层 | Requirement Agent（纯规则） | 槽位抽取与合并 | 每轮 | — |
| **灵感层** | `zhihu_search_tool`（官方 MCP） | 「为什么值得去」：方向、适合人群、玩法视角 | ②找灵感意图；失败不阻塞 | **非事实源**；须锚定 LBS POI 后才可在行程上下文引用 |
| 事实层 | 高德 POI/美食（腾讯 LBS 主） | 地点身份：名称→坐标→可定位；美食店检索 | 灵感锚定 + 规划候选池 | 坐标/类目可信；无房价（诚实口径） |
| 事实层 | `poi_service` 候选池（LBS live） | 规划的景点候选集 | 规划链内 | 同上 |
| 事实层 | 12306 MCP（`TRAIN_MCP_ENABLED`） | 城际火车班次/历时/票价 | **有 origin + destination + 日期才查**（§4.2） | 实时 Provider 实机可用（外部容器）；仅供学习口径；查不到≠查不了 |
| 事实层 | 天气（腾讯 LBS 主+和风备） | 适用日期的天气信息 | **有日期才查实时** | P0 只做信息卡；影响排程 P2 |
| 估算层 | 预算 | 费用估算 | 规划链内；无预算标「未设上限」 | 估算非报价 |
| 校验层 | validator（四轴：时间/地理/体力/预算） | 结构正确性 | 规划后 | 只判不改，error 阻塞交付触发 repair |
| 生成层 | reporter | 行程卡+行程亮点（从结果生成） | 交付 | — |

### 4.2 条件化调度矩阵（★新增，回应 GPT #6）

| 条件 | 跳过 | 交付口径 |
|---|---|---|
| 无 origin / 自驾 / 同城 | 12306 | 交通段标注「未查城际（无出发地/自驾）」 |
| 无 start_date | 12306 实时 + 天气实况 | 通用行程标注「选定日期后可刷新班次与天气」 |
| 无 budget | —（照算） | 预算卡标注「未设上限，以下为估算」 |
| 「不绕路」诉求 | — | 路线优化结果在交付中显式呈现（顺序图/里程对比） |

实现落点：supervisor 既有调度规则表扩充条件项——supervisor 本就是纯规则状态机，符合「协作规则代码管、灵活性模型给」的既定口径。

## 5. 前端交互

### 5.1 灵感卡构成（回应 GPT #7）

每轮**一张主推荐 + 少量备选（≤3）+ 一个关键问题**，防界面过载：

```
┌ 灵感卡 ────────────────────────────────┐
│ 主推荐：鼓浪屿——万国建筑+步行岛，适合慢节奏 │  ← 一句方向（知乎提炼）
│ 适合人群：带老人/拍照/文艺                │
│ ↳ 已锚定 POI：鼓浪屿（LBS，思明区）        │  ← 事实锚点
│ 备选：南普陀寺 · 沙坡尾                   │
│ 来源：知乎《…》 2026-08 · 原文链接         │  ← 灵感溯源（CC 口径注意）
└────────────────────────────────────────┘
下一步：[2 天精华] [3 天慢游] [自己填]        ← 一步选择（GPT #8）
```

### 5.2 启动卡（替代 v1 的「亮点确认门」，回应 GPT #3/#5）

```
┌ 启动卡 ────────────────────────────────┐
│ 已知条件：厦门 · 3 天 · 2 人 · 未设上限    │
│ 默认假设：节奏适中；未说出发地，不查城际     │
│ 待核实：营业时间/票价以规划结果与官方为准    │
│         [ 按这个生成行程 ]   [ 改一改 ]    │
└────────────────────────────────────────┘
```

- 只读规划无副作用，按钮是**启动语义**不是审批语义；强制确认只留给约束冲突（validator error、必去排不进）与未来交易类操作（沿人机边界白名单）。
- 直接规划意图（③）不出现启动卡。

## 6. 开关与降级（修订）

| 开关 | 默认 | 语义 |
|---|---|---|
| `TRAVEL_INSPIRE_ENABLED` | 关 | 灵感层总闸；关=现状行为 |
| `ZHIHU_MCP_ENABLED`（已有） | 关 | key 已配（7129a35），开闸+重启容器即生效 |
| `TRAVEL_INSPIRE_LLM_ENABLED` | 关 | 结构化生成；关=模板追问+无启动卡（齐槽直通不变） |

降级链（修订后语义，回应 GPT #4）：

```
知乎失败/未配 → 跳过灵感层，按槽位状态继续：
    槽位缺 → 模板追问（只问缺的；merge_brief 保证不重复已答）
    槽位够 → 直接出启动卡/直通规划
锚定失败（知乎内容挂不上 LBS POI）→ 灵感卡只展示方向，不进行程引用
LLM 失败 → 模板追问；启动卡素材缺失 → 已知条件照列，默认假设标「待确认」
任何降级不改变意图分类结果，不把检索失败表达成「缺条件」
```
