## 4. 施工项

### P0-1 分布式准入门（多副本全局并发上限）

**现状问题**：`_PriorityGate` 单进程计数，扩 N 副本实际放行 N×上限，准入失真。

**目标**：Redis 全局硬上限（可选租户级上限），快速失败不做分布式等待；进程内 `_PriorityGate` 保留为二级（排队+优先级语义不变）。

**设计**：
- 新文件 `backend/app/api/middleware/distributed_gate.py`，注册在 `concurrency_limit_middleware` **之前**（server.py）。
- 用 Redis **sorted set** 实现槽位：member=request_id，score=获取时间戳。
  - acquire（Lua 脚本原子执行）：`ZREMRANGEBYSCORE` 清理过期（>lease TTL）→ `ZCARD` 判上限 → 未满 `ZADD` 返回 1，已满返回 0；
  - release（finally 必达）：`ZREM`；进程崩溃靠 lease TTL（默认 30s）兜底回收。
- **分工口径**：分布式门 = 硬上限、无等待队列，拒绝即 `503 + Retry-After`；排队与优先级仍由进程内门承担。两层叠加，互不替代。
- 路径分类复用 `concurrency.py` 的 `_HIGH_PRIORITY_PREFIXES` / `_SKIP_PREFIXES`（抽到 `backend/app/api/middleware/path_classes.py` 共享，两边 import，避免两份清单漂移）。
- **故障语义：fail-open**——Redis 不可用时放行 + 记 `dist_gate_unavailable_total` + warning（进程内门仍在兜底，可用性优先）。
- 配置（`backend/config/__init__.py`）：`DIST_CONCURRENCY_ENABLED`（默认 `false`）、`DIST_MAX_CONCURRENT_REQUESTS`（默认 50）、`DIST_GATE_LEASE_TTL_SECONDS`（默认 30）、可选 `DIST_TENANT_MAX_CONCURRENT`（0=不启用，按 JWT tenant claim 限）。

**实施步骤**：
1. 抽 `path_classes.py`，`concurrency.py` 改为 import（行为零变化，独立提交）；
2. 实现 `distributed_gate.py`（Lua 常量 + acquire/release + middleware 函数 + 指标 `dist_gate_active` / `dist_gate_reject_total` / `dist_gate_unavailable_total`）；
3. `server.py` 挂载（开关关时直接放行，无 Redis 访问）；
4. 测试 `backend/tests/test_distributed_gate.py`：mock/fakeredis 单测（上限拒绝、过期回收、fail-open、release 幂等——release 对已过期 member 不报错）。

**验收**：开关关 = 全量 chat 相关存量测试绿、行为零变化；开关开 = 两进程并发总量 ≤ 上限（集成验证：本地起两个 uvicorn 或单测双 client 模拟）；kill 掉持槽进程后 TTL 到期槽位自动回收。

**风险与回滚**：Redis 抖动 → fail-open 已兜底；出问题回滚 = 关开关（零代码回滚）。
**预估**：1~1.5 工作日。

### P1-1 状态键登记守卫（防 LangGraph 剥离未知键）

**现状问题**：节点返回 update 中写了未登记进 schema 的键 → 被 updates 流静默剥离，4 次真实事故均靠排查发现。

**目标**：未登记键在写入点即被发现——log 模式告警，enforce 模式抛错（供测试/预发用）。

**设计**：
- `backend/orchestration/state.py` 新增：
  ```python
  KNOWN_STATE_KEYS: frozenset[str] = (
      frozenset(AgentState.__annotations__)
      | frozenset(OrchestratorState.__annotations__)
  )
  ```
  **由注解派生，禁止手抄键名**（G2）。
- 新函数 `validate_state_update(node_name: str, update: dict) -> list[str]`：返回未知键列表（纯函数，可单测）。
- 接线点：`trace_middleware.wrap_sync_node` 包裹的节点执行完后调用上述函数——发现未知键：`STATE_KEY_GUARD_MODE=log`（默认）记 `state_unknown_key_total{node}` 指标 + warning（点名节点与键）；`enforce` 模式 raise。
- **施工前核实点**：域图节点（builder.py:149 `wf.add_node(domain.node_name, ...)`）是否经过 `wrap_sync_node`。若未经过：把检查同样挂到域图节点注册处，或下沉到 `runner.py::iter_events` 事件流层统一挂钩——两选一，以覆盖全部节点为准。

**实施步骤**：
1. state.py 加派生常量 + 校验函数（独立提交）；
2. trace_middleware 接线 + 指标 + 配置 `STATE_KEY_GUARD_MODE`（默认 `log`）；
3. 核实域图节点覆盖情况并补齐；
4. 测试 `backend/tests/test_state_key_guard.py`：已知键零告警；未知键告警/enforce；**误报检查**——用现有 graph 集成测试跑一轮真实图（含 CS/旅游/选品 prefilter 命中路径），确认零误报；有误报 = 把对应键补进 schema（这是修复不是绕过）。

**验收**：默认 log 模式下全量相关测试绿 + 真实图零误报；enforce 模式单测可触发。

**风险**：域图私有键（cs_route/travel_context 等）若不在两个 TypedDict 注解里会成批误报 → 处理方式是补登记进 schema（正是本项要达到的效果），不接受 exclude 黑名单。

**预估**：0.5~1 工作日。**前置依赖：state.py 的并行未提交改动先落地。**

### P1-3 SSE 执行池观测补齐（原 P0-2 降级后）

**现状问题**：执行池有界可配但无池级指标——容量不足时外部只能看到 503/首字延迟升高，无法定位是池排队。

**设计**：
- `backend/observability/metrics.py` 新增：`chat_sse_executor_active`（Gauge）、`chat_sse_executor_wait_seconds`（Histogram，submit→开始执行）。
- `chat.py::event_generator` 在 `loop.run_in_executor(_executor, producer)` 前后打点（wait = 提交时刻到 producer 首事件时刻，近似即可，避免侵入线程池内部）。
- `config` 补 `CHAT_SSE_MAX_WORKERS` 的文档注释：sizing 口径（workers ≈ 目标 SSE 并发数；排队即背压信号）。

**验收**：并发 10 路流压测（本地 curl 并发即可）能在 /metrics 看到 active 与 wait 分布；单测覆盖指标打点函数。
**预估**：0.5 工作日。

### P1-4 管理端工具统计多副本聚合

**现状问题**：`admin_tools.py:27` 进程内 REGISTRY 直读（代码自注释 `"scope": "process"`），多副本数字不完整。

**设计**：
- **写侧**：`core/tool_runtime/metrics.py::record_tool_result`（全站唯一收口，改动面小）在 `TOOL_STATS_REDIS_ENABLED`（默认 `false`）开启时，向 Redis **fire-and-forget** 写：`HINCRBY tool_stats:{YYYYMMDD} {tool_id}` 字段 `total / ok / <七分类错误码>`，`EXPIRE 8 天`。异常只记 debug 不阻塞工具主流程（该函数现有多层防御风格，保持一致）。

**验收**：开关关行为零变化；`merged` 模式下模拟两进程各打点后管理端读到合计；单测 mock Redis。
**风险**：record_tool_result 在工具执行热路径上 → 必须吞错 + 不 await（Redis 客户端用同步接口 + 极短超时或线程池异步投递）。
