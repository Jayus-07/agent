## 0. 最重要的三个结论

1. **工作区未提交的 v2 线已覆盖 v3 P0-B 的相当一部分**：知乎 MCP 攻略双路检索、前端 GuidePreview 灵感卡、Plan 版本链 7 端点、12306 票价工具、事件流测试，全部已写好但未提交（详见 §2 矩阵）。v3 实施前必须先把 v2 线按路径限定提交落库，否则 v3 的 diff 无法甄别归属。
2. **v3 的核心 delta 是意图层，而意图层今天完全不存在**：slot_filler 纯规则零意图概念（docstring 自认「不判会话意图」）；`SupervisorAction(PLAN/MODIFY/QUERY/BOOK/CANCEL)` 枚举在 `backend/travel/core/actions.py:13-29` 已定义但**零接线**（注释「Phase 6 接线」未做）——这是现成的挂点。
3. **城市覆盖是硬闸**：`extract_destination` 只认种子 3 城（福州/厦门/杭州，`requirement_agent.py:199-232`）；丽江不在种子、不在别名、也不在 `KNOWN_MAJOR_CITIES`（`requirement_service.py:19-33`，西安在列=会得到「暂不支持」明示提醒，丽江连提醒都没有）。**v3 验收矩阵大量用丽江举例，这些场景今天全部不可达**，城市扩容是上线硬前置。

### 1.2 days / start_date / budget 校验

- **days 无静默默认**：`REQUIRED_SLOTS=("destination","days")`（`models/brief.py:18`），`missing_slots()` 判 None 或 <1 → 追问不规划（brief.py:115-126）；全 travel grep 无 `days=3` 类默认；`resolved_days()=max(1,int(days or 1))` 仅为防护（brief.py:140-142）。v3 要求的「缺天数给默认值完整 chip」是纯前端+payload 交互，后端校验已就绪。
- **start_date 可空通用行程已支持**：无日期 → 天气专家前置闸跳过并披露（`experts/weather.py:59-68`）、闭馆日判定因 `day_date is None` 不触发（`validator.py:200`）、置信度扣 0.05（validator.py:532-533）。
- **budget**：None/<=0 → 静默跳过（validator.py:336-338，注释「没说预算≠预算为零」）；超支 → `BUDGET_OVER` error 进修复（343-350）；>90% → warning。v3 要求的「已含/未含/未知项」三态口径**不存在**（CostBreakdown 仅 tickets/meals/lodging/transit+total，`models/itinerary.py:113-125`）。
- 补充：travel 域 validator 是六轴（time/geo/pace/budget/coverage + pool），全纯规则零 IO（`validator.py:63-88`）。

### 1.5 地图/种子池覆盖与约束过滤

- 种子池：`tools/travel/poi_seed.py:33-70` 仅福州 11/厦门 10/杭州 10 条，**坐标声明为示例值**；丽江/西安/泉州零种子。生产默认 `TRAVEL_POI_SOURCE=live`（腾讯 LBS 实时检索，`services/poi_service.py:61-116`），种子仅 fallback（`TRAVEL_POI_FALLBACK_SEED` 默认 false）——即 live 可用时技术上能查任意城市，**但 destination 抽取白名单是硬闸（见 §0.3）**。
- 约束现状：
  - avoid：种子通道硬排除（`tools/travel/poi.py:73-84`）；**live 通道不套 avoid**（`poi_service.py:61-116` 只按偏好词检索）→ 兜底是 validator `PREFERENCE_VIOLATION` warning（只披露不摘除，`validator.py:489-511`）。v3 要求「古城不出现在推荐与规划结果」→ live 通道需补过滤。
  - must_go：三态解析 + unresolved 如实披露 + required 永不静默丢弃（repair `kept_required`，`repair.py:247-252,349-354`）。
  - 同行人：adults/children 只记账不过滤；grep `老人|elderly|轮椅` 在 travel 域零命中——**v3 P0「体力/适老过滤」缺失**。
  - 饮食忌口：`brief.diet` 注释自认「只做记录与持久化，不参与排程判定」（`models/brief.py:63-65`）——**v3 P0「饮食约束进候选过滤」缺失**。
  - 天气冲突：非 validator 违反码，而是 `plan_weather_swaps` 主动替换（required 户外保留并披露，`services/weather_service.py:152-201`）；无日期整体跳过。v3「已知恶劣天气不得承诺户外可行」的口径基本可由 swap+披露满足，承诺话术需对齐。
