## 二、任务卡

### 一期：回归门禁接入发布流程（最高优先级——消灭「总分过线但比生产退化仍可发布」）

**C1-1 回归门接入 Release Gate**（GATE-11）
- 改动：`backend/prompts/release_service.py::record_result` 后增加基线对比步骤——取 `data/baselines/baseline_rag_{dataset_version}.json`（复用 `evaluation/gate/regression.py::diff_baseline`），结果（regression_pass/regression_details）写 release 行 `metrics` JSONB；`publish()` 增加 `regression_pass` 校验，失败 409（fail-closed）。
- 开关：`PROMPT_RELEASE_REGRESSION_GATE_ENABLED`（默认开——企业双门禁语义；存量无 baseline 的 release 跳过并记 `baseline_unavailable`）。
- 验收：无回归→publish 通过；faithfulness 超阈值下降→publish 409 且 failure_reason 含回归明细。

**C1-2 最低样本量门**（GATE-12、DATA-09、DATA-08）
- 改动：suite JSON 支持 `min_samples`/`min_valid_samples`（缺省走全局 `EVAL_MIN_SAMPLES`，默认 8）；`gate/evaluator.py::evaluate_tiers` 增加 sample-count 门：`valid = total - errors - skipped`，不足则 `passed_threshold=False` 且 reasons 注明；阈值随 tier_summaries 快照落盘。
- 验收：2 条样本 100% 通过 → gate 仍 FAIL（reason=样本不足）；pr_smoke 8 条 → PASS。

**C1-3 逐样本回归/提升清单**（REG-03、REG-04）
- 改动：`gate/regression.py` 增加 `diff_samples(current_report, baseline_report)`：按 case_id 对比 status，产出 `regression_samples[]`（原 pass→fail）与 `improvement_samples[]`（fail→pass），进 report.metadata 与 release metrics。
- 验收：构造两份报告（1 条 pass→fail、1 条 fail→pass），清单各含 1 条且带 case_id。

**C1-4 审批页 candidate vs production 对比**（REG-08）
- 改动：`frontend-admin` Prompt 发布审批面板增加对比表——后端复用 `GET /evaluation/prompt-version-runs` 取 production 版本最近 run + candidate release 的 metrics，展示 `current / baseline / delta` 三列（自研指标 + RAGAS）；后端如需汇总端点则加 `GET /prompts/{key}/releases/{id}/comparison`。
- 验收：管理端审批操作前可见对比表；无 baseline 时显示 `baseline unavailable`。

**C1-5 分桶回归检测**（REG-06）
- 改动：`diff_baseline` 增加 buckets 维度对比（report.metadata.buckets 已落盘），任一 domain/difficulty 分桶下降超阈值 → warning/error 分级（复用 critical_metrics 机制）。
- 验收：构造 overall 升高但单 domain 恶化的两份报告 → error 级阻断。

**C1-6 blocked 原因结构化**（GATE-16）
- 改动：release gate 拒绝路径统一产出 `blocked_rules: [{rule, expected, actual, severity}]` 数组（写 failure_reason 同字段 JSONB + API 返回体），管理端渲染规则清单。
- 验收：多规则同挂时 409 响应体含完整规则数组。

**C1-7 RAGAS 门纳入 gate 判定**（GATE-03，双门禁成型）
- 改动：release gate 判定从「tier 全过」扩为 `tier_pass AND ragas_pass`：candidate run 的 report.metadata.ragas_samples.valid 比率 + ragas_* 指标与 `docs` 建议阈值（faithfulness≥0.85 等，阈值进 release 快照）；RAGAS 未执行/不可用 → gate=blocked（fail-closed），开关 `PROMPT_RELEASE_RAGAS_GATE_ENABLED`。
- 依赖：C4-7 实分稳定化先行或同期灰度。

### 二期：运行生命周期
