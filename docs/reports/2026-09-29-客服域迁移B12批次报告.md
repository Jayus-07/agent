> 日期：2026-09-29 ｜ 基线：B10-B11 报告后 ｜ 验收策略：直接切换 + 本机真实链路验证

## B12 实施内容（本批提交）

**目标（委托方指令）**：统一 ticket / complaint / after_sales 为 **cs_case**，先完成核心闭环 **创建 → 分配 → 处理 → 关闭**；高级运营能力（质检/Copilot/情绪分级 SLA 自动化）后续。设计方案 §10.1 明确「case 是唯一案件事实源」「聊天 ≠ 问题」。

**三件套**：

1. **迁移 `058_cs_case.sql`**（登记 `scripts/init_db.py::MIGRATION_TARGETS` → memory 库，已在 5433/agent_memory 应用）：
   - 表 `customer_service.cs_case`（schema 跟随现役 CS 表 confirmations/tickets）：case_id UUID / tenant / conversation / user / case_type（refund|return|exchange|complaint|inquiry）/ priority（P0|P1|P2）/ status（open|waiting_user|processing|resolved|closed）/ context JSONB / owner_agent_id / related_confirmation_id / resolution（结案必填）/ sla_deadline_at / first_responded_at；
   - **防重入**：部分唯一索引 `uq_cs_case_active`（conversation_id+case_type 在活跃状态集上唯一）——同会话同类型只允许一个活跃案件，并发由 DB 决胜（对齐 051 确认链守卫模式），resolved/closed 后允许重新进线建新案；
   - ORM `models/case.py::CSCase`（CSBase，customer_service schema）+ SLA 表 P0=5min/P1=30min/P2=24h（设计方案 §4.6）。
2. **服务 `case/service.py::CSCaseService`**（与 TicketStore 同款 async + `_db_loop.run_sync` 同步门面）：
   - `async_create`：SLA 自动计算；IntegrityError → 幂等复用赢家行（**不做先查后插**）；类型/优先级白名单 fail-fast；
   - `async_assign`：分配坐席 + 首响 SLA 打点（first_responded_at）；closed 不可分配；
   - `async_start_process` / `async_set_waiting_user` / `async_close`：状态流转**白名单 fail-fast**（closed 终态；resolved→closed 单向），结案 resolution 必填；
   - 查询：active_by_conversation（幂等防重入消费方用）/ list（管理端用）。
3. **投诉源接入**（`experts/complaint.py`）：建投诉工单的同时**并行写入 cs_case**（severity→priority 映射 critical→P0/high→P1/其余→P2；context 携带 ticket_id 溯源）——fire-and-forget 同款（案件落库失败只损失可查询性，不阻断安抚与转人工）。tickets 表并存过渡，全面并表走后续批次（设计方案 §14.2 过渡策略）。

**验证**：
- 单测 `test_case_service.py` 7 条：SLA 表/闭环全链（创建→分配→处理→关闭，resolution 必填负例）/ 非法流转 fail-fast / 防重入幂等复用（mock IntegrityError→复用赢家行）/ 非法类型优先级拒绝 / **ORM 活跃状态集与 058 索引谓词成对守护**（防两处漂移）；
- 迁移实机应用：5433/agent_memory 建表成功，4 索引 + 唯一守卫在位；
- 回归门：CS 全量 + orchestration/graph（结果见提交信息）；
- 实机：HEAD 镜像重建后投诉场景触发 → `customer_service.cs_case` 落库可查（含 SLA deadline）。

**明确不做（后续批次位）**：ticket/after_sales 全面并表与视图迁移、管理端案件工作台 API/UI、质检抽检与 Copilot 接单卡（设计方案 §9.5/§9.1.2⑧⑨）、ANGRY 情绪分级自动建案（P1/P2 SLA 自动化）。
