## 冻结的执行契约

**每一次实际发给模型的请求，都必须满足该次调用的输入预算。** 预算按实际模型
窗口、输出预留、工具 schema、response_format 和安全余量计算。System、当前用户
问题、活跃工具调用组和业务 pin 需要保留；这些必需内容本身放不下时返回明确的
「上下文过长」错误，模型调用次数为零。原始 chat_messages 不改写。L5 负责提高
历史保留质量；确定性裁剪后的最终预算检查是最后一道防线。

关键修复原理备忘：

- **原事故链**：async 上下文 L5 一触发即在 `manager._run_l5` 引用未定义的
  `_L5_TASKS` → NameError → proxy 预检 `except Exception` 整体 fail-open →
  本轮已完成的 L2/L4/硬裁全部作废，**未裁剪的原始消息直发 provider**。
- **90%~100% 触发入口分裂**：原 proxy 在 `total <= budget` 时短路返回，L5 的
  90% 触发区间经代理路径永不进入；STOP D 把快路径阈值统一为
  `budget × CONTEXT_L5_TRIGGER_RATIO`（同步/异步同一常量）。
- **双重扣除缺陷**（STOP A 顺带修复）：`tool_schema` 已在 `get_input_budget`
  扣除，却被 `_finalize` 加回用量参与溢出对比——fail-open 时代只是误报日志，
  fail-closed 下会把未超窗误判为超窗。
- **投影二元组 vs E-I3**（STOP C）：二元组成原子组解决「只剩 policy 空壳」，
  但组**不享 System 预算豁免**（预算内整组留、超预算整组丢），否则长摘要
  永不可裁、硬门禁会在大摘要后拒绝一切请求（memory 层预算不变量回归实证）。

## 遗留（不阻塞四项 PASS，须跟踪）

1. **两个接线 hunk 在工作区**（并行会话文件未落定，按避坑纪律不代提交）：
   - `backend/infra/llm/proxy.py`：`_apreflight_context`（异步在线入口接线
     ainvoke/astream/_BoundLLMProxy.ainvoke）+ stream/astream 超长错误映射 +
     STOP D 快路径阈值。该文件同时含定价会话未提交的流式预占对账改动
     （`review_model_reservation`）。**hunk 未落库前，主干上的异步模型调用
     仍走同步预检入口（L5 在异步上下文按 STOP B 语义跳过、不等待），
     fail-closed 与单飞等核心保护已随 A/B 生效。**
   - `backend/orchestration/graph/runner.py`：SSE 稳定错误码映射 +
     `drain_pending_events(session_id=...)`。未落库前超长输入在 SSE 上表现为
     通用 error 帧（无稳定 code 字段），事件缓冲退化为会话桶照常生效。
   两文件落定后按 hunk 提交（提交信息注明随行变更归属）。
2. **实机链路验收**（矩阵末行）：需要重建 app 容器（当前容器代码落后 HEAD），
   会重启共享 backend——须与其他会话协调窗口后执行「一轮长历史成功 + 一轮
   超长输入明确拒绝 + trace 检查」。
3. **标定运维事项**：deepseek/qwen/siliconflow 的 ASCII 系数 0.30 无真实
   usage 回测（唯一回测样本是豆包，见 `token_counter._CALIBRATION` 注释）。
   按模型采样（真实 `usage.prompt_tokens` vs 估算）标定后再调系数/安全余量/
   触发阈值；本机若配置 8192 窗口则输入额度为 7168，测试不得写死本机数值
   （全部测试已参数化）。
4. 在线等待时限 `CONTEXT_L5_ONLINE_WAIT_SECONDS=8`：请求级 deadline 融合
   （`RequestDeadline`）尚未接入该等待上限，当前为固定配置值——如需按请求
   剩余预算动态收缩，挂账后续小改动。
