## B. 企业级目标架构（文字版）

```
【接入层】
  客户端×3（用户:3100/管理:3200/坐席:3300）→ APISIX（唯一入口，多副本）
    ├ JWT 鉴权(gateway-auth) + 按用户限流(limit-count/limit-conn)（已有）
    ├ upstream 主动健康检查 + app 多副本（无会话亲和依赖：SSE 走 F2 resume，状态在 PG/Redis）
    └ 访问日志 → ai.gateway_access_logs（T0 口径数据源）

【编排层】GraphRunner(LangGraph)：主图 9 节点 + 域图自动发现（结构保留）
    ├ 并发准入：进程内优先级门 → DIST 准入门（多副本必开，Redis 权威）
    ├ checkpointer：PG，TTL 单例清理；thread_id 每轮唯一
    └ 每节点 span 强制闭合（父子时长对账进 trace），prompt_versions 请求级 pin（已有）

【RAG 层】（rag-service 独立进程；目标无状态化）
  查询：改写→MultiQuery→混合检索→同文档扩展→Rerank→EvidenceGate→引用生成→META 尾判
        每阶段独立 span + 耗时标签（T3-T14 全覆盖，见 N 章）
  索引：解析→元数据→切分→embedding→pgvector + BM25
        BM25 持久化落盘（当前进程内，12s 重建窗口可接受，规模化后外置）
        索引收敛 Job：registry ↔ vectors ↔ BM25 三方每日对账，状态以实际索引为准

【数据治理层】
  生命周期：registered→parsing(超时看门狗)→active/failed→软删→物理清运
  失败重放：批量重放 API + 幂等（file_hash 键）+ 重放审计
  测试隔离：Temp/测试路径上传闸 + fixture_set 强制隔离

【评估层】
  套件分层：smoke(≥20，检索可断言)/regression(日)/golden(定标，live 录制回放)
  EvidenceGate 定标集：rejected 样本人工标注闭环 → 阈值实验台

【可观测层】（常驻，非可选）
  Prometheus+Grafana+Alertmanager 常驻；告警：索引覆盖率/拒答率/TTFT/队列积压/备份新鲜度/容器退出
  Trace：单一活跃表、timestamptz、span 闭合校验；TTFT 写失败必须计数告警
  成本：归因三列强制非空（入口 scope 兜底），按域/技能/模型日报

【模型治理层】保留现有 DB 唯一来源 + 15s 热刷新 + 发布门（已达标部分不动）

【安全层】保留 Input Guard/四埋点/审批门；补角色码验收测试化、越权回归集、NL2SQL banned_functions 补齐、凭据 90 天轮换

【部署层】
  Phase1：单机 Compose，监控栈常驻 + 备份每日验证
  Phase2：app×2 + rag-service×2（BM25 外置后）+ DIST 准入门 + PG 主备/托管
```

## D. 痛点逐条分析

**痛点 1：入库失败率 44%**
- 根因【实锤，材料#1/#2】：804 失败 100% 集中 9-28 单日；1360 份 A 类测试垃圾（`%Temp%\agent_test_data_*`）经真实上传链路落库；失败原因 top：embedding API Key 未配置 6117 / 免费配额耗尽 1430 / 测试临时表不存在 998（`rag_processing_runs` run 维度）。管线本身没错（质量门禁正确拒绝了垃圾），**错在投喂与隔离**；且批量导入绕过 rag_index 队列。
- 短期止血：799 份垃圾废弃清理 + 5 份真文档逐份重放（日常通道 0 失败已验证）。
- 长期治理：Temp/测试路径上传闸 + 批量导入强制走 rag_index 队列 + `fixture_set` 隔离。
- 成功指标：积压清零后 30 天滚动失败率 <5%；重放幂等（同 file_hash 二次重放 0 副作用）。

**痛点 2：索引覆盖断层（升格为最大痛点）**
- 根因【推断】：9-28 活动期间状态机把"登记完成"当"索引完成"（`last_indexed` 有值但向量未写/被清）；201 份空 department 说明元数据抽取也失败但状态仍置 active。
- 验证：`SELECT d.department, COUNT(*), COUNT(*) FILTER (WHERE EXISTS(SELECT 1 FROM rag_vectors v WHERE v.doc_id=d.doc_id)) FROM doc_registry d WHERE status='active' GROUP BY 1`（已跑，空 department 201 份全 0 覆盖）。
- 短期：以 `rag_vectors` 实际存在为准修正状态（active 无向量→failed/pending）；265 份补索引。
- 长期：**索引收敛 Job**（每日三方对账，不一致告警+自动修复）；`last_indexed` 只能由向量写入成功后回写。
- 成功指标：覆盖率 ≥99%；对账 Job 连续 14 天零不一致。

**痛点 3：拒答平衡无定标**
- 【事实】rag_agent 路径 7 天 178 条中 rejected 113 = **63.5%**；阈值散落 `operations.py`（min_top1/min_avg/min_gap、low 0.3/high 0.7、RERANK_SCORE_THRESHOLD=0.3）+ `controller.py:103`（meta_min_confidence=0.5 硬编码）+ config（RERANK_MIN_TOP1 等）。
- 根因假设：与 265 份 active 文档查不到互为因果——**先修痛点 2，再评估 Gate**。
- 验证：抽 100 条 rejected 的 question + 应命中文档是否在 rag_vectors → 分流"证据缺失型"vs"Gate 过严型"。
- 短期：归因分流；长期：200 条定标集（应答/应拒各半人工标注）+ 阈值实验台。
- 成功指标：假拒答率 <10%（定标集口径），漏拒答率 <5%。

**痛点 4：评估体系**
- 【事实】9 个套件（pr_smoke 实测 7 条/ci_golden/expanded_100/regression/scale_20k 等）；金标 34 条离线全绿，仅 T-G12 live 语境失效（材料#10）；9-25 后无 travel eval run（覆盖缺口）。
- 短期：pr_smoke 条数口径对齐+扩容 ≥20；金标 live 改录制回放。长期：按域召回/忠实度/引用准确率周报；rejected 样本周转进定标集。
- 成功指标：PR 门禁拦截有效性（植入坏改动可被 smoke 抓住）。

**痛点 5：延迟**
- 【事实】chat 主链路（workflow `agent`，`runner.py:416`）7 天 success 1210：**P50 2445ms / P90 10727 / P95 18855 / P99 149635 / max 209318ms**；degraded 210 条 P95 54.8s；TTFT 不可测。
- 拆解（典型 trace span 实测）：router（LLM 判域）2.9s + tool_selector 1.6s + 主体执行；RAG 侧 retrieval 占 root 96% 但内部 4.2s 黑盒（span 不闭合 + rerank 1ms 计时 bug）。
- 短期：修 TTFT 写入 + span 闭合 + rerank 计时；长期：判域/工具选择并行化缓存、检索各阶段独立超时降级。
- 成功指标：先测准（TTFT 有数据），再优化 P95 18.9s → ≤10s。

**痛点 6：权限**
- 【事实】super_admin 已补齐（`authorization.py:43`，2026-10-01）；auth.users 39 人（viewer 23/editor 7/admin 6/super_admin 3）；AUTHZ_DENIED 7 天 40 条可审计。
- 剩余：无越权回归测试集；容器部署版本是否包含修复未核验（app 容器重启于 26 分钟前，镜像构建身份未对账）。
- 成功指标：越权用例集 0 逃逸；角色码变更带契约测试。

**痛点 7：成本**
- 【事实】7 天 ¥17.79 / 260 万 token；**54% 烧在入库侧**（metadata_extract ¥5.57 + question_gen ¥3.69 + table_describe ¥0.36）vs 问答侧 ¥8.17；embedding/rerank 单价记 0（材料#4：应 0.5 元/百万 tokens，漏记账累计约 ¥1.0）；归因三列全空。
- 短期：rag-service 链路入口 scope 注入修通（`llm_context.py` scope 机制已有）+ model_price 补录两条 + e2e-seed 假价清理。
- 长期：按域单问成本日报（依赖归因修通）；metadata/question_gen 缓存命中率提升。
- 成功指标：归因填充率 ≥95%；单问成本可按域输出。

**痛点 8：文档漂移**
- 【事实】15 处行为漂移（材料#13 清单）+ 本次新增 3 处（PG16 vs 18、pr_smoke 7 vs 8、super_admin 痛点已修未更新）+ 活跃用户口径（材料#8）。

### N.2 查询方式（现有数据可立即执行的 SQL）

```sql
-- ① 覆盖率（K3）
SELECT count(*) AS active_total,
       count(*) FILTER (WHERE EXISTS (SELECT 1 FROM rag_vectors v WHERE v.doc_id=d.doc_id)) AS in_vec
FROM doc_registry d WHERE status='active';

-- ② 按日失败率（K1）
SELECT created_at::date, count(*) n, count(*) FILTER (WHERE status='failed') failed
FROM doc_registry GROUP BY 1 ORDER BY 1;

-- ③ Trace 覆盖率（K15）
SELECT count(*) FILTER (WHERE trace_id IS NULL OR trace_id='') AS no_trace, count(*) total
FROM llm_usage WHERE created_at::timestamptz >= now() - interval '7 days';

-- ④ TTFT 有效性（K8）
SELECT count(*) FILTER (WHERE ttft_ms IS NULL) AS null_ttft, count(*) total
FROM trace_summary WHERE created_at::timestamptz >= now() - interval '7 days' AND workflow_name='agent';

-- ⑤ 拒答率（K7 前置）
SELECT status, count(*) FROM trace_summary
WHERE created_at::timestamptz >= now() - interval '7 days' AND workflow_name='rag_agent' GROUP BY 1;

-- ⑥ span 闭合抽检
SELECT trace_id, data::jsonb->'spans' FROM trace_store
WHERE created_at::timestamptz >= now() - interval '1 day' AND workflow_name='agent' LIMIT 20;
```
