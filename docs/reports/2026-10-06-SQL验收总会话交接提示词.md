## 四、注意的地方（铁律，违反必踩坑）

1. **多会话纪律**：开工先 `git status` + `git log` 核基线；提交双重路径限定（`git add -A -- <paths>` + `git commit -- <paths>`）；别人的未提交文件绝不顺手提交/回滚。
2. **数据库连 5433**（docker agent-postgres-1 的 agent_business）；宿主机 5432 有同名库是另一个 PG。连接用 `backend.config.database.BUSINESS_DB_READONLY_CONFIG`（agent_readonly）。
3. **局部 pytest 必须加 `--no-cov`**（pytest.ini 挂死 cov-fail-under=55，全绿也 EXIT=1）。
4. **数据集不可变指纹**：改用例内容禁止原地改 `cases.jsonl`（fail-fast），必须走新版本目录 + `python -m backend.evaluation.datasets.gen_dataset_manifest` 生成指纹；可执行 selection 用 `datasets/sql/{name}.jsonl` 完整拷贝通道。
5. **评测线程预算旁路（本轮发现，待修）**：评测/脚本线程无 RequestContext.bind 时，budget enforce 下 LLM 调用不预占不结算——live 回放前要么补绑定要么显式接受旁路并记录。
6. **安全改动探针先行**：改 L4/权限逻辑前先跑探针拿实测行为再写断言（模板 D:/tmp/probe_g13_20.py、D:/tmp/probe_g04.py）；回归断言的层位/reason 全部以实测为准。
7. **SQL 安全三个反直觉坑**：`order` 是 PG 保留字（schema 限定必须写 `"order".orders`）；**CTE 别名会被自家 L2 表白名单拦**（gold SQL 禁用 CTE，用派生表）；无授权权角色执行 GRANT 是 PG 静默无操作（发 WARNING 返回成功，验证授权要查 information_schema）。
8. **G-20 拒绝码定序**：权限门先行（guest 无权限→PERMISSION_DENIED），身份闸殿后（有权限但空 user_id→SCOPE_UNAVAILABLE）——顺序反了会打红三个存量契约测试。
9. **不接受假绿**：A 类回放必须结果级断言（gold_rows 比对），只断言 status=success 视为无效验收；「查不到」与「查不了」话术必须分开。
10. **容器是旧代码**：docker app 容器不含本轮安全修复，实机验证（R-07/R-09 的 MCP 路径）前需 rebuild 或明确按 HEAD 代码本地起服务验证。
11. 需要拍板的事（门禁线数值 / 审计存 SQL 原文 / max_retries 放宽 / 全函数正向白名单 / 兜底池尾 anthropic 密钥）：写入清单 §9 台账，**不自行定夺**。
