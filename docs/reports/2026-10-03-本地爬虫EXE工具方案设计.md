# 本地爬虫 EXE 工具方案设计（travel-crawler）

> 日期：2026-10-03 ｜ 状态：**已实施（M1-M4 全量落地，冒烟 PASS）**，细节五轮拍板见 §10
> 位置：`D:\Program Files\workplace\travel-crawler\`（agent 仓库外独立目录）
> 验证：25 单测全绿 + 实机冒烟 PASS（msedge 有头启动/状态机/抽取/文档清洗/事件流）
> **待用户实机验收**：淘宝扫码登录、真实商品页字段核对、滑块人工在环、切号续跑（需真人扫码，无法自动验收）
> 定位一句话：一个与 agent 主项目**完全分离**的 Windows 本机爬虫工具，有头浏览器人工在环，产出的 md / csv 文件经管理端现成入口回流项目。

## 0. 背景与拍板记录

两条需求线汇合：

1. **旅游语料**：爬景点/美食/城市/特色介绍网页 → 清洗成词条 md → 上传 RAG（对应 2026-10-03 福州语料方案）
2. **电商选品**：爬淘宝商品详情页 → CSV → 选品漏斗表格导入

已拍板（本会话确认）：

- **工具与主项目完全分离**：零代码 import、零数据库共享；唯一接口 = 导出文件
- **仅本机人工使用**：不做容器/服务器形态、不做 noVNC 远程画面（家宽 IP + 有头 + 真人过验证 = 风控最友好形态）
- **分发形态 = EXE**：绿色 zip 包，解压双击即用，对方无需装 Python
- **人工在环**：滑块/登录在弹出的浏览器窗口里人工完成，不破解验证码
- **界面 = 本地图形窗口**（2026-10-03 细节拍板）：双击 exe 弹控制面板，全部按钮点击操作，不要命令行
- **细节拍板（同轮）**：浏览器 = Edge 优先缺失再引导下载；文档清洗 = 规则为主 + 可选 LLM；平台范围 = 仅淘宝（base.py 留扩展位）
- **细节五轮拍板（同日完成，§5/§7/§9/§11 已按拍板更新）**：单浏览器窗口全程复用｜批量抓完统一确认｜失败自动重试 1 次｜间隔 20~40s + 日软上限 40｜持久化 profile｜验证窗口置顶抢焦点｜过验证自动继续｜连续 2 次滑块 = 该账号 24h 锁定 + 人工确认切号（**账号池不限个数**，切号歇 2~5 分钟）｜cookie 20 天保鲜提醒｜CSV 增量导出｜类目待确认表格手填｜md 文件名 = 城市-类目-标题、日期写在内容里｜历史全保留手动清

为什么这样定（决策依据）：容器/机房 IP + headless 是风控重点画像，此前容器自动链路已被项目侧结论降级（`pool_builder.py` 明确"外站反爬不确定"，表格导入为主源）；本机真人形态反而能把爬到的数据变成**主源的供给方**。

## 1. 目标与非目标

**目标**

1. Windows EXE（PyInstaller 打包），解压即用，双击打开**图形控制面板**（按钮点击操作）
2. 淘宝商品详情页采集：单页 + 监控清单批量，登录/滑块人工在环
3. 网页文档采集：抓正文 → 去噪 → 词条 md（300~800 字，带元信息）
4. 本地 SQLite 存登录 cookie / 监控清单 / 抓取历史，导出带去重
5. 导出：CSV（表头对齐选品 import_pool 中文宽松映射）+ md + 一键打 zip

**非目标（红线，不做）**

- ❌ 滑块/验证码自动破解、mtop/h5 签名请求、代理池
- ❌ 搜索结果页抓取（风控最重 + 用户协议禁止）
- ❌ headless 模式（有头是本工具的存在前提）
- ❌ Linux/服务器/容器部署
- ❌ 共享账号：每人用自己淘宝号扫码，cookie 存各自电脑

## 3. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言/打包 | Python 3.11 + PyInstaller **onedir**（打 zip） | onefile 启动慢且 playwright driver 数据文件路径易碎；绿色文件夹 zip 是国内用户熟悉形态 |
| 浏览器 | Playwright `channel="msedge"` 优先 → `chrome` → 无则引导下载 Chromium | Win11 必有 Edge，零下载；**真实浏览器指纹**远优于 chromium-for-testing，反检测天然加分 |
| 抓取 | 有头 Playwright 直连 DOM | 不引 crawl4ai：人工在环场景不需要 stealth 魔法，真实浏览器+真人操作本身就是最好伪装，还省一个重依赖 |
| 解析 | BeautifulSoup4 + html2text | 正文提取与 md 转换，纯 Python 轻依赖 |
| 存储 | 标准库 sqlite3 | 零依赖；cookie 用 Fernet 加密，密钥首跑自动生成存 `data/key.key` |
| 界面 | **tkinter（标准库）** | 零额外依赖、打包体积最小、PyInstaller 兼容最稳；控制面板 = 按钮 + 表格 + 日志区 |
| 线程模型 | 抓取跑后台线程，GUI 经队列刷新 | tkinter 主线程约束：浏览器操作绝不能在 UI 线程跑，否则窗口假死 |
| LLM 清洗（可选） | httpx 调 OpenAI 兼容 endpoint | 默认关；用户在 config.json 自配 key 才启用 |

依赖合计：`playwright`、`beautifulsoup4`、`html2text`、`cryptography`、（可选 `httpx`）。
注意：Windows 控制台 GBK——入口统一 `sys.stdout.reconfigure(encoding="utf-8")`，避免中文乱码。

## 5. 功能规格

### 5.1 商品页采集：页面状态机（核心）

每次导航后判定状态，四态：

| 状态 | 判定依据 | 处理 |
|---|---|---|
| `PRODUCT_OK` | 标题+价格选择器/锚点命中 | 抽取字段 → 进 GUI「待确认」表格（**不直接入库**） |
| `LOGIN_PAGE` | URL 含 `login.taobao.com` 或登录关键词 ≥2（移植项目 `pipeline.py` 特征） | 提示「请在窗口扫码登录」→ 轮询至离开登录页 → **cookie 加密回存 SQLite** |
| `PUNISH` | 滑块/punish 页特征（URL 跳转 `punish.`、验证码元素） | **窗口置顶抢焦点**提示人工 → 轮询最多 3 分钟 → 恢复后**自动继续**；**连续 2 次 → 该账号锁定 24h**，批量暂停走 §5.4 切号流程 |
| `NOT_FOUND` / `UNKNOWN` | 无标题无价格且非以上态 | 记录 crawl_log 后跳过（「查不到」与「查不了」话术分开） |

抽取字段（淘宝）：`url, title, price, original_price, sold_count, review_count, shop_name, rating, promo_text, main_image` + `crawled_at`。销量与评价数**分离**（修正项目侧"已售"并入 review_count 的口径）。

单条失败（超时/页面没加载）**自动重试 1 次**，仍失败在待确认表格标红、可手动点重试；浏览器窗口全程共用一个，关闭 GUI 时一并关闭。

### 5.2 确认入库（GUI 交互）

抓取结果先进「待确认」表格（标题/价格/销量/链接逐行可见 + **可编辑「类目」列，入库前顺手填**），
用户勾选后点 **[入库选中]** 或 **[丢弃选中]**；批量抓完统一确认——人工在环同时充当数据质量把关。
期间浏览器窗口若弹出验证，GUI 顶部横幅提示「请在浏览器窗口完成验证」。

### 5.3 批量监控清单（GUI 清单页）

- 清单页表格增删 URL + 备注，点 **[批量刷新]** 按清单逐个抓
- 每页之间**随机 20~40s**、日软上限 **40 次/账号**（config.json 均可改），每次写 crawl_log
- 中途命中 LOGIN/PUNISH：人工处理后自动续跑；跑不完的剩余清单保留下次继续
- 配额与熔断按**账号**记账（§5.4），不是全局一刀切

### 5.4 多账号池（2026-10-03 拍板新增）

- GUI 账号页管理**不限个数**的账号列表，每账号独立存 cookie、独立配额与风控状态
- 账号被封（连续 2 次滑块）→ **该账号锁定 24h**，批量暂停 + GUI 弹「切换账号」
- 人点确认 → 浏览器弹登录窗口 → 扫新号 → **歇 2~5 分钟**再接着跑剩余清单（同 IP 秒换号是风控明显信号）
- **不自动切号**：停下等人确认是拍板口径

### 5.5 文档模式（旅游语料）

文档页支持**单篇 URL 或多行 URL 队列（批量）**，城市/类目下拉选择：

1. 有头抓取正文（文档站无风控，但同样可见可交互，遇到 Cookie 弹窗人工点掉）
2. 规则去噪：剥导航/页脚/广告/脚本残留/空链接行/图片 alt 噪声（bs4 + html2text）
3. 字数护栏：<150 字提示过短建议换源；目标 300~800 字（检索命中与切块粒度的平衡口径，同福州语料方案）
4. 生成 md：`title` H1 + 元信息（city/category/source/crawled_at）+ 正文；**文末保留来源标注**
   - frontmatter（`---` 块）与项目 MarkdownParser 的兼容性实现期验证，不兼容则退化为正文头部元信息行（§10 待核项）
5. `--llm` 可选：config.json 配了 OpenAI 兼容 endpoint+key 时走 LLM 清洗重写，默认纯规则（给别人用零配置可用）

### 5.6 导出（GUI 导出页按钮）

- **CSV 默认增量导出**：只导上次导出后新入库的记录（exported 标记去重），下拉可切全量；生成 `products_<日期>.csv`
- **CSV 表头直接用 import_pool 中文别名**（实现期已核对 `import_pool.py:37-50`）：
  `标题, 价格, 原价, 评分, 评价数, 销量, 平台, 类目, 链接, 促销, 卖点`
  （成本列爬不到，宁缺毋造不导出；单批 ≤2000 行，监控清单规模远够）
- md 文件名 = **城市-类目-标题.md**（如 `福州-景点-三坊七巷.md`），**日期写在文件内容元信息里**、不进文件名；导出落 `data/export/docs/` + 打 `docs.zip`
- `pack`：一键把未导出产物打单个 zip，方便微信直发

## 7. 反封与合规口径

- 画像：家宽 IP + 有头 + 人工在环 + **持久化 profile**（像"老用户"）= 风控最友好组合；**仍保守**：间隔 20~40s、日 40 次/账号、连续 2 次滑块单账号 24h 锁、切号歇 2~5 分钟
- cookie 保鲜：距上次扫码 >20 天 GUI 黄条提醒重扫（不强制）
- robots：文档模式目标站（文旅/百科类）先查 robots；电商监控属用户协议灰色地带，口径沿用项目既有拍板——**仅供学习研究、不商用**（与 12306 MCP / 知乎 MCP 同款）
- 分发纪律：README 明示工具用途与红线；不内置任何账号、代理、破解逻辑

## 11. 验收标准（六类清单）

- **单页采集**：登录态抓商品页，控制台字段表与页面实际一致，确认后 crawl_log 有记录
- **登录态闭环**：清 cookie 抓取 → 进 LOGIN_PAGE → 窗口扫码 → 自动续跑 → cookie 回存加密
- **人工在环**：触发 PUNISH → 窗口置顶提示人工 → 完成后自动继续
- **账号切换**：连续 2 次 PUNISH → 该账号 24h 锁定 → 批量暂停 → 人工确认切新号 → 歇 2~5min 自动续跑剩余清单
- **批量与限速**：批量间隔、日上限、导出去重均符合 config
- **回流对账**：CSV 走管理端「表格导入」成功建池；md 走 RAG 上传成功入库且能检索命中
- **分发**：无 Python 的干净 Windows 机器解压可用，全程无报错
