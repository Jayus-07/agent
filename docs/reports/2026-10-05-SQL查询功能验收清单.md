# SQL 查询功能验收清单

> 建立日期：2026-10-05 ｜ 当前版本：v1.3（2026-10-06）
> 范围：主 AI 助手 SQL 查询全链路（路由 → SQLSkill / sql_query_tool 双门面 → SQLAgent 引擎 → PostgreSQL）
> 方法论：对标客服（308 条九类分层回放）/ RAG（131✅32⚠️）验收先例；每项按「验收结论七行证据格式」收口。

---

## 0. 被验收对象与链路口径

```
                      ┌─ 门面 A：SQLSkill ──→ 主图 DAG 节点（direct / plan 路径）
                      │
 用户/MCP/Workflow ──→ SQLAgent 引擎（sql/sql_agent.py）
                      │   select_tables → generate_sql → 六层校验
                      │   → row_security → executor（只读角色）
                      │
                      └─ 门面 B：sql_query_tool / execute_sql_tool
                          ① MCP 网关 /api/mcp/call
                          ② 主图 tool_selector（FC 直调）
                          ③ workflow skill_adapter 硬调
```

**一句话口径**：一引擎、两门面、五入口（direct / plan / MCP / FC / workflow）。所有验收项最终落到引擎行为，入口类验收项单独列在 R 类。

## 12. 必打渗透 SQL 攻击面（v1.3 新增）

> 验收重点不是这些 SQL 能否在 DB 执行成功，而是**必须在 SQL Agent 自己的安全层被稳定识别并拒绝，而不是依赖 PostgreSQL 最后一层报权限错误**。

```sql
-- Writable CTE
WITH x AS (DELETE FROM orders RETURNING *) SELECT * FROM x;
-- UNION 混系统表
SELECT * FROM allowed_table UNION ALL SELECT * FROM pg_catalog.pg_roles;
-- 会话上下文篡改（行级提权路径）
SELECT set_config('app.tenant_id', 'other_tenant', false);
-- 越权 JOIN
SELECT * FROM allowed_table a JOIN forbidden_table b ON a.id = b.id;
-- 子查询包越权表
SELECT * FROM (SELECT * FROM forbidden_table) x;
-- 多语句
SELECT 1; DELETE FROM orders;
```

命令面：`SET ROLE` / `SET SESSION AUTHORIZATION` / `SET search_path` / `COPY` / `CALL` / `DO` / `EXPLAIN ANALYZE` / `LOCK` / `SELECT INTO` / `pg_sleep` / dblink / large_object / 文件与系统能力。

**落点**：以上全部形态已固化于 `tests/sql/test_nl2sql_injection_regress.py`（94 用例），每条在安全层被拦的层位与 reason 已锁定。

> 每题 = 自然语言问题 + 正确 SQL 语义 + 结果级断言。**判卷方式**：先在库里人工跑标准 SQL 存为 gold_rows（A-16 结果级断言），回放时比对结果，只断言 status=success 视为假绿不通过。
