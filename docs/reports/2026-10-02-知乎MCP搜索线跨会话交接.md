## 一、这条线是什么

把知乎官方 MCP（developer.zhihu.com，Streamable HTTP + Bearer，免费配额搜索类各
5000 次/期）接成平台的外部 MCP 数据源（外部 MCP 作 Tool 数据源的第二例，首例 12306），
并在旅游域落地「搜美食攻略」消费场景。

- 官方端点：`https://developer.zhihu.com/api/mcp/v1`（**无** /mcp、/sse 后缀）
- 上游工具：`zhihu_search`（≤10 条/次）、`global_search`（≤20 条/次）、`hot_list`、`zhida`（后两个未接）
- 实测返回形态：`{"code":0,"message":"success","data":{"has_more","item_count","items":[...]}}`，
  全网 items 字段更宽（vote_up_count/edit_time、content_type 可空串）。**解析规则勿凭文档改，以实测为准**

## 六、风险与坑（照抄自实测）

- **配额**：搜索类各 5000 次/期；本地 TTL 300s 缓存 + 节流 1s 已按省配额调优；count 超该工具上限本地收敛（zhihu>10 收敛到 10、global 上限 20 由参数校验拒绝）防烧配额
- **key 安全**：`ZHIHU_MCP_API_KEY` 在仓库根 `.env`（已 gitignore）与 ZCode 用户级 `~/.zcode/cli/config.json`（mcp.servers.zhihu）；该 key 曾出现在聊天记录，必要时在开放平台个人中心轮换，换后两处同步
- **app 容器生效条件**：`.env` 的开关需重启 backend 容器才加载（本会话未动容器，多会话共享环境）
- **失败语义**：code≠0（配额尽/无权限）与 McpClientError 都走失败封套，「查不到」（code=0 且 items 空）是成功封套+空列表——按键名分类，别做文本匹配
- **宿主机跑 pytest**：局部跑必须 `--no-cov`；PG 连 5433
