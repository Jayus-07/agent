## 二、任务卡（按企业做法编写；每完成一项立即双重路径限定提交）

### A. 迁移还债（解锁条件：`scripts/init_db.py` 干净）
企业做法：结构变更必须走可回滚迁移，惰性建表只是上线冲刺的临时口径。当前三张表是惰性建表：`ai.knowledge_lifecycle_events`（DDL 备份在 `backend/rag/indexing/lifecycle.py` 注释）、`ai.cs_faq`、`ai.cs_faq_query_log`（DDL 在 `backend/customer_service/faq.py`）。
步骤：查 `backend/sql/migrations/` 取下一个可用号（**071 已被两会话撞号，072 起可用**）→ 新迁移（up 幂等 CREATE TABLE IF NOT EXISTS 兼容生产已存在的表 + down 可回滚）→ `scripts/init_db.py::MIGRATION_TARGETS` 登记 → 登记测试（仿 `backend/tests/rag/test_rag_index_reconcile.py` 模式）→ `init_db --check` 通过 → 报告里把「惰性建表」口径改为「已迁移化」。

### B. C11 PII 扩面（解锁条件：`supervisor.py`/`experts/query.py`/`graph_builder.py` 干净）
企业做法：所有外发 LLM 的 prompt 统一过脱敏边界，不做选择性覆盖。当前只接线了知识问答主路径（`experts/knowledge.py`），剩 4 条：supervisor LLM 兜底、query/action/complaint 专家。用既有 `backend/customer_service/pii.py`（mask_pii/unmask_text），每条路径验收同 C11 口径：抽 payload 断言零明文 + 端到端还原 100%（测试仿 `tests/customer_service/test_pii.py`）。

### C. C6 缺口闭环批量化（无解锁条件，可直接做）
目标：缺口→知识→published 闭环 **≥10 条**（当前 1 条，机制已验证）。企业做法：
① 从 `ai.cs_faq_query_log` 拉 `matched=false` 的真实 miss（≥10 个不同问题）→ ② 逐条判定：KB 有答案→补条目或变体（改完必须复测命中）；KB 无答案→登记待补知识清单（不求立即解决）→ ③ 发布→复测→闭环记录（before-miss / after-hit 各留证）→ ④ 新增 `backend/scripts/cs_faq_gap_review.py` 周检脚本输出缺口清单，可挂 Celery beat（ maintenance 队列，注意 queue_router 任务名登记）。

### D. C9 三轮定标（①无门槛先做；②③需用户拍板，见决策门）
1. **无门槛**：18 条可疑应答逐条人工复核（定标纪律：逐条定「题目成立/改写/剔除」，改写后重录制该条分数）→ 重跑 `python -m backend.scripts.rag_gate_lab record-rerank` + `report --face rerank` → 出新基线。录制方法（免容器重建）：docker cp 数据集进 rag-service 容器 → `registry_store.refresh_registry()` 装载绑定 → 进程内直调生产 DashScopeReranker（完整脚本模式见 git 历史 `b13031d` 的实现与记忆条目）。
2. **需拍板**：录制候选集换混合检索并集（当前=向量腿 top8，BM25 腿缺席）——只动录制面不动生产。
3. **需拍板**：reranker 模型升级、生产阈值任何变更——必须过决策门 + PR 门禁，**禁止直接改**（当前冻结是 2026-10-04 实测结论：rerank 面假拒 24%/漏拒 13%，网格无达标点，调优无赢面）。

### E. FAQ 语义召回二阶段（可选，按数据立项）
企业做法：精准层不够再上语义层，勿过早优化。触发条件：`cs_faq_query_log` 周 miss 率持续 >30%。方案：复用既有 embedding 单例对 FAQ question 建向量（阈值先实验台后接线，方法论复用 `rag_gate_lab`）。命中时延预算仍按 ≤500ms 口径设计。

### G. 上线 Runbook（无解锁条件，优先做——这是生产运行件）
