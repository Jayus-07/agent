# 旅游检索规划重构·第三批（上半场）验收报告：快 + 细

日期：2026-10-04 ｜ 计划书：`docs/reports/2026-10-04-旅游检索规划流程重构计划.md` ｜ 提交：`e9d3340`(#9a 分级) + `7686e87`(#9b 区县) + `4da6123`(#7a 车票自动) + `dc998eb`(A4 时序修复)

## 修改内容

- **#9a 天气分级**（e9d3340）：`weather_severity` 纯函数——仅「小雨」降为提示级（带伞不替换），混强词（小雨转大雨/雷阵雨）仍 severe 防降级误放，小雪保持 severe（结冰不降级）；`bad_weather_dates` 改为仅返回替换级日期，新增 `mild_weather_dates` 提示源；`is_bad_weather` 旧语义保持（披露/证据口径不变，**既有断言零改动**）。expert 接线：mild 日出「建议携带雨具；行程无需调整」，与替换 notes 共存。
- **#9b 区县级天气**（7686e87）：行程景点质心（全程整体质心，单区县口径不放大调用数）→ 腾讯逆地理反查区县 → 和风 GeoAPI 按区县名查预报（keyword 查询天然支持 district，provider 链零改动复用）；区县解析失败/预报未收录 → 城市级重试一次（如实降级两次 tool 事件）；提示留痕「天气按景点集中区域 XX区 查询」。开关 `TRAVEL_WEATHER_DISTRICT_ENABLED` 默认开。
- **#7a 抵达车票自动查询**（4da6123）：`_needs_train_search` 去掉「查高铁」触发词门控——有出发地+出发日期即查（抵达交通是外地来的刚需）；单城市（无出发地）不查；重复查询由 provider 共享缓存+tool_cache 兜底。
- **A4 排序时序修复**（dc998eb）：实机抓到排序在 `result_summary` 生成之后执行——工具行 preview 显示高德原序、仅 state 候选有序。修复：排序移入 `run_travel_tool` 内部 lambda，工具行与推荐卡同源同序。

**#7b 市内公交候选模式本轮不做**：腾讯 route provider 位于 STOP J 冻结面（注释明示「TransitProvider 层（冻结面）」），启用公交查询需动 RouteRecord/live_leg 契约——按冻结纪律走「加法式变更+偏差报告」另批处理。API 能力已确认（`ROUTE_MODES` 含 transit）。
