| # | 旧行为 | 新行为 | 开关（默认） |
|---|---|---|---|

## 二、任务分解

### 阶段一（解锁文件已齐，可立即开工）

**T1. FAQ 相似推荐接口（faq.py，零 LLM）**
- 新增 `FAQStore.match_candidates(question, k=3, min_score=0.30)`：复用既有 bigram 索引返回 top-k 相似条目（阈值低于 MATCH_SCORE_THRESHOLD=0.42，只做"您是不是想问"推荐，不直答）。
- 测试：候选数≤k、分数降序、阈值过滤、published/valid_until fail-closed 同主匹配口径（仿 test_cs_faq.py FakeConn 模式）。

**T2. 拒答自救阶梯（knowledge/service.py + 话术常量）**
- REFUSE 路径改造：拒答 → ①固定引导换问法话术（模板，不做 LLM 定制澄清）→ ②`match_candidates` 有候选则附"您是不是想问"→ ③兜底话术"已记录，补充后可查"。
- 缺口留痕：`ai.cs_faq_query_log` 已记 matched=false（C6 现成），**不新增表**；③ 的"已记录"即真实动作。
- 话术与寒暄同一人设口吻（见 T3 prompt）；**不出现主动转人工引导**。
- 澄清防循环：同问去重复用既有追问守卫口径，同会话澄清引导 ≤2 次（clarify_content 解锁后接细，阶段一先模板化）。
- 测试：阶梯顺序断言（有候选→带候选话术；无候选→兜底话术；全程 llm_usage 增量=0）；C8 handoff_timing_golden 50 条重跑**漏转=0 不变**（拒答改造不得影响必转时机）。

**T3. 寒暄分支（新模块 chat_fallback.py，~60 行）**
- `backend/customer_service/chat_fallback.py`：persona prompt（骨架见下）+ PII 脱敏（复用 pii.py mask/unmask）+ 一次 LLM 调用 + 约束后处理；不出工具不出 SQL。
- 人设 prompt 骨架（模型角色走治理 DB，运行角色=main；禁业务代码 os.getenv）：
  ```
  你是电商店铺的客服助手，用口语化中文和用户聊天。
  - 简短：一两句话回应完，不写小作文
  - 先接情绪再说话；用户道谢自然回应，用户着急先安抚
  - 红线：不编造政策/订单/售后事实；不承诺赔偿/时效/补偿；
    不回答购物客服以外的话题；需要业务时引导用户直接提问
  ```
- 测试：mock LLM 边界（只 mock 外部依赖）；PII 断言（进 prompt 的 payload 零明文）；开关关闭时走旧路径。
- **阶段二接线点**：cs_supervisor 分诊新增"非业务对话"出口 → chat_fallback（supervisor.py 解锁后）。

**T4. 出域词表与话术（vocab.py + vocab_gate + golden 扩类）**
- vocab.py 新增 `out_of_scope` 段：旅游/选品强信号词（口径对齐既有 prefilter 正则，不另造第二套）+ 平台外通用话题词；固定话术模板随词表段版本化。
- **顺序铁律**：先判客服信号、后判出域（"订单里的行程单丢了"不得错杀）；分诊吃不准的落业务漏斗（宁可尝试不可错拒）。
- 变更过 vocab_gate（fail-closed）；`intent_triage_golden.json` 扩类：出域说明类、非业务对话类样例补足（复测 triage 准确率不低于 94.7% 基线）。
- 测试：词表段回归 + golden 回放绿。

### 阶段二（混线解锁后，一次性原子提交）

**T5. redirect_main 反转（router_node.py）**
- `CS_WINDOW_STANDALONE=true` 时：锁域消息不再转出，强信号消息放行进 CS 域图（由 T4 词表在域内接住）。
- **守护用例同步**：`tests/orchestration/graph/test_router_prefilter_order.py` 断言更新（转出→放行+出域话术路径）；prefilter 优先级"客服 > 旅游 > 选品"的全局入口语义不变（不锁域流量照旧）。
- admin 前端若有域开关展示，口径同步。

**T6. 分诊出口接线（supervisor.py + clarify 细化）**
- 分诊新增两个出口：`out_of_scope` → T4 固定话术；`chitchat` → T3 chat_fallback。
- 澄清引导复用 clarify_content 守卫（同问去重 + 会话封顶 2 次）。
- 分诊度量 decision_layer 口径不变（1:rule/2:combination/3:llm），出域/寒暄出口打点进 trace。

**T7. 实机验收（部署后执行，逐项留证）** —— 验收矩阵见 §三。

## 四、红线

1. 混线文件（router_node/supervisor/clarify_content/rag/chain）不碰不收编；阶段一/二严格按解锁顺序，提交双重路径限定。
2. 词表/golden 任何变更过 vocab_gate（fail-closed），坏变更拒绝落盘。
3. **C8 漏转=0 纪律不放松**：自救阶梯只改变"拒答场景不推人工"，情绪/投诉/办理失败必转时机原样保留，handoff_timing_golden 每轮重跑。
4. 寒暄/出域路径全程 trace 归因（skill_id/agent_domain 注入），llm_usage 可对账。
5. 新开关默认值进 .env.example；业务代码禁 os.getenv。

## 五、回滚

- 开关级：`CS_WINDOW_STANDALONE=false`（恢复转出）、`CS_CHAT_FALLBACK_ENABLED=false`（寒暄回旧漏斗）——均免重建，env 热改重启进程即生效。
- 代码级：逐提交 revert；话术常量随 revert 回退；词表回退走 vocab 版本回滚（revert 词表提交）。
