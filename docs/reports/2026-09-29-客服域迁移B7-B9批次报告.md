## B9：Knowledge META 置信度收紧 — 提交 3285d3c ✅

**问题（审计 §8.6）**：META（`<!--META-->` 注释）遵循度不稳时，旧兜底 `can_answer 默认 True → confidence=0.65` 直接放行 CAUTIOUS 档——0.85/0.60 两道门禁对这部分流量形同虚设（审计记录的「知识置信度运行在兜底值上」）。

**实施**：
1. 三档门禁由既有 `CSAnswerDecision`（`CS_CONFIDENCE_ANSWER=0.85` / `CS_CONFIDENCE_CAUTIOUS=0.60`）承担，与委托方规则逐字对齐：≥0.85 直接回答；0.60~0.85 回答+可信提示；<0.60 拒答+建议人工；
2. **META 缺失 = 置信度与证据均不可信**：confidence 兜底 0.0 + has_evidence=False → REFUSE（禁无证据生成答案；P3.5 时代的 0.65 放行废弃——当年因「丢弃真实答案」放宽，现按设计方案 §4.3「兜底值必须保守」+ §14.1「兜底收紧 REFUSE」收口，拒答链自带追问建议与转人工引导兜住可用性）；
3. **兜底值监控**：新增 `cs_knowledge_meta_fallback_total` 计数器——兜底率上升 = 模型 META 注释遵循度劣化的直接信号。

**验证**：新增 5 条回归（META 缺失拒答 / meta=None / 真实分值路径 / 高分无证据仍拒 / 兜底指标递增）；委托方三类验证场景对应既有用例（有答案=0.92→ANSWER、无答案=can_answer False→REFUSE、错误召回=0.3→REFUSE）全部继续通过。回归门 **1281 passed / 0 failed**。

**回滚**：revert 3285d3c。

## B7：审计异步化 — 边界核对结案（不改码）✅

逐项核对 `_persist_audit_records` 落库对象：①`action_record` 走 `insert_action_idempotently` 同事务幂等（=退款执行审计+幂等相关审计）；②`cs_audit_entries` 全部为写操作/状态变化类（complaint_ticket_created / handoff_timeout_recovered / pending_cancelled / 动作审计）。**现有审计条目全部落在委托方「必须同步」三类内**，不存在可安全异步的「普通行为日志/非关键运营日志」现役条目；trace 日志本已异步（Redis streams）。结论：**维持同步，不做 fire-and-forget**（「不要为了性能破坏审计完整性」）；同步成本=有审计轮次一次 PG 往返（轮内占比 <5%）。
