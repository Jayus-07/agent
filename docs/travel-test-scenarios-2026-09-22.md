## 执行结果（2026-09-22 实施回填）

- **T/W/B/C 四组已自动化**：`backend/tests/travel/test_scenarios.py` 23 用例，travel 全量 298 passed。提交 e34a02e。
- **实施中发现并修复**：E 组用例固定日期漂移（"9月21日"已过 → 动态下周一锚）；日期区间→天数兑现（B6 从"追问"升级为"直接算出 5 天"，显式天数优先）。
- **浏览器实机验证（agent-browser）**：注册→登录→填表→生成→逐日时间轴/地图/确认区/ICS 按钮全链路 200（提交 0334268）。
- **实机发现两处新问题**：
  1. **页面经 client.ts request() 提交 /travel/plan 稳定 422**（后端收到非对象 body；同页面裸 fetch 同 body 200）。页面已改用 fetchRaw 绕开。⚠️ request() 封装的深层行为待 client.ts 负责人复查——影响面可能不止 travel 页。
  2. **CostBreakdown.total 是 @property 不进 model_dump**，前端渲染崩溃——前端已自算兜底。
- **V1 场景顺带验证**：app 容器被并发会话重启的 503 窗口期，页面展示干净错误文案，无误导性认证报错。
- **S2 决策**：前端超时压到 55s（fetchRaw 无 timeout 参数，最终以网关 60s 兜底；超时文案依赖网关 504 → fetchRaw 会抛 "Failed to fetch" 类错误，页面 catch 显示通用失败提示）。
- **✅ 复查结案（2026-09-22，提交 b427ab5，client.ts 负责会话）**：上面第 1 条的"request() 深层行为问题"**不成立**——实机对照复现证明 stringify 后的 string body 走 request() 全链路 200；422 真因是 request()/fetchRaw 都不自动序列化 body，当时代码把**对象**直接传给了 fetch（浏览器把它 String() 成 `[object Object]` 出网 → 422）。"裸 fetch 200"的对照走的是 api-key 直连非浏览器同链路（APISIX 日志可证），结论不可靠。根治：client.ts request() 收口 body 序列化（对象自动 stringify + 3 条契约测试）；CostBreakdown.total 改 @computed_field（进 model_dump）；travel 页回归 request() 并恢复 55s 超时。验证：travel 298 + 前端 vitest 267 全绿，实机 request() 新链路 APISIX 记录 200。

### D 组实测结论（2026-09-22，LLM=MiniMax-M3）

| 结论 | 场景 |
|---|---|
| ✅ 旅游域主链路（带明确目的地+天数） | D1 |
| ✅ 不串域 | D6、D7 |
| ❌ **Router 分诊缺陷：跨轮短指令/泛问题被兜底吞掉** | D2、D3、D5、D8 |

**根因定位（2026-09-22 两层拆解）**：

1. **第一层（已修复 ✅）：InputGuard 输入守卫 VAGUE 误杀**。`rule_guard.detect_vague`
   对 <10 字且不含 `_BUSINESS_NOUNS` 词表名词的短句拦成 CLARIFY——词表只有电商+HR
   名词，无任何旅游词，「改成3天」「太赶了」「帮我规划个行程」全部在**到达分诊之前**
   被拦。修复：词表补旅游域名词 + 新增 `_RESCHEDULE_INTENT`（改成/多排/N天）豁免；
   放行判据全组回归通过（误杀修复后 D5 已正确进旅游域追问+推荐）。commit 本次。
2. **第二层（待处理 ❌）：主图分诊层接不住短指令**。守卫放行后，「改成3天」「太赶了」
   「福州天气怎么样」经 LLM 分诊落到通用兜底/知识库检索——分诊层未消费会话内旅游
   上下文（`_sync_brief_to_conversation_context` 同步了 brief 摘要但分诊未使用）。
   REST 直连域图跨轮改单正常（checkpointer 状态无损），缺陷仅在对话分诊入口。

**分诊层修复建议（需 Router 层处理）**：
1. 分诊提示词注入当前会话 travel 摘要（destination/days/pace），短指令优先沿续上一域；
2. 强信号词（「行程」「排几天」「赶/轻松」）+ 存在旅游 brief 摘要 → 直接路由旅游域（免 LLM 或 LLM 兜底）。

**守卫修复后 D 组复测（2026-09-22）**：D5 ❌→✅（正确进旅游域追问+推荐）；
D1 ✅ 保持；D2/D3/D4/D8 守卫已放行但分诊仍接不住（落通用兜底/知识库检索）——
与上述第二层定位一致。
