# 旅游域测试场景清单（2026-09-22 P0+P1 验收）

> 来源：P0+P1 实施后的验收设计对齐（用户确认版）。
> 分工：T/W/B/C 组落 pytest 自动化（本文件同一提交内实现）；S2/S4、C5、六、七组留手工/实机验证。
> 每个场景的「预期表现」即验收判定标准：实际表现与文案语义一致即通过。

## 一、多轮会话（T 组，pytest）

| # | 场景 | 预期表现 |
|---|---|---|
| T1 | 只说"帮我规划个行程" | 不硬排；追问城市/天数 + 附推荐（needs_clarification） |
| T2 | 追问后只答"杭州" | 基于上轮槽位继续，不重复问已答槽位 |
| T3 | 行程出来后说"改成3天" | 重规划；行程单标注需求已变化；版本 +1；changed_fields 含 days |
| T4 | 说"太赶了" | pace→relaxed 并重排（2026-09-22 已实测） |
| T5 | "不想去X了"（X 是必去） | X 移出必去；不得同时出现在必去与避雷 |
| T6 | checkpointer 降级（MemorySaver）+ REQUIRE_PERSISTENCE 时跨轮改单 | 不静默失效；行程单明示跨轮改单不可用；本轮按全新规划 |
| T7 | 服务重启后同会话继续 | PG checkpointer 健在可续；降级时按 T6 |

## 二、断线重连（S 组，手工/实机为主）

| # | 场景 | 预期表现 |
|---|---|---|
| S1 | chat SSE 中途断开（关页面/断网） | stop_event 触发线程干净退出；已持久化的会话历史不丢 |
| S2 | REST 规划请求超时（前端 120s vs 网关 60s） | ⚠️ 已知差异点。决策（2026-09-22）：**前端超时压到 55s**（低于网关 60s），前端拿到干净的本地超时提示而非网关 504；网关不动 |
| S3 | 排程期间长时间无事件 | SSE ping 心跳保活，代理不掐连接 |
| S4 | 双标签页同会话并发发送 | 不崩、不串话；后到请求重新规划（后到覆盖语义，用户确认前仅保证不出错） |

## 三、外部调用失败软降级（W 组，pytest + mock）

| # | 场景 | 预期表现 |
|---|---|---|
| W1 | 天气 API 超时/异常 | 行程照出 +「天气预报暂时不可用…出行前请自行确认」 |
| W2 | 腾讯路线 API 挂 | 降级 estimate:local；来源标注「本地估算」，不冒充实时路况 |
| W3 | RAG 检索失败 | 无知识库参考段；免责声明兜底；不报错 |
| W4 | PG 挂（偏好读写） | 偏好静默跳过（日志 warning），规划照常 |
| W5 | 远期行程（预报窗口外） | 不发天气请求、不套用当前预报；无天气替换 |
| W6 | 坏天气但无室内候选 | 行程维持原样 +「没有可替换的室内地点，请备好雨具」 |

## 四、并发（C 组，pytest）

| # | 场景 | 预期表现 |
|---|---|---|
| C1 | 同用户两会话并发规划 | thread 隔离，行程互不污染 |
| C2 | 同 user_id 并发 upsert 偏好 | ON CONFLICT 单行写：不死锁、不抛错、最后写者胜 |
| C3 | 30+ 并发 /travel/plan（进程内） | 全部完成；LBS 未配置时走本地估算；无异常冒泡 |
| C4 | 同城市并发查天气 | TTL 缓存幂等，不重复打爆配额（以 mock 计数验证） |

## 五、输入边界（B 组，pytest）

| # | 场景 | 预期表现 |
|---|---|---|
| B1 | 不支持城市"去纽约" | 明示不支持 + 列可规划城市 |
| B2 | days=0 / 负数 / 超大 | 校验拦截（不产出 0 天/99 天疯行程） |
| B3 | 预算 0 / 负数 | 视为未提供预算；不触发预算校验误删 |
| B4 | 2000 字长文 / 纯表情 / 纯符号 | 不崩；抽不到槽位走追问 |
| B5 | 过去日期"9月21日" | 顺延到未来（明年同月日），星期正确 |
| B6 | "9月21到25日"（日期区间） | days=5，而非把"21日"读成 21 天 |
