# 熔断状态 Redis 共享设计（审查报告 #13，遗留事项 3.1）

> 状态：**设计对齐稿，未实施**。原因见 §7「实施前提」。
> 关联：`docs/2026-09-21-全仓代码审查报告.md` #13；现状代码 `backend/infra/circuit_breaker.py`。

## 1. 问题

`circuit_breaker.py` 预置 `llm / pg / chroma` 三实例是**进程内单例**（模块级字典 + threading.Lock）：

| 症状 | 影响 |
|---|---|
| 阈值放大 N 倍 | N 个 worker/副本各自计 5 次失败才各自熔断，系统级实际承受 5N 次失败 |
| 恢复探测 ×N | 每个 HALF_OPEN 进程各发一个探测请求，后端恢复期被 N 倍探测流量捶 |
| 状态漂移 | /health 的 `get_all_breakers()` 只反映单进程视角，告警口径分裂 |

## 2. 目标与非目标

**目标**
1. fail 计数与状态迁移（CLOSED→OPEN→HALF_OPEN→CLOSED）跨进程共享，行为与单进程语义一致。
2. Redis 不可用时**退回本地状态**（降级方向安全：熔断器宁可多熔也要保住后端；本地态至少维持现有行为，不劣化）。
3. 热路径（每次 Tool 调用都过 `_check_state` / `record_success`）零额外网络往返 —— 熔断判定在本地缓存态上做，Redis 只做状态广播/收敛。

**非目标**
- 不改三实例的 name / 阈值 / timeout 配置面；
- 不做分布式精确计数（目标 1 是"系统级先熔断"，不是"计数完全一致"）；
- 不动 `test_circuit_breaker.py` 已锁定的单进程状态机语义。

## 3. 方案：Redis 计数 + 本地状态机收敛（推举制）

不把整个状态机搬进 Redis（Lua 全量搬最复杂且每次调用都有 RT），而是拆两层：

```
本地（每进程）                     Redis（跨进程共享）
────────────────                  ────────────────────────
CircuitBreaker 状态机原样保留  ──► cb:{name}:fails   (INCR + TTL, 原子)
  - CLOSED/OPEN/HALF_OPEN         cb:{name}:open_at  (SET NX + TTL = timeout)
  - _probe_in_flight 探测位        （无 Lua；两个 key 各自原子，时序容忍见 §4）
  - 本地阈值判定用「Redis 计数 + 本机增量」的合并视图
```

### 3.1 失败计数（fail 上报）

- `record_failure()`：本地计数照旧（本地快速熔断兜底）+ 异步投递 `INCR cb:{name}:fails`（pipeline/fire-and-forget，不阻塞调用方），首次失败 `EXPIRE = timeout`（滑动窗口 = 熔断 timeout，与现有语义对齐）。
- 判定阈值时用 `本地计数 + Redis 计数快照` 的最大值：任一进程看到系统级超阈即熔断本地实例（宁可误熔，不可漏熔 —— 与熔断器保守方向一致）。

### 3.2 OPEN 广播

- 本地转入 OPEN 时：`SET cb:{name}:open_at <now> EX <timeout> NX`。
- 其它进程每 N 秒（默认 5s，热路径不查）惰性拉取一次 `open_at`：发现他人已 OPEN 且比自己新 → 本地 `_transition(OPEN)`，快速失败直接生效。
- HALF_OPEN 恢复成功 → `DEL cb:{name}:open_at` + `DEL cb:{name}:fails`（PUB/SUB 可选优化，P0 用轮询即可，探测窗口本来就带 timeout 量级的延迟容忍）。

### 3.3 探测位共享（P1 可选）

P0 各进程探测仍 ×N（与今天一致，但 OPEN 全局广播后探测总量显著下降）；
P1 用 `SET cb:{name}:probe NX EX <probe_budget>` 做跨进程探测位，抢不到者保持 OPEN 快速失败。

## 4. 一致性口径

- INCR 与 SET NX 两步之间无事务 —— 允许极小概率「计数已超阈但 open_at 未写入」，
  下一个失败者会补写（幂等 NX）；熔断是保守机制，延迟一拍熔断可接受。
- Redis 键全部带 TTL，进程崩溃后状态自动过期自愈，无需清理任务。
- `reset()`：本地复位 + DEL 两个 Redis 键（管理端手动复位要全局生效）。

## 5. 降级矩阵

| Redis 状态 | 行为 |
|---|---|
| 正常 | 共享计数 + OPEN 广播 |
| 连不上 / 超时 | 纯本地状态机（= 今天的行为），启动后每 30s 重探一次，恢复后自动重新共享 |
| 写成功读失败 | 用本地态，下次成功读取时收敛 |
| Redis 返回脏数据（类型错） | try/except 吞掉并记 warning，等同读失败，**绝不**让熔断路径抛错 |

## 6. 可观测

- `/metrics`（`get_all_breakers()`）每实例增加 `shared: true/false` 与 `shared_fails` 字段；
- `_Stats` 增加 `redis_degraded_at`（降级起始时间），降级 >5min 打 warning（非 fatal）。

## 7. 实施前提与工作量

- ⚠️ **`backend/infra/circuit_breaker.py` 与 `backend/tests/test_circuit_breaker.py` 当前有另一会话的未提交改动**（HALF_OPEN 单探测位 `_probe_in_flight`）。本方案在其上叠加，必须等该改动提交后再动工，否则同文件无法剥离提交。
- 预估：状态机改造 + 降级封装 ≈ 1 个半天；测试（含 Redis fake）≈ 半天；灰度开关 `CIRCUIT_BREAKER_SHARED_ENABLED`（默认 false，与域开关同模式放根 .env）。
- 验收：多进程（≥2 worker）注入失败 → 仅 N 倍中的 1 份流量打到后端即全局熔断；kill Redis → 行为退回单进程且无报错。
