# 产品需求与范围

本文定义 Agent 平台的用户、功能范围和质量目标，不记录逐轮实现状态、测试数量或历史验收结论。实际行为以代码、配置、数据库迁移、测试及专项文档为准。

配套阅读：[系统概览](architecture/system-overview.md)、[AI Runtime](architecture/ai-runtime.md)、[Agent 开发规范](development/tool-skill-guide.md)、[RAG 领域说明](domains/rag.md)、[数据库说明](DATABASE.md)。

## 1. 背景与目标

企业运营人员需要在商品、订单、库存、客服及知识资料之间切换。平台通过统一对话入口与声明式 Agent 能力，把检索、只读数据查询、报告和领域工作流组合为可追踪的业务结果。

目标：

- 用户用自然语言提交问题或业务任务，并获得有依据、可解释的结果。
- 对复杂任务进行受控拆解、调度和恢复；对有副作用的操作执行授权、确认和幂等保护。
- 让能力按统一 Tool、Skill、Runtime 契约扩展，保留身份隔离、可观测性和失败降级。

平台提供运营辅助，不代替业务系统的权威账本；具体写入仍通过受治理的业务接口完成。

## 2. 用户角色

| 角色 | 主要需求 | 权限边界 |
|---|---|---|
| 普通用户 / 运营人员 | 知识问答、数据查询、报告、旅游规划和客服咨询 | 仅访问获授权的租户与资源 |
| 管理员 | 管理知识库、模型配置、预算、权限、审批和运行状态 | 按平台角色授权；高风险管理操作留审计记录 |
| 客服坐席 | 接管转人工会话、处理工单、查看工作统计 | 按客服坐席身份及会话分配规则访问 |
| 未登录访客 | 访问统一入口和公开导航 | 不得调用受保护的业务接口 |

## 3. 功能需求

### 3.1 统一对话与任务路由

| ID | 需求 |
|---|---|
| FR-001 | 接受自然语言问题，支持流式展示回答和执行过程。 |
| FR-002 | 按任务类型将请求交给直接执行、Workflow、规划器或领域 Agent；支持中断、会话历史和断线恢复。 |
| FR-003 | 运行过程中的状态、工具结果和最终业务结果应有清晰区分，失败应能解释。 |

### 3.2 RAG 知识问答

| ID | 需求 |
|---|---|
| FR-RAG-001 | 知识库按授权范围隔离，支持文档 ingest、索引和评测数据管理。 |
| FR-RAG-002 | 文档切片和元数据处理应支持检索所需的类型、业务域、摘要及关键词信息。 |
| FR-RAG-003 | 回答应标注文档依据；证据不足或质量门禁不通过时，应明确拒答或降级。 |

检索流程和门禁约束见 [RAG 领域说明](domains/rag.md)。

### 3.3 SQL Agent

| ID | 需求 |
|---|---|
| FR-SQL-001 | 将自然语言转换为受约束的业务数据查询，并解释结果。 |
| FR-SQL-002 | SQL 执行前校验语句类型、Schema/列白名单、敏感字段、函数、行级范围和结果上限。 |
| FR-SQL-003 | 禁止未经业务治理的 SQL 写操作；查询失败时返回可解释状态，不伪造结果。 |

### 3.4 Agent 与 Workflow

| ID | 需求 |
|---|---|
| FR-AGENT-001 | 支持直接处理、DAG 工作流和多步任务规划等执行模式。 |
| FR-AGENT-002 | Tool、Skill、Capability 和 Workflow 使用仓库现有声明式注册与契约。 |
| FR-AGENT-003 | 支持依赖调度、并行步骤、超时、降级及可恢复的长任务。 |
| FR-AGENT-004 | 对工具输入输出和业务结果执行校验，保留追踪信息。 |

### 3.5 报告、客服与领域功能

| ID | 需求 |
|---|---|
| FR-REPORT-001 | 按模板生成运营报告，并对关键数值执行校验。 |
| FR-REPORT-002 | 支持定时或事件触发的工作流与邮件等受治理的交付方式。 |
| FR-CS-001 | 客服 Agent 支持知识应答、订单查询、待确认操作和转人工。 |
| FR-CS-002 | 退款、改签等敏感操作必须经过授权、用户确认及幂等保护。 |
| FR-CS-003 | 坐席工作台支持会话接管、状态流转、工单处理和统计。 |
| FR-TRAVEL-001 | 支持通过对话或表单补全旅行需求并生成结构化行程。 |
| FR-TRAVEL-002 | 行程需校验时间、地理、体力和预算约束；保留用户指定的必去项并解释冲突。 |
| FR-TRAVEL-003 | 旅行结果支持按日查看、地图或日历等适用的导出能力，并披露数据依据与时效。 |
| FR-SEL-001 | 支持按市场、差异化、财务和评审等步骤开展选品分析。 |
| FR-SEL-002 | 支持选品决策过程及相关运营指标的展示。 |

### 3.6 管理与治理

- 管理端应提供知识库、模型与供应商、预算、权限、审批和运行观测所需的入口。
- 模型、密钥和价格采用各自的配置、审计与审批规则；秘密值不得从接口回显。
- 运行状态、Trace、错误分类及工具/模型耗时应支持问题定位；敏感数据不得进入日志。

## 4. 质量与安全目标

以下时延是产品目标，是否达标须由对应评测或生产指标验证：

| 场景 | 目标 |
|---|---:|
| 普通单步知识问答 | 5 秒内 |
| SQL 查询 | 10 秒内 |
| 报告生成 | 30 秒内 |
| 多 Skill 批量任务 | 60 秒内 |

- **身份与租户**：身份以服务端验证后的上下文为准；所有资源访问执行授权与租户隔离。
- **数据安全**：SQL 参数化并限制只读范围；敏感字段按策略屏蔽；密钥加密存储且不写入日志。
- **副作用治理**：订单、退款、发布等写操作经过现有审批/确认机制和幂等保护。
- **可靠性**：外部服务失败须显式返回错误或按既有契约降级；禁止吞异常、静默丢任务或伪造成功。
- **可扩展性**：新增能力复用既有 Router、Runtime、Domain Agent、Skill、Tool 和注册机制，不另建平行框架。
- **可观测性**：关键链路保留结构化日志和 Trace，记录错误类别及工具/模型耗时，并保护敏感信息。
