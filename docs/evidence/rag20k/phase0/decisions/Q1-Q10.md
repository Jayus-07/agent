## 逐项明细

各 ID 的"待确认问题 / 暂定假设 / 未确认的影响 / 最晚确认点"四个字段逐字取自审计报告第 0 节，不再在两处重复维护；`decision` 字段如标注"暂定假设（未签字）"，即表示该数值只用于规划计算，不是已冻结门槛。

## 状态流转规则

1. 某项取得书面确认后：在 JSON 中填 `owner`（真实负责人）、`decided_at`（YYYY-MM-DD）、`evidence_refs`（会议纪要/邮件/合同等引用），`status` 改为 `confirmed`，同步删除 `decision` 中的"暂定假设（未签字）"标注。
2. 每次改动后运行：`D:/Python/python.exe backend/scripts/validate_rag20k_decisions.py docs/evidence/rag20k/phase0/decisions/Q1-Q10.json`（blocked 退出 2，schema 错误退出 1，全部确认退出 0）。
3. 阶段 0 出口门（`backend/scripts/check_rag20k_phase0.py`）要求全部 confirmed 才放行决策项；任何 blocked 都会使阶段 0 保持未通过。
4. 报告第 0 节原文是唯一的问题定义来源；本文件与 JSON 不得改写问题语义，只能更新状态与签字要素。
