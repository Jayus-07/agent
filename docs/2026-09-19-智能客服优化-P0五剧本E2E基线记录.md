- **C**：动作意图未触发 资格检查→proposal→确认卡 链路，回答停留在政策说明层（含引用）。对照规划稿 C 剧本"接通 CSConfirmCard / 不得只依赖文本确认"，**确认卡链路在全局入口未打通**（或需客服窗口 domain_hint=customer_service 才进 CS 子图——待 P0 评审定位）。

## 4. P0 补充：B/C 剧本根因定位与修复记录（2026-09-19，E2E 之后追加）

### 5.1 B 剧本根因（10/10 落空）

**结论：不是种子数据缺失，是入口路由语义。** 实测证据链：

1. `"order".orders` 中演示客户 99001 有 **15 笔种子订单**（数据都在）；
2. 全局入口（无 domain_hint）：订单查询走了主图 direct 路径（"信息查询"标签），未进客服域 → 拒答模板；
3. **客服窗口语义（`domain_hint=customer_service`，即前端 /agent 页右上角窗口使用的入口）：立即正常**——列出 DEMO-1006/1012/1010/1001 等订单及状态金额。

基线中 B-02 的「ORD-20260915 被截断」由缺陷 ②（见 5.3）造成，与路由无关；指定订单号不存在时客服域的拒答与引导是正确行为。

### 5.2 C 剧本根因（确认卡不可达）与修复

三段缺陷链，逐段修复：

| # | 缺陷 | 位置 | 修复 |
|---|---|---|---|
| ① | 缺槽位兜底 `"latest"` 按字面匹配 → `OrderNotFoundError`，退款确认卡永远无法生成 | `refund_service.py` / `after_sales_service.py` 的 `_get_order` | 新增 "latest" 语义化分支（`ORDER BY created_at DESC, id DESC LIMIT 1`），兑现 action.py 注释承诺；无订单时抛 OrderNotFound |
| ② | 订单号正则 `\b[A-Za-z]{2,10}-\d{2,12}\b` 对两段式订单号截断（`ORD-20260915-0042` → `ORD-20260915`） | `experts/action.py` + `experts/query.py` | 正则改为 `\b[A-Za-z]{2,10}(?:-\d{2,12})+\b`（多段连字） |
| ③ | 资格拒绝（`OrderNotEligibleError`）被当专家异常裸抛 → 通用报错"处理请求时遇到问题" | `experts/action.py::execute_action` | 捕获 `OrderNotEligibleError`/`OrderNotFoundError` 转为可读答复（含原因 + 下一步指引），status=success |

修复后实测（经 APISIX + 客服窗口）：

- 「我要申请退款」（缺订单号）→ latest=DEMO-1006（pending）→ **可读拒绝**：「订单状态 'pending' 不允许退款，仅支持… + 提供订单号/查全部订单指引」✅
- 「订单 DEMO-1012 申请退款」（paid，合规）→ **确认卡正常生成**：订单号/金额 ¥299.00/状态/「回复确认提交或取消放弃」✅
- B：「查一下订单 ORD-20260915-0042 的状态」→ 完整订单号呈现（不再截断）+ 正确的未找到引导 ✅

## 5. D 剧本核验结果（2026-09-19 补充，admin/admin 坐席 + e2e_p0ae 客户）

| 环节 | 结果 | 证据 |
|---|---|---|
| 工单落库 | ✅ | `customer_service.handoffs`：e2e-p0-D-01 = human_active / ticket_id=HANDOFF-E1882023；e2e-p0-D-07/10 = waiting_human |
| 队列可见 | ✅ ≈1468ms | 客户转人工 → 坐席队列可见（目标"入队可见 ≤2s"达标） |
| 坐席认领 | ✅ 原子 | waiting_human → human_active，`already_claimed=false`，agent_id=admin |
| AI 不抢答 | ✅（宽松口径） | human_active 下客户追问未触发 AI 业务回答 |
| 坐席回复落库 | ✅ | sender_type=human_agent，消息可经会话 messages 接口回读 |

发现与口径说明：

1. **坐席身份规则**：浏览器 JWT 通道 = 登录账号且**必须 admin 角色**（`_resolve_agent_identity` 服务端解析 user_name/user_id，前端/请求体声明无效）；服务间 API-Key 通道（BFF）才允许声明 agent_id。→ "坐席 id = 登录账号 id，谁登录固定是谁"成立。
2. **缺口 D-2**：human_active 期间客户经 `/chat/stream`（AI 入口）的追问**未写入会话消息流**——坐席看不到该条追问（AI 未抢答，但消息连续性断）。窗口正式消息通道是 WS（useCSChat），页面级核验待做后定性。
3. **网关边界**：APISIX 未配置 `/api/cs/conversations/**` 路由（404 Route Not Found）——CS 管理端页面全部经 :3200 BFF 直连后端（`X-Auth-Type: api-key` 服务通道）。P5 可观测/灰度时需决策是否补网关路由或维持 BFF 直连口径。
4. UX 小项：human_active 后客户再经 AI 入口提问，话术仍是"排队中"（未感知已认领状态），列 P2。
