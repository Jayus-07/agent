## 四、目标体验架构

### 4.1 信息架构：双端 + 三段 Route Group（衔接 ADR-001，URL 不变）

> **实施修正（2026-09-17 P1 开工前实测回写）**：v3 计划 P1-1 写作「frontend 内部建
> 三段 Route Group、移动 31 条路由」——但**双端物理拆分落地后 frontend/ 仅剩 6 页**
> （/、/login、/agent、/agent/tasks、/reports、/reports/[id]），管理端 37 页已在
> frontend-admin/。**三段分区事实上已由双 app 实现**（public+workspace=frontend /
> admin=frontend-admin），frontend 内部再做 Route Group 属纯装饰性移动，**P1 降级为
> 可选整理，不做**。P1 的实际价值落在：⑤ 双 nav 补「我的告警」入口、⑥ 残债清理、
> 用户端错误反馈接线。

- `(public)`：`/login`、`/`——无 Shell、免登录，1 页
- `(workspace)`：用户端 Shell（SidebarRail）。现有 6 页 + 新增 `/alerts`（我的告警，只读）= 7 页
- `(admin)`：管理端 Shell（AdminShell + 双 nav）。23 → P2 后 35 页
- **移动端策略**：仅 `(workspace)` 做 ≤768px 断点——侧栏收纳为底部四 tab（对话/任务/报告/我的）；`(admin)` 桌面优先，移动只保证不崩
- `(admin)` 移动端与小程序一样**不承诺**，写进 README 避免预期错位

### 4.2 角色与门禁模型（三级 RoleGate）

- 数据源：登录后解析 JWT `roles` claim → Zustand session store（一次解析全局可用）
- 组件：`<RoleGate allow={['admin']}>` 包裹敏感页；未授权渲染**页内 403 卡片**（保留 nav 上下文，不整页跳转）
- 矩阵：viewer → `(workspace)`；editor → `(workspace)` + 提交审核；admin → 全部
- 分层口径：UI 层 RoleGate 只是体验优化，**权限真闸在后端**（与 admin navConfig 注释口径一致，30b4936 后端语义不变）
- ⚠️ 与 B4 决策不冲突：B4 是「后端 resolve_operator_role 的 role 通道暂不开」；本节是**纯前端消费 JWT claim**，零后端改动

### 4.3 核心旅程闭环（五步）

提问 → 生成任务 → 报告产出 → **一键拍板（新增）** → **通知回环（新增）**

- 拍板卡片放报告详情页底部：决策项 + 选项 + 依据摘要，调 B1 新增 API；拍板结果回填 decision_log → 报告状态徽章联动 + 下轮问答可引用
  - **实施修正（2026-09-17 P0-③）**：拍板卡落点改在 **admin 任务详情页** `/selection-decision/[id]`（决策留痕归属选品任务）；已完成
- 通知：报告产出/拍板提醒走 EmailSkill（发送侧真实验收 = B6，等首个业务场景顺带验）
  - **场景已拍板（2026-09-17 用户确认）**：B6 首个业务场景 = **报告中心工作流结果邮件推送**——报告生成完成后由 EmailSkill 推送日报/决策报告给订阅者；实现落点在报告工作流的完成回调，验收时随 B6 顺带验

### 4.4 反馈语义层

> **实施修正（2026-09-17 P0-② 实测后回写）**：原计划「DOMAIN_ERRORS 填首批 8 码」经实读
> `errors.ts` + `errors.test.ts` 修正——其中 **5 个 HTTP 派生码（网络/超时/401/403/429）已由
> 既有机制覆盖**（`CLIENT_ERRORS` + `FALLBACK_BY_STATUS`，L227-239 有测试锁定），
> 无需重复登记；**3 个 RAG 语义码后端尚未在响应体发送**（属 C4 前后端联合项），
> 且 `errors.test.ts` L222-225 有守卫测试锁定「登记表刻意为空」——强行填充即「臆造」。
> 落地形态改为：`DOMAIN_ERRORS` 保持为空（守卫不动），**RAG 三语义码的行动映射
> 预登记在 `ErrorCard` 层**（`RAG_REJECTION_ACTIONS`），后端 C4 接通（响应体携带
> code 字段）时**零前端改动点亮**；权限申请页/版本历史页尚不存在，故只给文案
> 不给假跳转。

- RAG 拒答三型差异化指引（ErrorCard 预登记）：无证据→「换个问法重试」；权限→「申请权限或联系管理员」；版本→「确认制度版本或查看历史版本」
- 错误卡片统一三段式：发生了什么 / 我能做什么 / 详情折叠（`src/components/shared/ErrorCard.tsx`，纯函数 `resolveErrorFeedback` 可直测）

### 4.5 等待体验

- 阶段化进度：把 ThinkingPanel / AgentTimeline 的组件语言复用到 CS 链路——意图分类→检索→生成→质检四段，每段有完成态
- 乐观 UI：任务提交即出骨架卡 + 任务号；SSE 心跳已有，补「阶段完成数」徽章
- 体验目标：155s 的主观等待压缩为「每 10 秒有可见变化」（延迟根因优化仍归 C17，需用户授权）

### 4.6 空态体系（管理端）

- 三层空态：接口未就绪（骨架 + 「建设中」）/ 权限不足（403 卡）/ 数据为空（引导 CTA）
- C11 约束「不写假数据」→ 空态即首体验：必须可导航（回 admin 首页 / 知识库入口），不允许死白板

## 五、设计 Token 扩展（衔接 globals.css，不替换）

现有：中性灰 + accent #4D6BFE + 气泡/侧栏变量。新增四组（写进 globals.css `:root`，Tailwind 镜像补 `colors.status.*`）：

```css
:root {
  /* 状态语义色（中国市场惯例：涨红跌绿） */
  --status-up: #d92b2b;      /* 涨/正向 */
  --status-down: #0f9d58;    /* 跌/负向 */
  --status-warn: #d97706;
  --status-info: var(--accent);

  /* 等待进度色阶（阶段化进度组件用） */
  --progress-done: var(--accent);
  --progress-active: rgba(77, 107, 254, 0.35);
  --progress-idle: var(--border-subtle);

  /* 间距（4px 网格，供新组件统一） */
  --space-1: 0.25rem;  /* 4px  */
  --space-2: 0.5rem;   /* 8px  */
  --space-4: 1rem;     /* 16px */
  --space-6: 1.5rem;   /* 24px */
  --space-8: 2rem;     /* 32px */
}
```

明暗主题切换（ArchitectUX 默认要求）**列为 P2**：当前两端纯浅色、无暗色资产，先做 token 双套预留，不做半成品暗色。
