# 全仓审计与安全重构执行手册

> **先证据后改动；先标准后审计；先小批合并后继续。** 适用于目录重构、模块收敛、脚本/测试清理。既有 Worktree 和当前正在施工的旅游 V2、记忆及其它任务优先保护，不因本手册覆盖。

## A. 全仓审计维度与证据

| 维度 | 需要逐处核对 | 证据 |
| --- | --- | --- |
| 入口与拓扑 | APISIX → API → Router/Domain/Skill/Workflow → Repository/Provider；直接 API 旁路是否授权 | 路由/注册源码 + 调用链 |
| 目录归属 | 文件是否处在所属层、是否确实重复；runtime/workflows 等同名近似目录 | import 与动态加载、测试、构建引用 |
| 数据与授权 | 租户/资源范围、迁移、CAS、幂等、缓存/Checkpoint 的权威归属 | 读写 SQL 与并发/越权用例 |
| 错误处理 | HTTP/Tool/业务/领域状态，重试、熔断、硬依赖、后端失败前端假成功 | 注入故障回归 |
| 前端接口 | 3 前端复用边界、SSE/WS/REST 契约、错误与加载态、移动布局 | DTO 与浏览器交互 |
| LLM/Agent | Router、Prompt 版本、Token/成本、记忆、RAG/SQL 与工具治理是否重复 | 真实调用入口及 Trace |
| 质量与交付 | CI、测试选择、依赖缓存、环境、文档链接、监控/告警 | 配置、检查结果、复现步骤 |
| 杂项资产 | tmp/data/artifacts/docs/reports/脚本等是否在 Git 跟踪且需要保留 | `git ls-files`、引用、资产清单 |

结果分类按 [目录规范](repository-layout.md) 标成 KEEP / FIX / MERGE / MOVE / DELETE / REVIEW，不允许全仓同名文件直接认定“重复”。每项审计记录：**事实源（path+symbol）、偏差、影响范围、风险 P0/P1/P2、分类、预计变更、验证命令、回滚方案、负责人/在途工作树**。缺证据标 `NOT VERIFIED`。

## B. 三批施工顺序

### Batch 0 — 基线冻结，不改代码

核对远程 main/ref、未提交工作树、在途任务、容器/数据库共享资源与 CI 状态；保存目录树、导入图、接口清单、现行注册表、关键测试基线。盘点已跟踪的 tmp/data：**先数据安全和引用调查**，不给出直接删除指令。

### Batch 1 — 低风险整理

修复文档断链、重复静态 import、明确命名冲突、标记生成物、完善 `.gitignore`（不自动移除 Git 跟踪文件）。一次变更只碰一个责任边界；T0/T1 确认运行入口未变化。正式移出数据与脚本前需清点消费者和恢复副本。

### Batch 2 — 中风险归一

选择一个确实重复的实现（例如重复 DTO/HTTP 客户端/错误映射），定义旧→新调用矩阵，先建兼容出口，迁移调用方与测试，再退役旧入口。移动包时检查 Python import、`__init__` 自注册、副作用 import、动态 `importlib`、配置字符串路径、pytest fixture、Docker COPY/volume、CI、脚本和前端相对 import。所有跨层路径迁移至少 T2；杜绝“编译通过但未注册”的静默失败。

### Batch 3 — 高风险架构收口

Router/Graph、SSE、Checkpoint、跨域 Service、SQL 权限、任务及账本属于高风险；只有证实真实边界问题才开展，事先 ADR + 兼容/数据迁移计划 + T2/T3 验收和回滚。**不为漂亮的目录树强行把独立业务域合并。**

## C. 每批合并门禁

- 用隔离分支/Worktree；当前工作树有他人改动则停止并报告；禁止覆盖、`reset --hard`、强推、清理共享容器/数据卷。
- 改动前记录入口、所有引用、目标路径；删除文件需提供无活跃依赖证据；迁移 SQL 只走现有迁移器。
- 至少运行 T0 和对应 T1；影响公共状态、安全、调用路径或目录移动必须 T2；生产发布或真实数据影响才需 T3。不可运行项写 BLOCKED。
- 验收须包含原用例、异常/拒绝/并发用例、接口/API/前端消费端、Trace/成本归因；不可用扩大 mock、skip 或删断言换 PASS。
- 提交审阅时列出新增、迁移、合并、删除、保持原状的清单；成功后再合并到 main，下一批从最新 main 开始。可以正常 revert 单批提交；数据/Schema 迁移须另有回滚策略。
