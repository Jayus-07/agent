# 提示词治理收口实施计划（2026-10-06）

> 状态：施工中｜验收清单：`docs/reports/2026-10-06-提示词治理收口验收清单.md`
> 背景：2026-10-06 提示词长期使用审计发现四类结构性问题。本计划把「优化建议」落成可验收的改造。
> 铁律：G1/G2/G4 照旧；模板引擎不换（保持 str.format 严格校验）；不改 SSE/graph 契约；无破坏性 API 变更。

## 0. 问题回顾（审计结论，2026-10-06）

| # | 问题 | 实查证据 |
|---|---|---|
| P1 | 治理覆盖面缺口：4 个高频 LLM 决策点是裸字符串，不进 lock / 版本 pin / 发布门禁 / 审计 | `tool_selector.py::_SYSTEM_PROMPT`、`general_chat_node.py::_SYSTEM_PROMPT`、`travel/services/llm_intent_service.py::_SYSTEM_PROMPT`、`follow_up_resolver.py::_llm_rewrite` 内联 f-string |
| P2 | 事实内嵌漂移：planner 模板硬编码「15 张表」，实际 schema_config 已是 18 表 7 schema | `prompts/defaults/planner_system.yaml` vs `sql/data/schema_config.py` |
| P3 | 版本机制有轨无车：43 prompt 中 41 个停在 v1、change_kind 全 NULL、评测覆盖无台账 | `prompts.lock.json` 版本分布实测 |
| P4 | 工程脆弱性：planner 模板 29 处 `{{` 转义；JSON 输出解析失败零指标 | planner_system.yaml / 各解析点静默回落 |
| P5（新发现） | **断线缺陷**：`customer_service.chat_fallback` 有 defaults YAML、有消费代码（`chat_fallback.py::render_prompt`），但 **registry 无注册项** → loader 启动即告警跳过 → 运行时恒走模块常量降级，注释宣称的「权威=注册表」实际从未生效 | 启动日志 `key 'customer_service.chat_fallback' not in registry, skipping` |

## 1. 目标 / 非目标

**目标**
1. 五个 prompt 纳入 registry + defaults + 版本/lock/trace 治理（4 收编 + 1 断线修复）。
2. planner.system 事实变量化：schema 概览从 `schema_config` 派生，JSON 示例外置代码常量，YAML 零 `{{` 转义，稳定段前置（prefix cache 友好）。
3. LLM JSON 解析失败可观测：统一走 `json_extractor` 策略链 + `llm_json_parse_fail_total`（label: source）。
4. 评测覆盖矩阵可派生：脚本生成「43+ key × 证据」报告，禁手抄。
5. 双源定位写死：defaults YAML = 种子 + 降级兜底 + 灾备，README 声明。
6. 默认模板变更 → DB 新版本草稿的升级路径脚本（激活仍走既有发布门禁）。

**非目标**
- 不给 high risk prompt 新建评测数据集（覆盖矩阵把缺口亮出来，补集单独排期）。
- 不动 `PLAN_CRITIQUE_SYSTEM` 等 registry 已纳管但仍有 legacy 常量的键（无漂移风险，另有更值当的活）。
- 不改模板引擎、不引 Jinja。
- 不在本会话激活任何 DB prompt 版本（激活 = 管理员经发布门禁）。

全部 DB 可管（不设 code_controlled）：与 `router.llm` 同待遇，发布门禁/lock/pin 全量生效。

### 消费点改造模式（统一三层：注册表优先 → 模块常量逐字降级 → 漂移守卫测试）

```python
def _system_prompt() -> str:
    try:
        from backend.prompts.service import prompt_service
        return prompt_service.render_sync("router.tool_selector").text  # 记账+trace+pin
    except Exception:
        return _SYSTEM_PROMPT  # 注册表不可用时逐字一致降级（chat_fallback 同款约定）
```

- `render_sync`（非 `get_template_sync`）：自动获得 usage 记录 + `record_prompt_version`（trace 可答「当时用的哪版」）+ 请求级 pin 生效。
- YAML 模板与 legacy 常量**逐字一致**；新增守卫测试锁定相等（防双源漂移）。
- `follow_up_resolver._llm_rewrite` 的 f-string 拼接改为模板渲染，JSON 字面量按 str.format 转义，渲染结果与现网逐字节一致。

### 附带修复

- `tests/prompts/test_registry_defaults.py::test_total_count`：45 → 50。
- 模块 docstring 更新（chat_fallback「待混线解锁后迁移」的过期说明）。

## 3. 批次 B：planner.system 事实变量化

### 模板重构（新 v2 模板，YAML defaults 更新）

变量从 2 个 → 3 个：`schema_overview`（新）、`capabilities_schema`、`output_example`（新，替代 cap_example 在示例块中的位置；`cap_example` 从模板移除）。

```
你是任务规划专家。……
## 数据库概览（由 schema 配置自动派生，勿凭记忆猜表）
{schema_overview}
## 可用能力（及参数格式）
{capabilities_schema}
## 输出格式与示例（输出契约，代码侧维护）
{output_example}
## 能力选择指南 / edges 含义 / 规则 1-9   ← 纯指令文字留在 YAML，零 {{ 转义
```

- 排序 = 稳定段（schema 概览）→ 半稳定段（能力表）→ 指令，prefix cache 友好；动态用户问题本就在 human 消息，不进 system。
- **派生源（G2）**：`schema_overview` 由 `backend/sql/data/schema_config.py::SCHEMA_CONFIG` 派生（静态配置 dict，非 DB 连接，不违反「Planner 禁调 DB」——禁的是运行时查询）；`output_example` 由 `backend/prompts/planner.py::build_output_example(cap_example)` 生成（与 `_normalize_plan` 的 DAG 契约同文件演进）。
- 兼容性：DB 现网 v1 模板只有 `capabilities_schema/cap_example` 两变量 → renderer 按「模板实际所需」取变量，多传不报错（仅 code_controlled 才拒多余变量），v1/v2 渲染路径并存无感。
- legacy 常量消灭双源：`prompts/planner.py::PLANNER_SYSTEM` 改为 import 时从 defaults YAML 派生（`load_defaults().get("planner.system")`，兜底内联旧文），公开名不变，`prompts/__init__` 导出不变。

### DB 升级路径（不激活，只造草稿）

新脚本 `backend/scripts/promote_prompt_default.py`：读 YAML default → `prompt_service.create_draft(key, template, change_kind="minor", change_note=...)`。幂等防重（同 hash 草稿已存在则跳过）。**激活一律走管理端发布门禁（评测→审批→发布），脚本绝不碰 active_version。**

## 4. 批次 C：JSON 解析失败指标

- 新模块 `backend/observability/llm_output_metrics.py`（独立文件，避免与他人在改的 `metrics.py` 混线）：
  `llm_json_parse_fail_total{source}` + `record_json_parse_fail(source)`（软失败）。
- `shared/json_extractor.py`：`extract_json / extract_json_or_empty / extract_json_strict` 增加可选参数 `source: str = ""`，全策略失败时记数。默认参数 = 完全向后兼容。
- 接入点（source=prompt_key 或模块名）：

## 10. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 新模板渲染行为变化 | 模板/常量逐字一致守卫测试；v1/v2 变量兼容有测试 |
| planner prompt 内容变化影响规划质量 | v2 只做「来源变化」不做「语义变化」（事实同源派生）；激活前强制 planner 评估 |
| 混线冲突 | 目标文件均不在他人未提交清单；metrics 走新模块；提交全部双重路径限定 |
| registry 数量断言类测试散落 | 全仓 grep `PROMPT_REGISTRY` 断言点收口后再改 |

**回滚**：全部为代码/文档变更，`git revert` 对应提交即回滚；无迁移、无 schema 变更、无 DB 激活动作。
