# 多域隔离收官实施计划（含完整验收清单）

> 日期：2026-10-06 ｜ 分支：`feat/domain-isolation-closure` ｜ 基线：main @ 1528862（0431bc3 + 并行 docs 提交，对本计划零影响）
> 前置事实：RoutingEngine 六阶段已合并 main 并验收全绿；客服抽屉（`domain_hint=cs` 锁域）与旅游页（`POST /api/travel/plan/stream` 直达）两条专属入口已上线；选品漏斗后端图与 `/selection-funnel/*` API 齐备、无前端专属页。

## 一、背景与拍板方向

已拍板（本计划即其落地）：**AI 助手不执行域规划，只留问答 + 引导；三域回专属页。**

隔离的两个半成品必须补齐：

1. **补偿机制缺一半**——主图识别到域诉求后，缺「引导卡带参跳转」；没有它，隔离 = 把路由成本转嫁给用户，是产品倒退。
2. **第四扇门没装**——选品有后端无前端页，对话面只能靠主图 prefilter 截流。

设计原则（本计划全部决策的判据）：

- **契约先行**：先定交接契约，再装门和卡；否则每加一个域，主图硬编码一套跳转。
- **能力集中、状态分家、设施共享**：域图执行与跨轮状态严格隔离；llm 代理 / trace / 审批门 / RAG 权限 / 预算 / 七分类错误口径全员共享，不动。
- **脚手架要有退役日**：凡是过渡机制，必须带退役指标（§七）。

## 二、范围内 / 范围外

**范围内**：M0 部署地基 → M1 handoff 交接契约 → M2 全局入口执行/引导判据 → M3 主图引导卡 → M4 选品专属页 → M5 Planner 可见清单收缩（E9）→ M6 文档与口径归位。

**范围外（明确不做）**：

- 分诊收敛（正则词表 → CoarseIntentClassifier 泛化）＝长期项，不在本计划，仅在 §七留指标。
- 客服知识质量门（A6 口径 10.1%/16%）属另一条线，本计划不碰客服知识链路。
- 不改任何 Tool 签名（`tool_contracts.lock.json` 零漂移）。
- 不动客服抽屉锁域链路（`domain_hint=customer_service` 语义不变）。
- 不做层级规划（总 plan → 域子 plan）——已论证为反方向，域内规划权维持现状形态。

## 三、里程碑依赖与排期

```
M0 部署(0.5d) ──► M2 判据+flag(1d) ──► M3 引导卡(2-3d)
```

## M1 handoff 交接契约（1-2 天）—— M3/M4 的前置

**内容**：把「转接」定义成稳定契约：`转接 = 目标域 + 参数包 + 状态锚点 + 引导原因`，前后端共享同一份定义。

**关键决策（设计九项中的形态选择）**：

1. **传输载体 = 新增 SSE AUX 帧 `handoff`**，不复用 `clarification` 帧（语义混淆，且 clarification 语义是「向用户要信息」，handoff 是「给用户出口」，方向相反）。AUX 帧按现行口径允许中段任意位置任意次出现，`ping` 不计帧序——新增 AUX 类型是向后兼容演进。
2. **契约模型落点**：`backend/orchestration/contracts/handoff.py`（Pydantic，`HandoffPayloadV1`）。
3. **前端同构类型**：`frontend/src/types/handoff.ts`；双端消费**同一份 JSON fixture** 做对齐测试（防字段漂移，不靠人肉同步两份类型）。
4. **参数包按域声明 schema**（必填最小化）：旅游 `destination/days/party_size/budget_cny/must_go`；选品 `category/platform`；客服 `prefill_question`。契约版本字段 `v: 1`，破坏性演进走 v2 并存期。

**改动点**：

| 文件 | 动作 |
|---|---|
| `backend/orchestration/contracts/handoff.py` | 新建：契约模型 + 各域参数 schema |
| `backend/orchestration/graph/event_schema.py` | 登记 `handoff` AUX 帧 |
| `backend/tests/test_sse_event_schema.py` | handoff 帧回归用例（中段任意次出现） |
| `backend/tests/orchestration/test_handoff_contract.py` | 新建：必填校验/未知域拒绝/按域参数校验 |
| `frontend/src/types/handoff.ts` | 新建：同构类型 |
| `frontend/src/types/handoff.test.ts` | 新建：消费同一 JSON fixture 的对齐测试 |

**验收**：
- [ ] 契约单测全绿：缺必填拒绝 / 未知 target_domain 拒绝 / 参数包超出域 schema 拒绝
- [ ] `tests/test_sse_event_schema.py` 全绿（handoff 帧已登记，帧序门禁不破坏）
- [ ] 双端 fixture 对齐测试通过（同一 JSON 两端解析字段一致）
- [ ] 旧前端对未知帧容忍：SSE 解析器遇 `handoff` 帧不崩、不误判终态（实机走查项）

**回滚**：新增 AUX 帧对旧链路零影响；契约文件独立，可直接删除。

## M2 全局入口执行/引导判据（1 天）—— M3 的前置

**内容**：把拍板判据落进 prefilter 出口，用 feature flag 按域灰度，默认行为不变。

**判据（已拍板口径）**：

```
一次性答案（主图现能力可答完）→ 留主图执行
  例: "福州有什么景点"(travel.poi_search) / "三坊七巷在哪"(map.lookup)
产出作品（要画布/多轮槽位/专属工作台）→ handoff 引导
  例: "帮我规划3天行程" / "这批数据帮我选品" / 转人工类客服诉求
```

**实现**：

- 每域一个入口模式开关：`CS_GLOBAL_ENTRY_MODE` / `TRAVEL_GLOBAL_ENTRY_MODE` / `SELECTION_GLOBAL_ENTRY_MODE` ∈ `execute | guide`，**默认 execute（行为零变化）**，与既有域总闸（`CS_ENABLED` 等）串联：总闸关 → 域图整体不可达，模式开关只决定「命中后执行还是引导」。
- 改 `backend/orchestration/graph/routing/prefilter_chain.py` 出口：guide 模式下 prefilter 命中不再直进域图节点，改产 `HandoffPayloadV1`（经 router_node 注入 SSE 流）。
- **域锁入口不受影响**：`CSDrawer` 带 `domain_hint` 的请求跳过本判据（锁域语义不变）；旅游页直达端点同理。
- `travel.poi_search` / `map.lookup` 作为「一次性答案」保留在主图（判据左侧的兜底执行能力）。

**验收**：
- [ ] 三开关默认 execute：合并后主图行为与基线逐字节等价（回归门：既有 prefilter 用例全绿不改断言）
- [ ] `TRAVEL_GLOBAL_ENTRY_MODE=guide`：「帮我规划3天行程」→ 产 handoff 帧，**不进**旅游域图（trace 无 travel_graph 节点）
- [ ] guide 模式下「福州有什么景点」→ 仍走主图 poi_search 直答（判据左半边）
- [ ] 开关切回 execute → 行为与基线等价（回滚验证实测）
- [ ] CSDrawer 域锁请求不经过模式开关（用例锁定）

**回滚**：开关全 execute = 完整回滚，零代码回退。

## M3 主图引导卡带参跳转（2-3 天）—— 依赖 M1+M2

**内容**：主聊天渲染 handoff 卡（图标 + 一句话 + 带参跳转按钮），把隔离转嫁的路由成本赎回来。

**改动点**：

| 端 | 文件/动作 |
|---|---|
| 后端 | guide 模式下经 SSE 发 `handoff` 帧（M1 契约）；引导话术与域归属进 trace tags（`handoff_target_domain`） |
| 前端 | 主聊天流渲染 HandoffCard 组件（消费 `frontend/src/types/handoff.ts`）；点击 → 路由跳转带参 |
| 跳转 | 旅游：`/travel?destination=福州&days=3&...` → 旅游页解析参数预填 TravelBrief；客服：打开 CSDrawer 并预填 `prefill_question` |

**验收**：
- [ ] 实机全链：主图问「带爸妈福州玩2天」（guide 模式）→ 引导卡出现 → 点击 → 旅游页 brief 已预填 `destination=福州 / days=2 / party_size=3`，直接可续跑
- [ ] 参数部分缺失：卡片只带已有参数，落地页不崩、缺失槽位走旅游域既有追问链
- [ ] execute 模式下主图永不出现引导卡（用例锁定）
- [ ] SSE 帧序实测：`meta → status/log/delta → handoff(AUX) → done`，既有帧序门禁全绿
- [ ] 引导卡点击埋点上报（§七退役指标的数据源）
- [ ] `npx tsc --noEmit` + 前端 npm test 全绿；截图归档

**回滚**：M2 开关切 execute（卡片不再出现）；前端组件独立可摘。

## M4 选品专属前端页（3-5 天）—— 依赖 M1；可与 M3 并行

**内容**：补上第四扇门。后端零新增（图 + API 全备），纯前端页面 + 主图选品 prefilter 切 guide。

**页面最小闭环（一期）**：导入池上传（`POST /selection-funnel/import/file` / `import/text`，上传入口从「主图对话里说」改为「页面上传」）→ 候选列表（`GET /import/candidates`）→ 跑漏斗 → 报告展示。二期再接赛道画像（`/market/snapshot`）与痛点（`/reviews/pain-points`）。

**跨轮契约（本期最容易翻车的点，验收重点）**：

- 页面持有 `conversation_id`，漏斗追问（need_info）后用户补充 → 带同一 conversation_id 续跑，候选不丢；
- 漏斗候选已由后端同步进 ConversationContext（E1 机制，`sync_funnel_candidates_to_context`）——页面消费该载体，不自建第二份状态（G2）。

**主图联动**：`SELECTION_GLOBAL_ENTRY_MODE=guide` 后，主图选品话术 → 引导卡跳选品页（复用 M3 卡片组件）。

**验收**：
- [ ] 实机全链：上传 CSV → 候选池可见 → 跑漏斗 → 报告渲染，全程无「主图对话」参与
- [ ] 淘空（empty_pool）/ 缺槽位（need_info）短路话术如实展示，无「服务暂时不可用」假错误
- [ ] 跨轮续跑：need_info 后补充参数 → 同会话续跑 → 候选与上下文不丢
- [ ] guide 模式：主图说「帮我选品」→ 引导卡 → 跳选品页带 `category/platform` 参数
- [ ] `npx tsc --noEmit` + 前端测试全绿；截图归档

**风险**：四域中前端工作量最大；一期只做最小闭环，画像/痛点面板明确列为二期，防止扩范围。

**回滚**：页面独立路由，不上导航即下线；prefilter 切回 execute。

## 五、执行纪律（本仓库铁律，执行 agent 必读）

- 局部 pytest **必须 `--no-cov`**（否则用例全绿 EXIT=1 并覆写覆盖率产物）。
- 提交双重路径限定：`git add -A -- <paths>` + `git commit -m "..." -- <paths>`；每里程碑收口立即提交，防并行会话收编。
- 改 SSE 帧必过 `test_sse_event_schema.py`；改 planner 必跑 planner 评测；本计划不改 Tool 签名，若执行中需要改 → 先停下扩范围评审（lock 重生成随变更提交）。
- 动容器前 `docker ps` 查归属；连接 PG 显式 5433。
- 全量 pytest 冻结纪律：跑之前确认无其他会话在跑。

## 七、退役指标（脚手架管理——企业长期做法的验收）

| 脚手架 | 指标 | 退役条件 |
|---|---|---|
| prefilter execute 语义 | 域话术主图执行占比 | 持续趋零后，execute 整体退役（只留 guide） |
| 引导卡 | 曝光→点击转化 + 主图域话术总量 | 入口成熟（用户直接进专属门），占比下降即健康 |
| 主图域兜底能力清单 | poi_search/map.lookup 在主图的命中量 | 域页搜索能力成熟后评估撤收 |

**长期终态自检**：明年接入第五个域 = 一个页面 + 一份契约实现，天级完成、不碰主图布线——达不到即契约没立住，回炉 M1。
