# 数据查询权限与会话追问设计

## 目标

在现有 SQL Agent、SSE 和会话上下文能力上，完成以下闭环：

1. 常用 NL2SQL 示例能稳定命中所需关联表，并修复列名幻觉导致的执行失败。
2. 管理端和用户端都根据服务端可信角色、权限和数据范围展示及执行 SQL 查询。
3. 管理端数据查询和用户端聊天支持同一会话内的结构化 SQL 记忆与追问。
4. 管理端和用户端复用现有 `meta/status/log/done/error` SSE 事件，不新增破坏兼容性的事件类型。

## 根因

SQL Agent 的“全量表目录”只用于 LLM 路由阶段；当前关键词快路径对“分类”只返回 `product.categories`，生成器因此看不到 `order.order_items.price`，根据常见命名猜出 `oi.unit_price`。现有校验能在数据库执行阶段发现 `UndefinedColumn`，但 SQL Agent 将 `syntax_error` 作为终态，不会进入修复重试。

## 设计

### 权限

- 继续使用 `AuthorizationContext` 的 `sql.read` 和 `data_scope`，禁止前端传入角色、用户或数据范围作为授权依据。
- SQL 生成前基于 `SQLPolicyGuard` 得到当前主体可见的表集合；路由和生成器只接收这个集合。
- 表目录只返回当前主体可访问的表和可见列；单表浏览在入口处同样执行可访问性判断。
- 生成、校验、行级范围注入、执行四个阶段都再次经过策略约束；权限拒绝不带详细表名和字段名回显。
- 继续保留只读、敏感列拒绝/脱敏、LIMIT、超时和审计。

### SQL 正确性

- 关键词路由为高频分析问题补齐依赖表：分类销售额需要 `product.categories`、`product.products`、`order.order_items`；库存、订单金额、竞品价格同样声明完整依赖。
- 路由支持调用方传入已授权表集合和上一轮上下文表集合，结果取交集，不允许扩大权限。
- 列名执行失败归一为可修复的 `schema_mismatch`，仅允许有限次数带错误反馈重新生成；每次重试重新执行 Validator 和 SQLPolicyGuard。
- Prompt 继续声明“只允许 supplied schema 的列”，但正确性不依赖 Prompt 自觉。

### 会话记忆与追问

- 在现有 `ConversationContextRepository` 增加 `sql_query_context`，通过 Redis/Memory 现有 TTL、租户和用户三元组隔离。
- 只保存结构化安全摘要：上一轮问题、改写后的独立问题、表名、列名、SQL 模板、时间/筛选条件摘要、状态和权限指纹；不保存完整结果行。
- 请求增加 `session_id` 和可选 `reset_context`，管理端在浏览器会话中复用 session id；用户端继续复用已有聊天 session id。
- 追问先做确定性识别；命中“上次/刚才/按月/只看/改成/为什么/这些结果”等信号时，将上一轮独立问题和当前追问合并后再路由与生成。上下文不足时返回澄清，不猜测。
- 每轮追问都以当前角色和数据范围重新授权；权限指纹变化时不复用旧授权结果。
- 成功或可安全总结的失败结果才更新 SQL 上下文；显式 reset 清除上下文。

### 动态体验

- SQL 流式查询复用既有 SSE 事件：按顺序展示需求理解、表路由、SQL 生成/校验、Tool 执行、结果完成。
- 日志 payload 增加结构化 `phase`、`tool`、`status`、`tables`、`follow_up` 等字段；前端对未知 payload 保持兼容。
- 用户端扩展现有 AgentTimeline/ProgressCards；管理端新增轻量查询过程面板和“基于上次查询”提示。
- 错误展示具体可行动原因、重试按钮和生成 SQL 折叠区，不展示越权表名、内部 SQL 错误堆栈或敏感值。

## 验收标准

1. `统计各商品分类的销售额排名` 生成并执行使用 `order.order_items.price`，不再出现 `oi.unit_price`。
2. 四个常用示例在授权范围内成功或返回真实 `no_data`，不因路由遗漏关联表失败。
3. viewer 无 `sql.read` 时接口、表目录和流式查询均被拒绝；editor 看不到 internal/personal 不可表达范围的表；admin/super_admin 按既有策略可查。
4. “按月展示”“只看某分类”“为什么下降”等追问能基于同一 session 复用上一轮上下文；换用户、换租户或权限收窄时不会串用。
5. 后端 SQL、权限、上下文、SSE 有回归测试；两个前端通过 TypeScript 与现有测试。
