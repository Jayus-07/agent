# 数据查询权限与会话追问 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 NL2SQL 常用示例的表/列错误，并让管理端与用户端在可信权限范围内支持流式过程展示、结构化会话记忆和 SQL 追问。

**Architecture:** 复用现有 `AuthorizationContext`/`SQLPolicyGuard` 做服务端权限边界，复用 `ConversationContextRepository` 保存租户+用户+会话隔离的 SQL 摘要；SQL Agent 在生成前收到授权表结构，在执行列错误时有限反馈重试。管理端新增流式 SQL API，聊天端继续消费现有 SSE v2，两个前端只扩展既有 `log` payload。

**Tech Stack:** FastAPI、Pydantic、sqlglot、PostgreSQL、Redis/Memory ConversationContext、Next.js 14、React、TypeScript、Vitest、pytest。

**Spec:** `docs/superpowers/specs/2026-10-02-数据查询权限与会话追问设计.md`

## Global Constraints

- 所有授权只信任服务端 `Principal`/`AuthorizationContext`，不信任请求体角色、用户或 scope。
- SQL 只能是只读 SELECT，继续经过表/列/函数/LIMIT/行范围/readonly executor 全链路。
- 现有 13 类 SSE 事件保持兼容，不新增独立事件类型。
- 结构化上下文主键必须是 `(tenant_id, user_id, conversation_id)`，不保存完整 SQL 结果行。
- 修改前保留并行会话已有工作区改动；只改本计划列出的目标文件。
- 局部 pytest 必须带 `--no-cov`。

## Review Focus

- 关键词快路径只选一张维表时，聚合查询必须补齐 FK 依赖表：由 Task 1 的路由回归测试覆盖。
- LLM 生成不存在列时，必须重试并最终使用数据字典真实字段：由 Task 2 的 Agent 重试测试覆盖。
- viewer/editor/admin/super_admin 看到的表目录和可执行范围必须一致：由 Task 3 的权限矩阵测试覆盖。
- 追问不能跨用户、租户、会话或权限变化串上下文：由 Task 4 的上下文隔离测试覆盖。
- SSE 断流/失败/未知 payload 不得让管理端和用户端卡死：由 Task 5 的事件归约测试覆盖。
