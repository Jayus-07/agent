## 建议施工顺序（依赖驱动）

1. **P0 部署件**（1.1-1.3, 1.7）：compose 补 worker + .env/compose 注入 CELERY_*（broker db1 / result db2）+ worker healthcheck。不修这个，任务功能在 Docker 部署下等于不存在。
2. **P0 链路验证**：投测试任务，看 `LLEN agent` 涨落 + db2 result 键。
3. **P1 表扩展**：tasks 补列（worker/queue/trace_id/started_at/finished_at/duration_ms/error_type/traceback/max_retries）+ 补索引；用 Celery signals 统一埋点收口。
4. **P1 系统健康端点**：`/observability/system-health`（admin 闸 + 30s 后台采集缓存），先做 Redis/DB/worker/队列四块。
5. **P2 任务中心**：管理员任务 API（筛选/统计/retry/revoke/审计）→ 管理端页面（复用 SSE 与 gateway 页的缓存/降级模式）。
6. **P2 可观测扩展**：redis_exporter/postgres_exporter/celery-exporter + worker 离线/队列积压/失败率告警规则。

> 注：1.2 的「.env 无 CELERY 键」意味着当前本地若跑通过任务，走的是宿主机 `localhost:6379`（config 默认值恰好在本机成立）——容器化部署才是断点，本地成功会掩盖问题。
