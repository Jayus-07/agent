## 0. 背景与目标形态

原 `frontend/` 是单 Next.js 应用，混杂业务功能（对话/入库/报告）与运维功能（配置/trace/评测）。
拆分决策（2026-09-16 与用户确认）：

- **拆成独立应用**（非单应用路由组）；
- **用户端**：网页（保留现有 Next.js）+ 微信小程序（Taro）双端可用；
- **管理端**：独立 Web 应用；
- **技术栈**：Web 两端统一 Next.js 14 + React 18 + Tailwind + zustand；小程序 Taro 4 + React；
  SSE 不作为换栈理由（现有 fetch 流式方案已跑通，小程序端用 `Taro.request enableChunked`）。

目标结构：

```
frontend/          # 用户端 Web（:3100，保留现有，移除管理页面）
frontend-admin/    # 管理端 Web（:3200，从 frontend 复制裁剪而来）
frontend-mp/       # 用户端小程序（Taro，编译微信小程序）
packages/shared/   # ⏸ 后续：两端共享 api 封装/types/业务 store/SSE 解析（npm workspaces）
```

## 2. 关键契约（跨会话续作用必读）

- 登录：`POST /api/auth/login {username,password,deviceId}` → `Result{data:{token,expiresIn,userInfo}}`；
  refresh 走 HttpOnly Cookie（小程序端无 Cookie，过期即重登，微信登录待做）。
- SSE 聊天：`POST /api/chat/stream` body `{question, session_id, request_id, department?}`，
  事件 `event: meta|status|log|delta|thinking|todo|usage|file|ping|done|error`，`data:` 为 JSON 行；
  `delta.content` 增量正文，`done.elapsed/sources/usage` 终态。
- 中止：`POST /api/chat/abort {session_id, request_id}`。
- 网关：APISIX :9080（`AUTH_GATEWAY_URL`）；Next dev 经 rewrites `/api/*` → `API_URL`（默认 :8000）。
- SSE 注意：Next `compress: false` 是打字机效果的前提，两端 next.config 均不可开压缩。

**踩坑记录（复现排查用）**：
1. babel-preset-taro 需要显式安装 `@babel/preset-react` + `@babel/preset-typescript`（7.x，
   8.x 要求 @babel/core 8 会 ERESOLVE 冲突）；
2. `@/` 别名 tsconfig paths 只管类型，webpack 必须在 `config/index.js` 配 `alias`；
3. 页面路径约定 `<dir>/<name>` 与文件名严格对应，统一用 `pages/<name>/index`，
   `reLaunch` 跳转路径必须同步；
4. 构建日志的 tail 可能只剩错误栈，真实报错在日志前段（`✖ Errors:` 之后）。

## 5. 风险与备注

- 管理端目前与用户端同一套 JWT，无角色区分；Phase 4 之前任何人可访问 :3200（仅内网/本地使用）。
- 两端 api/lib 整份复制会产生漂移，Phase 3 shared 抽取前不要在单端新增跨端通用逻辑。
- 小程序端 token 存 Storage 且无 HttpOnly Cookie refresh，token 过期即重新登录（安全上可接受，
  体验优化等微信登录落地）。
- `frontend/.next-dev-*` 为启停脚本的临时 distDir，继续按原注释定期手清。
