# 安全、幂等、预算与反馈闭环——前端体现方案

结论：采用“用户端反馈层 + 管理端治理层”双入口，不新建独立 FinOps 系统。

- `frontend`：只呈现当前用户可理解、可操作的预算状态、失败原因、幂等状态、澄清与反馈。
- `frontend-admin`：负责用量观察、预算策略、模型价格版本、双人审核、反馈候选治理。
- 预算判断、成本计算、权限判断、审核身份仍以服务端为准；前端只展示服务端结果。

原始依据：[后端实施规划](D:/Program Files/workplace/agent/docs/superpowers/plans/2026-09-18-安全幂等预算反馈闭环实施规划.md)。

## 一、假设与拍板决策

### 1. 当前假设

| 编号 | 假设                                 | 本方案采用的明确口径                                         |
| ---- | ------------------------------------ | ------------------------------------------------------------ |
| A1   | “前端”包含两个应用                   | 用户端 `frontend` 与管理端 `frontend-admin` 都纳入           |
| A2   | 后端核心逻辑已完成，但允许补管理 API | 不改预算算法；补充查询、审核、审计和前端专用 DTO             |
| A3   | 用户 3/50 USD 的含义                 | 它是“新建用户覆盖策略”的预填值；未建立用户策略时仍继承租户，不宣称所有用户自动拥有 3/50 |
| A4   | 币种                                 | 全部只显示 USD；删除前端固定汇率及 CNY 切换                  |
| A5   | 时间                                 | API 返回 UTC ISO 8601；界面统一转换为 `Asia/Shanghai`        |

| A8   | 权限                                 | 普通用户只能查看自己的预算；viewer 看聚合统计；只有 admin 可改策略、导入价格和审核价格 |

| A10  | 前端灰度                             | 沿用后端 10% → 50% → 100%，每档至少运行 24 小时              |

### 3. 当前实现需要正视的缺口

1. 当前预算表没有 `user_default` 作用域，解析逻辑是“用户覆盖不存在则继承租户”。因此前端不能把 3/50 描述成全局用户默认值。见 [quota.py](D:/Program Files/workplace/agent/backend/infra/llm/quota.py) 和 [迁移 0014](D:/Program Files/workplace/agent/backend/sql/alembic/memory/versions/0014_budget_quota_price_tables.py)。
2. 当前价格仓储的 `approve_version()` 一次接收两个审核人，无法证明两个独立登录会话分别审核；也没有面向前端的预算/价格管理路由。见 [pricing.py](D:/Program Files/workplace/agent/backend/infra/llm/pricing.py)。
3. 现有 Token 页仍硬编码 `USD_CNY = 7.25`，并显示“按 `AVAILABLE_MODELS` 单价估算”，与 PostgreSQL `model_price` 权威来源冲突。见 [Token 用量页](D:/Program Files/workplace/agent/frontend-admin/src/app/observability/tokens/page.tsx)。
4. 前端虽已登记 9 个错误码，但 `ApiError` 只保留 `code`；`retryable`、`handoff_available`、`trace_id`、`source`、`details` 尚未贯通。SSE error 目前也只是把 message 写成 Markdown。见 [client.ts](D:/Program Files/workplace/agent/frontend/src/api/client.ts)、[useSSE.ts](D:/Program Files/workplace/agent/frontend/src/hooks/useSSE.ts)。
5. 用户反馈目前是乐观切换 👍/👎，失败时只写控制台；未采集原因、纠错内容和期望答案，也没有管理端候选审核页。见 [MessageActions.tsx](D:/Program Files/workplace/agent/frontend/src/components/chat/MessageActions.tsx)。

## 二、目标与成功标准

### 1. 目标

让后端闭环在前端形成四个可验证结果：

1. 用户知道发生了什么、是否可重试、何时恢复、能否转人工。
2. 写操作不会因连点、网络重试或刷新造成重复副作用。
3. 用户和管理员能看到真实预算状态，管理员能追溯策略来源。
4. 模型价格从导入、双审、灰度到生效均有可审计界面。

### 2. 成功标准

| 编号 | 成功标准                                                     | 检查方法                                                     |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| FS1  | HTTP、SSE 两条链路均完整保留 9 个错误协议字段                | 两个前端各运行 9 个错误码 × 2 种传输形式契约测试，共 36 组通过 |
| FS2  | `BUDGET_EXCEEDED` 能区分请求预算、用户日/月额度、租户日/月额度和缺价熔断 | 6 类夹具均展示唯一文案和唯一动作                             |
| FS3  | 硬额度达到 100% 后，聊天发送和写副作用按钮不可执行；只读页面仍可访问 | E2E 断言被禁按钮请求数为 0，只读 GET 返回 200                |
| FS4  | soft 或 audit 策略超额时不禁用操作，且页面不出现“无限”       | soft、audit 两组 E2E 通过；页面文本扫描“无限”命中数为 0      |
| FS5  | 同一逻辑写操作连续点击 20 次，浏览器最多发送 1 个在途请求，后端副作用次数为 1 | 浏览器网络断言 + 后端适配器调用断言                          |
| FS6  | 网络重试和 401 刷新复用原 `Idempotency-Key`；用户新建操作生成新键 | API 单测比较请求头                                           |
| FS7  | 管理端显示显式策略、继承来源、当前生效值和下次重置时间       | 平台、租户、用户三组夹具字段全部匹配                         |
| FS8  | 管理端预算总额与 PG 查询差异不超过 `0.000001 USD`            | 验收 SQL 与 API 原始值对账                                   |
| FS9  | 价格版本必须经过两个不同 admin 的两次操作才能进入灰度状态    | 同人二审返回 409；异人二审后状态转换成功                     |
| FS10 | 价格历史没有编辑和删除入口，导入只产生新版本                 | DOM 中不存在编辑/删除按钮；数据库旧行未变化                  |
| FS11 | 价格覆盖率不足 100% 时不能启用成本硬熔断或完成价格灰度       | 按钮禁用且后端直接调用同样拒绝                               |
| FS12 | 负反馈可提交原因和纠错，生成同租户 pending 候选              | 用户端提交、管理端查看、跨租户 403 三组测试通过              |
| FS13 | 两个前端无 CNY 切换、无固定汇率、无 `AVAILABLE_MODELS` 权威价格文案 | `rg` 扫描目标文件命中数为 0                                  |
| FS14 | 两个前端 `tsc --noEmit` 与 `npm test` 退出码均为 0           | 保存四条命令及退出码                                         |

## 三、范围边界

### 1. 做

- 完整消费统一错误协议，并根据服务端字段决定重试、等待、转人工或联系管理员。
- 为聊天、上传、导出、邮件、数据采集、竞品写操作接入稳定幂等键。
- 把 Tool 选择失败呈现为澄清卡，不显示内部 capability 名称。
- 用户端提供本人预算摘要、80% 预警、100% 阻断及重置时间。
- 管理端提供用量与预算看板、预算策略治理、预算事件查询。
- 管理端提供价格版本导入、校验、双审、灰度和历史查询。
- 用户端补充结构化负反馈；管理端增加评测候选审核页。
- 管理端首页增加预算超限、缺价和待价格审核待办。

### 2. 不做

- 不在浏览器计算权威成本、剩余额度、继承结果或是否允许执行。
- 不让前端直接访问 PostgreSQL、Redis 或 Prometheus。
- 不允许浏览器提交 `user_id`、`tenant_id`、审核人身份或操作者身份。
- 不增加 CNY 换算；没有权威汇率系统前只显示 USD。
- 不允许修改或删除已导入价格行。
- 不将“审计豁免”显示为“无限额度”。
- 不因预算超限锁定整个应用。
- 不把 pending 反馈候选自动写入 golden set。
- 不新建独立 FinOps 前端项目。
- 不借本次改造重构无关页面。

### 3. 停止条件

满足任一条件，停止对应阶段：

1. `BUDGET_EXCEEDED` 未提供 `budget_kind`、`limit_kind`、`reset_at`，却准备实现精确用户提示。
2. FQ1 未确认，却准备向用户展示“默认 3/50 USD”。
3. 价格审核接口仍允许一次请求提交两名审核人。
4. 审核人身份来自请求体而不是认证上下文。
5. 预算策略修改没有旧值、新值、操作者、原因和时间审计记录。
6. 价格版本没有版本级状态，却准备显示“已灰度”或“已生效”。
7. 价格覆盖率低于 100%，却准备开放硬熔断开关。
8. 用户预算查询不能证明只返回当前用户数据。
9. 跨租户管理查询没有服务端权限过滤。
10. 本次实施不使用 `test-quality-guard`；以现有契约测试、回归测试、类型检查和实际退出码作为质量门。

### 3. 前端不得绕开的 API 契约

以下是前端开工前必须冻结的接口，不代表当前均已存在。

| 接口                                                      | 最小返回/提交字段                                            | 权限                            |
| --------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------- |
| `GET /api/budgets/me`                                     | `currency`、`mode`、user 日/月 used/reserved/limit/ratio/reset_at、tenant_blocked、policy_source | 当前用户                        |
| `GET /api/admin/budgets/summary`                          | 总成本、价格覆盖率、临近额度主体数、阻断数、未结算预占数     | viewer 返回聚合；admin 可看明细 |
| `GET /api/admin/budgets/subjects`                         | scope、ID、显示名、日/月 used/reserved/limit、enforcement、ratio、policy_source | admin                           |
| `GET /api/admin/budgets/policies`                         | 显式策略、生效策略、继承来源、`updated_at`                   | admin                           |
| `PUT /api/admin/budgets/policies/{scope}/{id}`            | 金额字符串、enforcement、audit_exempt、变更原因、`expected_updated_at` | admin + `Idempotency-Key`       |
| `GET /api/admin/budgets/events`                           | 80%/100% 事件、主体、周期、发生时间                          | admin                           |
| `GET /api/admin/model-prices/versions`                    | 版本、来源、状态、两名审核人、有效期、覆盖率                 | admin                           |
| `POST /api/admin/model-prices/imports/validate`           | 行级校验结果、重复键、覆盖缺口；不落库                       | admin                           |
| `POST /api/admin/model-prices/imports`                    | 版本、来源、有效期、已验证行；只追加                         | admin + `Idempotency-Key`       |
| `POST /api/admin/model-prices/versions/{version}/reviews` | `decision`、`reason`；审核人由后端取得                       | admin                           |
| `POST /api/admin/model-prices/versions/{version}/canary`  | 开始/完成灰度；完成时返回三项门槛结果                        | admin                           |
| `GET /api/idempotency/operations/{client_key}`            | `running/succeeded/failed/conflict/uncertain`、安全结果摘要  | 原操作者                        |
| SSE `clarification`                                       | `question`、用户文案选项、`handoff_available`；不下发 capability ID | 当前会话                        |
| 统一错误 `details`                                        | `budget_kind`、`limit_kind`、`scope_type`、`period_type`、`reset_at` | 按错误发生者                    |

所有金额字段传 `"3.000000"` 这类字符串；禁止传 JS 浮点数作为价格修改值。

### 4. 统一错误的前端动作

| 错误码                            | 前端动作                                        |
| --------------------------------- | ----------------------------------------------- |
| `INVALID_PARAM`                   | 定位表单字段；不显示重试按钮                    |
| `PERMISSION_DENIED`               | 显示联系管理员；不重试                          |
| `NOT_FOUND`                       | 提供返回列表或刷新；不原样重试                  |
| `TIMEOUT`                         | 保留输入，显示重试                              |
| `UPSTREAM_UNAVAILABLE`            | 保留输入，显示重试和 trace ID                   |
| `RATE_LIMITED`                    | 按 `retry_after` 倒计时，归零前禁用重试         |
| `IDEMPOTENCY_CONFLICT`            | 禁止重新提交；提供“查看原操作状态”              |
| `BUDGET_EXCEEDED`                 | 不显示重试；显示预算层级、恢复时间或联系管理员  |
| `INTERNAL_ERROR`                  | 显示重试和 trace ID；不显示异常类名、路径、堆栈 |
| 任意码且 `handoff_available=true` | 额外显示“转人工”，调用既有客服入口              |

## 七、验收清单

### 错误与恢复

- 

  9 个错误码在两个前端均有唯一中文文案和唯一动作。

- 

  HTTP 与 SSE 使用同一个错误解析结果。

- 

  ```
  retryable=false
  ```

   时没有重试按钮。

- 

  ```
  handoff_available=true
  ```

   时显示既有人工转接入口。

- 

  ErrorCard 不显示异常类名、本地路径或堆栈。

- 

  trace ID 可复制，空 trace ID 时不渲染复制按钮。

### 幂等与写操作

- 

  每个逻辑写操作生成一个 

  ```
  Idempotency-Key
  ```

  。

- 

  网络重试、401 刷新和立即重试复用原键。

- 

  用户修改参数后生成新键。

- 

  提交期间按钮不可重复点击。

- 

  20 次连续点击只产生 1 次副作用。

- 

  ```
  running
  ```

   显示处理中，不自动发起第二次写请求。

- 

  ```
  conflict/uncertain
  ```

   不允许自动重试。

### Q4 预算

- 

  请求预算展示 8 次调用、32,000 token、0.50 USD、2 次重试、1 次 fallback。

- 

  用户覆盖策略新建表单预填 3.00/50.00 USD，但未配置用户明确显示“继承租户”。

- 

  租户默认显示 60.00/1000.00 USD。

- 

  平台默认租户显示 20.00/300.00 USD。

- 

  内部租户显示 100.00/2000.00 USD。

- 

  测试租户显示 10.00/100.00 USD、soft。

- 

  80% 只显示一次预警事件。

- 

  100% hard 禁止模型与写副作用。

- 

  soft 超额继续执行并显示“测试环境软额度”。

- 

  audit 显示“审计豁免”，不显示“无限”。

- 

  日/月重置时间按上海时区显示。

- 

  原始金额与 SQL 相差不超过 0.000001 USD。

### Q8 价格

- 

  所有金额只显示 USD。

- 

  界面金额固定显示 2 位。

- 

  导入和 API 金额保留 6 位。

- 

  六个维度全部可识别：input、output、cache_read、cache_write、reasoning、tool_call。

- 

  token 单位为 per 1M；tool_call 单位为 per call。

- 

  历史版本无修改和删除入口。

- 

  两名不同 admin 分两次完成审核。

- 

  缺价列表能定位 model、component、dimension。

- 

  价格覆盖率不足 100% 时不能完成灰度。

- 

  源码无固定 USD/CNY 汇率。

- 

  成本页不再声称 

  ```
  AVAILABLE_MODELS
  ```

   是权威价格源。

### 反馈与权限

- 

  👎 可提交原因、纠错内容和期望答案。

- 

  提交失败会恢复未选择状态。

- 

  负反馈产生一条 pending 候选。

- 

  普通用户不能访问候选审核页。

- 

  pending/rejected 不能 promotion。

- 

  重复 promotion 不生成重复评测用例。

- 

  viewer 响应不包含用户级预算明细。

- 

  前端隐藏按钮与后端 403 两层权限均通过。
