## 3. P2 FollowUpResolver（0e0f135）
- ConversationContext：`backend/orchestration/context/conversation_context.py` —— 主键 `(tenant_id, user_id, conversation_id)`；TTL+LRU 进程内存储；日期沿用 `start_date + days`（无 date_range）；`last_verified_source_ids` 只存 ID；`source_context_fingerprint` 反映 destination/cities/topic。
- Resolver：`follow_up_resolver.py` 规则优先（指代词表/天次/续接模板/overwrite 正则，实体优先级 最近实体>city>destination>topic，确定性无随机）；LLM rewrite 已实现（严格 JSON、max_tokens=200、解析失败不猜→澄清）但默认关闭（`FOLLOWUP_LLM_REWRITE_ENABLED`，与 CS_REDIRECT_MAIN_LLM_ENABLED 同一成本管控先例）。
- Router 接线：`runner.py` 全局入口在 memory 加载后、进图前执行 `_resolve_followup_for_request`；Router/各域消费 standalone，`state["raw_query"]` 保留原文；CS 锁域（domain_hint=customer_service）跳过解析；澄清走既有 status→delta→answer→done 通道（无新增 SSE 事件类型）；Trace tags 记 follow_up_detected/rewrite_method/context_slots_used/need_clarification。

- 测试结果：方案 §P2.12 全部 7 用例 + 确定性/同步/指纹共 10 passed；orchestration 既有 495 passed（TestCsRedirectMain 3 例为干净 HEAD 上的既有环境失败，与本改动无关）。

## 10. 剩余风险
1. **P2 检索侧 evidence 复用未接线**：上下文只保存 `last_verified_source_ids` + 指纹并在切换时清理（权限面完整），RAG 检索尚未把历史 source 作为低权重候选 —— 接入需动 RAG adaptive retrieval，按兼容性要求刻意留给后续变更单。
2. **LLM rewrite 默认关闭**（`FOLLOWUP_LLM_REWRITE_ENABLED=false`）：规则层已确定性覆盖验收用例；开启后对规则不可靠的复杂 follow-up 生效，需评估 token 成本后再开。
3. **memory_records 无 tenant_id 列**（历史 schema）：L3 tenant 隔离依赖 tenant-scoped user_id 键；如需列级 tenant 隔离须另立迁移（本层仅 user 级校验，测试已注明）。
4. **TestCsRedirectMain 3 例既有失败**（干净 HEAD 复现，环境相关：LLM/Redis 依赖），与本次改动无关，建议另单排查。
5. **会话持久化与前端联动**：P6 改密后的新 token 已返回给调用方；前端 `frontend-admin` 登录态对 `mustChangePassword` 的强制跳转 UI（改密引导页）未在本轮实现（后端 403 错误码 `must_change_password` 已可被前端识别），属前端体验补齐项。
