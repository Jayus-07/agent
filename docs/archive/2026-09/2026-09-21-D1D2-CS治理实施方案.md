## 一、审计结论（真实代码与库端事实）

### D1 多轮追问（根因已定位）

完整调用链：

```
chat.py:chat_stream(L184) → GraphRunner.iter_events(runner.py:L147)
  → memory.start_session(L295，取 L1 历史)
  → router_node(router_node.py:L65)
      → travel prefilter（travel_prefilter.py:L26 纯正则，「那当地有什么特色美食」零命中）
      → router.route(query) → rag_skill
  → tools/rag.py:search_knowledge_tool(L13)  ← 只透传原始 question，无任何上下文解析
  → pipeline.ask → RAGChain.ask(chain.py:L651) → hybrid_retrieve → EvidenceGate 拒答
```

关键事实：
1. **已有** HistoryAware 改写（`chain.py:L628`，`ENABLE_HISTORY_AWARE_RETRIEVAL` 默认 true），但依赖 `chat_history` 且只做文本级改写；「云南」这类信息只存在于 travel 域 checkpointer 的 `TravelBrief` 里，主链路拿不到。
2. **travel 域槽位已存在**：`travel/models/brief.py:L58 TravelBrief` 有 destination/origin/start_date/days/party_size/budget_cny/preferences/must_go/avoid（**无 date_range 字段**，由 start_date+days 表达），跨轮靠 checkpointer（thread_id=conversation_id）+ `merge_brief` + `brief_fingerprint`。
3. **没有 session 级结构化槽位存储**；**evidence/source_ids 不跨轮持久化**（sources 仅在 done 帧）。
4. 轻量 LLM 调用先例：`retrieval/multi_query.py:L136` `llm.invoke(..., max_tokens=200)`，rewrite fallback 可复用此模式。
5. 主图 checkpointer thread_id 每轮唯一（runner.py:L374-380），**主链路跨轮状态只能靠 memory 层，不能靠 graph state**。

## 二、修改计划（按优先级）

### P1 · D1 会话级结构化上下文 + FollowUpResolver

| 项 | 内容 |
|---|---|
| 新增 | `backend/orchestration/context/session_context.py`：SessionContextStore（PG 持久化，键=session_id，槽位 destination/cities/date_range/days/party_size/preferences/current_topic；操作 set/overwrite/clear，显式切换目的地=overwrite） |
| 新增 | `backend/orchestration/context/follow_up_resolver.py`：①规则指代解析（当地/那里/那边/这个地方/附近/这边/它/这个/第二天/然后呢/还有呢/便宜一点呢/推荐几个呢…）结合槽位与 current_topic（城市比国家优先）；②规则不可靠 → LLM rewrite fallback（复用 multi_query.py 轻量调用模式，输入 current_query+structured_context+last_user_turn，输出结构化 JSON：standalone_query/resolved/used_context/need_clarification/clarification_question）；③无上下文可依 → clarification，**不瞎猜** |
| 接线点 | `tools/rag.py:search_knowledge_tool` / rag skill 入口前统一解析（不动 router_node、不动主图 8 节点）；travel 域复用 brief 作为槽位源（brief 本身已在 checkpointer 跨轮） |
| 槽位回写 | 每轮解析后用 travel extract_brief 同款规则抽取 destination/cities 更新槽位；「算了，改成成都」→ overwrite |
| evidence 复用 | SessionContextStore 增存上一轮 **verified source_ids**（仅 ID，不存生成文本），follow-up 检索时作为候选补充，保持引用可追踪 |
| 澄清交互 | **复用现有 SSE 事件**（done 帧 answer 文本输出澄清问题 + trace 打 need_clarification 标记），不新增事件类型 |

### P3 · CS 事务边界统一

- 统一模式：**路由层 use-case 持有事务** `async with session.begin()`；service 只做业务+flush，不 commit
- 落地：①offers 三函数去 `_txn`、去路由显式 commit → 统一 begin 块；②cs_admin 的 claim/close/rating/agent message 从裸 `AsyncSessionLocal()` 改 get_session dependency + begin 块；③handoff/dispatch service 内部 begin 上移到调用方
- 不破坏 F2/F3：行为等价重构，accept 后立即发消息的事务可见性语义保持（先提交再返回）
- 测试：现有 dispatch/offers/concurrency 全量回归（test_p3_concurrency_pg.py 等）

风险：中。涉及 6+ 个写路径，靠现有并发测试兜底；`if session.in_transaction()` 判断全部消灭。

### P4 · CS 事件一致性（轻量 outbox 接入）

- claim/close/rating/agent message 的事件改走**现有 PG outbox**（同事务 append_event + commit，复用 relay_pending_events dispatcher 与其重试），替换 fire-and-forget 的 AgentHub.publish；rating 的静默 `pass` 改为失败计数+日志
- WS 事件名不变；成本可控（outbox 链路现成）

### P5 · F1 后端资源权限加固
