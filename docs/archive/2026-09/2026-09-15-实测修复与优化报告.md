## 三、真缺陷修复（按严重度）

### A. 架构级 / 高危

**1. 并行 Send 状态合并覆盖真实成果**（`de8b9c2`）
- 现象：复合问题跑完后 reporter 判"全部步骤失败"，用户拿到空回答。
- 根因：`state.py::_merge_step_results` 是朴素 `dict.update(right)`；并行分支各自返回 **dispatch 时刻的全量快照**（他人步骤仍是 running 旧视图），后返回的分支把先返回分支的 **success 覆盖成过期 running**。
- 修复：按状态进展优先级逐步骤择优（success > failed/skipped > running > pending），并进一步让 **Skill 只返回自有步骤**（`8237054`），从根源消除过期快照。
- 影响面：**所有 plan 并行路径**。

**2. 答案缓存越权污染**（`61470cd`）
- 现象：内部制度问题经网关表现为"查不到"，同一问题换个身份有时又能查到。
- 根因：缓存键 = `query|kb|version|filter|model`，**不含主体身份**；而主体授权过滤发生在检索之后（按 subject_type/department 剔除越界文档）——customer 主体的拒答被 employee 主体复用。
- 修复：缓存键增加身份 scope（`subject_type:department`）。

**3. LLM 降级话术冒充模型输出**（`c2f43e6`）
- 现象：LLM 不可用时 SQL 报错"只允许 SELECT 查询，检测到 Alias"，与真实原因（401）隔三层。
- 根因：韧性层把"AI 服务暂时不可用…"话术作为**正常模型内容**返回，下游结构化消费者（SQL 生成/Planner JSON）把它当 SQL/JSON 解析。
- 修复：默认改为 **fail-fast 抛原异常**；保留开关；降级消息加 `llm_degraded` 标记并提供 `is_degraded_response()` 判定。
- 实测：注入无效 key → `RAISED OpenAIAuthenticationError 401`，SQL 报错直指 `Invalid API-key`。

### B. 功能失效

**4. `retrieve_knowledge` 双检索腿 100% 失效**（`af11fbe`）
- 根因：`bm25.search()`（LangChain BM25Retriever 应为 `.invoke()`）+ `get_relevant_documents()`（CustomRetriever 应为 `.retrieve()`）两处方法名错误，被 except 软降级吞掉 → 恒返回空。BusinessAnalyzer 等下游拿不到任何知识。
- 修复后：`报销的审批流程是什么` 从空 → 414 字符真实内容。

**5. PDF 版面分析路径从未生效**（`7a39393`）
- 根因：PyPI 包 `pymupdf-layout` **不提供顶层模块 `pymupdf_layout`**（装进 `pymupdf.layout` 命名空间）；且代码调用的 `analyze(page)` 也不是真实 API。
- 处置：守卫显式置 False + 写明正确接线姿势（零行为变化）。

**6. 客服失败回复无意义**（`5942630`）
- 现象：匿名用户请求退款 → 返回"已收到您的问题…正在处理中，请稍候。"
- 根因：专家 `failed` 时 error 直接掉进泛化占位语，**从未呈现给用户**。
- 修复：鉴权/权限/超时/通用四类映射；实测变为"这项操作需要先确认您的身份，请登录后重试 / 回复转人工"。

**7. 事件归属串线**（`4baf376`）：并行时 step1 失败挂在 rag_skill 名下、完成事件重复播报 → 按 capability 反查属主过滤。
**8. guard 误杀**（`4baf376`）：`查询技术部有多少人` 被判"笼统"短路 → 查询意图豁免 + 业务词表补齐；话术去电商化。
**9. reporter 弱汇总**（`4baf376`）：拒答话术(10 字符)绕过长度门槛透传、SQL 0 行静默丢弃 → 空话术识别 + 显式交代。
**10. direct 路径泄漏内部标签**（`de8b9c2`）：`### 直接执行 sql.query` → 用户可读标签表。
**11. 容器依赖缺失**（`c2f43e6`）：容器内缺 7 个包，其中 **redis 缺失导致缓存/记忆/限流/Trace 全线静默降级**。

## 四、性能优化（实测前后）

| 场景 | 优化前 | 优化后 | 手段 |
|---|---|---|---|
| 旅游规划（暖机） | 14.4s | **6.4s** | 预过滤顺序重排（跳过白烧的 CS embedding 1.0~3.4s）+ 路段缓存与并行预热 |
| 旅游规划（冷启首请求） | 385s（网络抖动时） | **24.5s** | LBS 熔断快速失败（3 次失败开路 60s）+ 预取 4s 硬性预算 |
| 首个请求冷启 | 30s+（LLM 客户端初始化） | ~0 | 启动后台预热 LLM 客户端 + 域检测索引 |
| 域检测（每次请求） | 1.0~3.4s | 命中缓存 ~0 | `detect_cached`（5min TTL）+ `cs_rule_hit_count` 廉价预判 |
| 路线段（5 段） | ~5s 串行 | ~1s | 同日相邻段并发预热进缓存 |

> ⚠️ **口径更新（2026-09-18 起失效，勿当现状引用）**：上表「域检测（每次请求）1.0~3.4s」
> 对应的**向量通道已于 2026-09-18（`3f88b4f`）删除**。现行 `DomainDetector.detect()` 为**纯正则**，
> 实测冷路径 ~21µs、命中缓存 ~1µs。该行数字仅代表 **2026-09-15 当天**的历史测量。
> 「预过滤顺序重排」这一项本身仍然有效（顺序保留至今），但**其收益来源已不再是省 embedding 往返**，
> 而是判定语义（客服优先 > 旅游 > 选品）。

## 八、运维约定（本次固化，已写入项目 MEMORY）

- 容器栈 **改代码必须重建镜像**（app/rag-service 均无代码卷）。
- **compose `environment` 是白名单式**，新增凭据/base URL 极易漏传 → 已统一 `env_file: .env`（显式条目优先级更高）。
- **凭据注入禁用 sed/shell 插值**（本次把 `agent_readonly` 密码写坏，排查半小时）；改用「宿主生成 .sql → docker cp → psql -f」。
- **直连 8000 测 RAG 必须带 `department`**：未声明身份按对客最严 fail-safe，内部库(policy_*)会被授权矩阵整体剔除 → 拒答（这是设计正确行为，非 bug）。
- **`pip show <pkg>` ≠ `import <module>`**：分发包名与模块名常不一致；写可选依赖守卫用 `importlib.util.find_spec(真实模块名)`。
- 排障方法论：SSE 事件是**分支局部视图**，final state 才是 reporter 看到的；两者不一致时查 trace/日志定位。
