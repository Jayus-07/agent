## 一、机制盘点（代码层，实测取证）

| 要素 | 现状 | 证据 |
|---|---|---|
| 灰度判定 | 客服域：`session_id` MD5 稳定哈希分桶（`digest % 100 < CS_ROLLOUT_PERCENT`）——同会话恒定命中同组，不随重试漂移 | `orchestration/graph/cs_prefilter.py:267-274` |
| 白名单 | `CS_ROLLOUT_WHITELIST`（指定会话强制进实验组，验收/内部用户通道） | 同上 :269 |
| 实验组打标 | trace.tags `cs_variant=treatment/control`（对比评测数据面） | cs_prefilter.py `_stamp_variant` |
| 放量配置 | `CS_ROLLOUT_PERCENT`（0-100 环境变量，代码默认 100/关由 .env 决定）；域总闸 `CS_ENABLED`；旅游/选品/预订/商务各域独立 env 开关（默认全关） | `config/customer_service.py:258`、AGENTS.md 开关矩阵 |
| 回滚开关 | `CS_ENABLED=false`（一键降级主路由，锁域请求同受总闸）；灰度档位回退 = env 调回 0 | 既有契约 |
| 指标 | `routing_domain_total`（域路由计数）、`cs_variant` trace 标签、`chat_request_total{status}`、`sse_resume_total` 等 Release Signals | observability/metrics.py |
| 告警阈值 | Grafana/Prometheus 在位（alertmanager 容器运行）；**灰度专用告警规则尚未建**（见缺口） | docker 拓扑 |

**缺口（登记，不阻塞 INFRA_READY）**：灰度专用告警规则（error-rate/P95 越限自动通知）未落地为 Prometheus rule 文件——首档放量前由值班面板人工盯守替代，登记为 P2 债务。

## 二、四阶段放量 Gate（每档 24h，未跑满不得写 PASS）

### 观察指标（每档逐小时采样）

| 指标 | 来源 |
|---|---|
| request error rate（/chat/stream 非 2xx + SSE error 帧率） | chat_request_total |
| P95/P99 latency | chat_request_duration_seconds |
| SSE reconnect failure / resume failure | sse_resume_total{result!=hit} |
| CS handoff failure | cs_* 指标 + 工单队列 |
| duplicate side effects / IN_DOUBT rate | idempotency_execution_total{result=uncertain} |
| task terminal error / worker recovery | tasks 表状态 + recovery_count |
| DB errors / LLM provider errors / RAG reject rate | 各域既有指标 |

### 阶段定义

| 档位 | 进入条件 | 中止阈值（任一触发即回滚） | 晋升条件 |
|---|---|---|---|
| 5% | 前档 FULL_PASS + release.sh 12 Gate 全绿 | error rate >2% 或 P95 >2×基线 或 duplicate_side_effect>0 或 IN_DOUBT 率 >1% | 24h 内中止阈值零触发 |
| 20% | 5% FULL_PASS | 同上 | 同上 |
| 50% | 20% FULL_PASS | 同上 | 同上 |
| 100% | 50% FULL_PASS | 同上 | 24h FULL_PASS → 灰度收尾 |

### 回滚程序（Runbook 摘要）

1. `.env` 将 `CS_ROLLOUT_PERCENT` 回退上一档（或 `CS_ENABLED=false` 全关）；
2. `docker compose up -d app`（env 变更需重建容器）——或紧急时直接 `docker restart agent-app-1`（先改 compose 环境）；
3. 观察回滚后 30 分钟指标回基线；
4. 值班记录登记回滚原因 + 触发阈值快照。

### 发布检查单（每档进入前）

- [ ] release.sh 12 Gate 全绿（GIT_COMMIT 非 unknown）
- [ ] 迁移三层校验 MIGRATION_STATE_OK
- [ ] 灰度档位 env 已按计划设置（默认 0 起步）
- [ ] 值班面板（Grafana CS 域 + 任务域）可访问
- [ ] 回滚命令演练过一次（非首次放量时）

## 三、为何本轮不能写 GRAY_ROLLOUT_PASS

真实观察窗（5%→20%→50%→100%，每档 24h）属运维执行域，累计 ≥96 小时的生产流量观察未启动——
代码 Agent 侧的诚实判定：机制就绪（INFRA_READY=true），效果证据未取得（PASS=false，
BLOCKED_BY_OBSERVATION_WINDOW=true）。任何短时压测/手工流量都不能替代 24h×4 窗口。
