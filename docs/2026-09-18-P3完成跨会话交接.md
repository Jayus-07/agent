## 二、P3 落地内容（接手人最小必读）

**3.1 确认卡（剧本 C）**
- 链路：CSGraphResult.pending_action → done 帧 → 前端 `csChat.pendingProposal`（zustand）→ CSDrawer 渲染 CSConfirmCard → `POST /cs/confirm`（cs_admin.py，复用 process_confirmation 文本路径，P1 原子认领闸门自动幂等）

- 文本确认路径保留（降级），双实现已收敛于 process_confirmation

**3.2 事件封套 + Redis 广播（剧本 D/E）**
- 封套：`{type, event_id, seq, ts, **payload}` —— 原平铺字段保留（前端老消费端不破），event_id=uuid4 客户端去重键，seq=events 表自增 id
- 新表 `customer_service.events`（迁移 `0002_cs_events.py`，**注意：alembic upgrade 尚未在真实库执行**，P3.5 前必须先跑）
- `EventRepository.append`（ON CONFLICT(event_id) DO NOTHING RETURNING → 冲突回读原 id） / `replay(conversation_id, after_seq, limit)`
- AgentHub（realtime.py 重写）：publish → 主 loop `_persist_and_broadcast` → 落库拿 seq（失败 seq=null 仍广播）→ Redis `cs:events` 发布；专用 daemon 订阅线程收消息跳回主 loop 广播。**双降级**：Redis 不可用 / 无订阅者 → 本进程直接广播。publish 调用点零改动
- 补发端点：`GET /cs/conversations/{id}/events?after_seq=N`（带归属校验）
- 测试桩注意：单测 `bind_loop(loop, start_subscriber=False)` + monkeypatch `_persist_event`/`_publish_via_redis`（本机 Redis localhost:6379 **真实可用**，不桩会走真发布）
