# 旅游攻略 RAG 文档规范（travel_guide）

> 适用范围：`kb_id=travel`（旅游知识库）上传的城市/景点介绍文档。
> 消费方：旅游助手「城市指南」（四级内容链第一级）、RAG 检索、城市速览卡。
> 代码依据：`rag/preprocessing/chunking.py`（切分）、`metadata.py`（摘要）、
> `metadata_taxonomy.yaml`（分类）。参数可调处在文末「调参接口」。
> 最后验证：2026-10-03（M3）

## 一、元数据（上传时确定）

| 字段 | 值 | 说明 |
|---|---|---|
| kb_id | `travel` | 旅游知识库（平台公共，audience=customer） |
| doc_type | `travel_guide` | taxonomy 规则 doc_type.travel_guide.001~006 自动命中 |
| destination | 城市名（如 `福州`） | 城市指南按目的地过滤的**唯一依据**；自动抽取（文件名/概览段）+ 上传表单可覆盖 |
| business_domain | `travel` | domain 规则 travel（旅游/景点/景区 权重 3） |

## 二、文件与格式

- **格式**：Markdown（.md）首选——标题结构直接决定切分边界；PDF/DOCX 可用但标题结构弱
- **粒度**：**一城一档**，3000~8000 字（**必须 ≥2000 字**，否则摘要退化为前 3 句提取式）
- **命名**：`<城市>旅游攻略.md`（如 `福州旅游攻略.md`）——文件名含「旅游攻略」命中 doc_type.travel_guide.002（weight 8），也便于 destination 抽取

## 三、标题结构（切分质量的生死线）

```markdown
# 福州旅游指南                ← 一级标题，全文仅 1 个
> 更新：2026-10               ← 时效标注（「以官方最新为准」话术的依据）

## 城市概览                   ← 二级，必须放最前（见「摘要机制」）
2~3 段：地理格局、文化气质、最佳季节、城市气质关键词

## 必逛景点
### 三坊七巷｜别名：三坊七巷历史文化街区
- 亮点：XXXX（一句话，卡片介绍的提炼源）
- 实用：门票 ¥XX｜建议 2h｜开放 08:30-17:30
- 注意：XXX（闭馆日/预约要求等）

## 必吃美食
### 同利肉燕（肉燕馄饨）       ← 店名尽量与高德商户名可对齐
- 招牌：肉燕、鱼丸
- 人均 ¥25｜位置：澳门路
- 为什么值得：一句话（只写事实，不写软文）

## 避雷贴士
- 条目式：船票提前 1~2 天抢／老城打车难／海鲜先问时价

## 交通与实用信息
- 地铁/公交/打车要点、住宿推荐区域
```

### 硬性规则

1. **层级不跳级**：`#` → `##` → `###`（结构分里层级一致性占 35%，跳级掉分）
2. **`##` 节数 ≥3**（3 节满分；无章节直接 0.1 分，文档会被判「结构缺陷」）
3. **每个 POI 一个 `###` 小节，≤500 token（约 350 中文字）**——保证「一个 POI = 一个完整 leaf chunk」，检索时两家店的内容不会互相污染
4. **城市概览 + 前 3 个 POI 必须落在文档前 4000 字节内**——LLM 摘要只看 `text[:4000]`，元数据抽取只看前 6000 字符；放后面的内容摘要「看不见」
5. **POI 命名双写**：`### 标准名｜别名：高德/腾讯地图上的名称`——实体对齐（介绍挂到候选卡/时间轴卡）靠名称匹配；别名缺失会导致对不上
6. 正文自然出现「景点/必吃/门票/建议游玩/行程」等词（命中分类规则 .003~.006）

## 四、系统消费映射

| 文档数据 | 消费出口 |
|---|---|
| destination 元数据 | 城市指南按城市过滤（kb_id=travel AND doc_type=travel_guide 双过滤） |
| 城市概览段 | LLM 摘要（≤300 字）→ 城市速览卡 / 指南抽屉「城市气质」段 |
| POI 亮点+实用字段 | 候选卡/时间轴卡的介绍行（标「介绍来自攻略」） |
| 避雷条目 | 指南抽屉「避雷贴士」段 |
| 更新时间 | 「时效未核实，以官方最新为准」标注 |
