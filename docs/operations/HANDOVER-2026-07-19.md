## 一、做了什么

### Metadata Pipeline（核心改造）

文档上传入库从 6 步扩展到 8 步 Span 树：

```
load → parse → clean → dedup → chunk → metadata → embed → vector_db
```

**Metadata 步骤内部**：
1. `classify_with_confidence()` — 加权计分 + 文件名 + 文件夹路径 + LLM 胶着仲裁 → `(doc_type, confidence)`
2. `extract_rule_keywords()` — 从 keyword_store 热加载，按 doc_type 匹配
3. `analyze_complexity()` — token 数 + 结构复杂度 + 风险关键词命中
4. **LLM Decision Router V2** — 5 维评分决定是否调 LLM
5. `extract_doc_keywords_llm()` — 条件触发，Token 追踪
6. Chunk 分层注入 — chunk_keywords（只存该 chunk 命中的词）+ doc_type 继承
7. Span 输出 — `rule_metadata` / `llm_metadata` 分两层

### LLM Decision Router V2

| 维度 | 分值 | 说明 |
|------|------|------|
| high_value type | +40 | policy/compliance/legal/security/financial/customer_data/contract_template |
| risk_hits ≥ 3 | +20 | 合同/GDPR/隐私/审计/监管/处罚/罚款/合规/诉讼/知识产权 |
| risk_hits ≥ 1 | +10 | |
| confidence < 0.7 | +20 | 分类不确定兜底 |
| token > 10000 | +15 | 长文档 |
| structure ≥ 20 | +15 | 标题层级+表格+法规引用 |
| token > 50000 | 不加分 | 标记 ultra_long + section_summary_needed |

阈值 50，force_types 始终调 LLM。

### 关键词动态管理

- SQLite `keyword_rules.db` — 150 条种子数据 + 热加载 (60s TTL)
- 前端 `/knowledge/keywords` — 按文档类型分组，增删改 + 启用/禁用
- 提取时按 doc_type 过滤，只匹配该类型的词 + 通用词

## 四、已知问题

1. **后端改 Python 后需重启**：uvicorn --reload 不总是生效，改 config/rag.py 后建议手动 kill + 重启
2. **__pycache__ 污染**：遇到 `cannot import name 'XXX' from 'backend.config.rag'` → 删 `backend/**/__pycache__` + 重启
3. **LLM_REQUEST_TIMEOUT 在 config/llm.py**，不在 config/rag.py。metadata.py 已修正导入路径
4. **trace 内存限制 200 条**：知识库索引的 trace 很快被挤出，操作中心"查看链路"可能显示过期
5. **doc_db.add_texts 超时 3s+**：全文 embedding 太慢，metadata span 标记 skipped 继续流程
6. **_embed_with_retry 调 embed_query 而非 embed_documents**：功能正常但 API 用错了
