# 安全、幂等、预算与反馈闭环灰度/回滚手册

## 适用范围

本手册覆盖 WP1–WP6 的最终验收、Q4 日/月预算、Q8 模型价格表、写副作用门禁和反馈候选 promotion。
所有操作先在 observe 灰度完成证据留存，再进入 enforce；不得通过删除预算策略、写入 0 额度或关闭幂等来恢复流量。

## 放量前检查

1. 确认 memory Alembic 为 `0014 (head)`，并确认 `budget_policies` 存在 platform/default、tenant_default/default、platform-default、internal、test 五类基线策略。
2. 导入 `model_price` 的 pending 版本，检查六个维度、USD、单位、有效期和来源；由两名不同审核人批准后才允许生效。
3. 设置 `LLM_BUDGET_MODE=observe`，观察 7 天：缺失 user/tenant 归属为 0、价格覆盖率 100%、误阻断为 0、`budget_price_total{result="missing"}` 为 0。
4. 检查 `/metrics` 能抓到 WP6 九个指标，确认标签没有用户、租户、Trace、request 或幂等键。
5. 在测试租户验证：只读查询仍可用；硬预算模型调用和写副作用返回 `BUDGET_EXCEEDED`；重复提交仍返回幂等结果；pending/rejected 候选不能 promotion。
6. 保存以下证据：专项 pytest 命令和退出码、`alembic current`、Prometheus targets/rules 状态、一次 80% 阈值事件和一次 100% 拒绝事件。

## 灰度顺序

```text
price pending → 双人 approve → observe 7 天 → 1% enforce → 10% → 50% → 100%
```

每次扩大前检查 `budget_quota_total{result="rejected"}` 是否符合真实策略、
`budget_price_total{result=~"missing|unavailable"}` 是否为 0，且无 `IdempotencyUnavailable`。

## 触发回滚的条件

- 价格表缺失/不可用、PG ledger 错误或策略继承不一致；
- 幂等权威存储不可用、同一副作用出现超过一次执行；
- 只读查询被预算误伤，或预算拒绝没有统一 `BUDGET_EXCEEDED`；
- pending/rejected 评测候选进入 golden set；
- 指标出现用户、租户、Trace、request 或幂等键标签。

## 回滚步骤

1. 将 `LLM_BUDGET_MODE` 从 `enforce` 改回 `observe`，重启 app/worker，使新请求不再执行金额硬拒绝；不要删除 ledger、reservation 或 price history。
2. 若价格版本错误，保留原版本，修正为新的 pending 版本并重新双人审核；`model_price` 只允许追加，不允许 UPDATE/DELETE。
3. 若 Redis/PG 故障，保持写副作用拒绝，恢复依赖后先执行幂等/预算冒烟，再恢复流量。
4. 若反馈 promotion 异常，停止 promotion API；只保留 approved 候选，修复后在 advisory lock 下重试，禁止直接改 JSONL 为 promoted。
5. 留存告警、trace、审计和迁移状态，完成根因复盘后再从 observe 重新开始 7 天基线。
