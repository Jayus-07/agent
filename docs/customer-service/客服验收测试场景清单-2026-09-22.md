# 客服系统验收测试场景清单（40 例）

日期：2026-09-22
适用范围：智能客服全链路（AI 服务 / 人工转接 / 坐席工作台 / 工单 / 质检 / 高并发）
优先级：**P0 = 上线必须通过**；P1 = 首月观察；P2 = 回归兜底

执行环境要求：
- 用户端（frontend）与坐席工作台（frontend-cs）各开一个浏览器窗口对照验证
- 业务网关处于 http 模式（BUSINESS_SERVICE_URL 指向 business-mock 或真实 Java 服务）
- 压测场景（#39/#40）会产生真实 LLM 调用费用，执行前确认额度

## 四、断线重连与可靠性

| # | 场景 | 操作 | 用户端预期 | 客服端预期 | 优先级 |
|---|---|---|---|---|---|
| 20 | WS 短暂断网 | 坐席端断网 5 秒恢复 | — | 指数退避重连（1s 起封顶 30s），角标恢复"实时推送"；**重连后全量对账**：新排队工单 + 选中会话漏掉的消息全部补齐 | P0 |
| 21 | 长断网降级 | 断网 >30 秒 | — | 自动切 **2 秒轮询**，角标"轮询降级"；收发照常 | P1 |
| 22 | 降级恢复 | 网络恢复 | — | 自动切回 WS，轮询停止 | P1 |
| 23 | 断线漏事件补发 | 断线期间用户发 3 条消息 | 消息正常 | 重连后 3 条全部补显（events 表 seq 游标 `after_seq` 回放） | P1 |
| 24 | Redis 宕机 | 停 redis 容器 | 消息收发不受影响 | WS 新连接被拒（1013），已连不掉线；广播降级本进程 | P2 |
| 25 | PG 抖动 | 短暂停 postgres | 兜底话术不白屏 | 事件进 outbox 补偿，恢复后自动补发 | P2 |

## 执行顺序建议

1. **P0（13 条）先行**：主链路 1/2/3 + 工作台 12/13/14/15/16/18 + 网关 26/27 + 工单 31/32/34 + 安全 37/38。全过再谈上线。
