# 2026-09-22 分层路由改造实施报告（Hierarchical Routing）

> 规格：用户《分层路由改造 22 条规格》。本报告 = §22 要求的交付说明。
> 状态：代码全部落地，默认 `ROUTING_ARCHITECTURE=legacy`（行为零变化），切 `hierarchical` 即启用新链路，`ROUTING_SHADOW_MODE=true` 可双轨评估。

---

## 一、旧链路是什么

```
用户 Query
 → Router（backend/orchestration/router/router.py，三层 fallback）
    ├─ RuleRouter   关键词强/弱信号，conf ≥ 0.8 直接拍板 capability
    ├─ VectorRouter pgvector 对 capability examples 做相似度，conf ≥ 0.85/0.6 采纳
    └─ LLMRouter    qwen 兜底，输出 candidates（conf=0.7）
 → RouteDecision{execution_mode, candidates}
 → direct 时：tool_selector 节点（tool_selector.py）
    fast set（sql/rag/business）score ≥ 0.85 直通；否则 FC LLM（tool_selector 角色）bind_tools 选工具+填参
 → skill_executor → reporter
```

问题：**一级路由（含 LLM Router）直接决定具体 capability**，规则/向量/LLM 与 tool_selector 的 FC 之间存在「两次 LLM 判断工具」的重复路由；域语义（knowledge/data/business…）没有显式层。

## 二、新链路是什么

```
用户 Query
 → CoarseIntentClassifier（domain_classifier.py）
     Rule Hint（manifest domains[].keywords 正则）
     → Embedding Prototype 域心分类（softmax 概率化）
     → Confidence Gate（confidence ≥ 0.75 且 margin ≥ 0.12，否则 unknown）
 → Domain
     ├─ customer_service / travel / selection_funnel → 复用既有域图 prefilter（未放行回退 legacy）
     ├─ general → 既有 plan 支线（v1 行为不劣化）
     ├─ unknown → 澄清（复用 L1 追问卡片 + 防循环守卫）
     └─ 工具域（knowledge/data/business/report/communication）
         → Domain Tool Registry（manifest capabilities_by_domain 派生视图）
         → FineToolRouter（hierarchical.py::select_tool）
             Fast Path：top1 ≥ 0.85 且 margin ≥ 0.15 且 fast_path_enabled 且 risk=LOW
             灰区 → tool_selector FC（只 bind 域内候选，选择+填参一次完成）
 → Validator（Skill params_schema 校验，既有 validate_params）
 → Execute（skill_executor / Tool 层审批门不变）
```

三级职责收敛（§14）：
| 层 | 职责 | 实现 |
|---|---|---|
| CoarseIntentClassifier | 属于哪个业务域 | 规则 hint + embedding 域心 + gate |
| FineToolRouter | 域内哪个 Tool | 域内向量分数 + Fast Path 三条件 |
| ToolSelector LLM | 灰区最终选 Tool+填参 | 既有 tool_selector 节点，只 bind 域内候选 |

**不再存在的重复路由**：hierarchical 模式下 legacy 三层 Router 的 vector/LLM 层不再被调用（除 degraded 回退），「QueryRouter LLM 判一次 + ToolSelector LLM 判一次」消失；LLM 工具选择唯一入口 = tool_selector 节点。

## 四、关键机制问答

**Fast Path 何时走**（三条件同时满足，缺一进灰区）：
1. 域内细路由 top1 分数 ≥ `FINE_TOOL_HIGH_CONFIDENCE`(0.85)
2. top1 − top2 margin ≥ `FINE_TOOL_MIN_MARGIN`(0.15)
3. 该 capability `fast_path_enabled: true` 且 `risk_level: LOW`

**何时调 Qwen3-8B（tool_selector LLM）**：粗分类给出工具域、细路由 top1/margin 未达 Fast Path 阈值，或候选是 HIGH/MEDIUM 风险（如 email.send）→ tool_selector 节点 FC，bind_tools **只有域内候选**（如 customer_service 域绝不出现 rag.search/sql.query）；选择+填参一次完成，越界/校验失败带反馈重试 1 次，仍失败多候选→澄清、单候选→passthrough（既有策略不动）。

**何时 clarification**：粗分类 gate 拒判（confidence < 0.75 或 margin < 0.12，如 knowledge=0.61/data=0.59）→ unknown → 复用追问卡片（`COARSE_UNKNOWN_ACTION=clarify`，可配 `legacy` 回旧 plan 支线）；同一会话 10 分钟防循环守卫沿用。

**旧 QueryRouter 保留/废弃**：保留——workflow 强信号与复合意图两类**确定性规则**（语义是「执行方式」而非「选工具」）；hierarchical 模式下 rule/vector/LLM 三层的 capability 选择职责废弃，degraded（embedding 不可用）时整体回退 legacy 保可用。legacy 模式下一切照旧。

**风险控制**：HIGH 风险（email.send / email.watch / competitor.watch）manifest 层禁 fast_path + Fine Router 双保险不直选；执行期既有 Tool 审批门（`security/tool_approval.ensure_approved`）与 CS 确认状态机（PENDING→CONFIRMED→EXECUTING→SUCCESS/FAILED）完全未触碰——**classifier confidence 再高也不会自动执行副作用**。

## 五、如何灰度切换

```bash
# 第 1 步：shadow 双轨（legacy 拍板执行，新链路只算 domain+fine top1，零 LLM 成本）
ROUTING_ARCHITECTURE=legacy
ROUTING_SHADOW_MODE=true
#   → 观察 routing_shadow_match_total{is_match}、trace.metadata.routing_shadow

# 第 2 步：切 hierarchical（建议先白名单/低比例场景验证，再全量）
ROUTING_ARCHITECTURE=hierarchical
ROUTING_SHADOW_MODE=false

# 第 3 步：按 §19 评测校准阈值后，稳定运行一个周期，再删 legacy 三层的 capability 选择职责
```

回滚 = `ROUTING_ARCHITECTURE` 改回 `legacy`（纯 env，无需发版）。路由缓存键已带架构位（`arch=hierarchical`），切换瞬间新旧决策互不串。
