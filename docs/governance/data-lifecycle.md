# 数据分类、版本、备份与生命周期统一规范

> PostgreSQL 数据模型与迁移依旧由 [DATABASE.md](../DATABASE.md) 负责；本文定义业务生命周期和保留/恢复的通用原则。**不在此新建表、强制所有业务共享一个状态机、或给未确认的数据写死保留期限。**

## 数据分类：先判断是谁的事实

| 类型 | 典型对象 | 生命周期权威与行为 |
| --- | --- | --- |
| 正式业务状态 | Trip Revision、客服工单、订单/退款、模型价格版本 | 领域数据库表、服务端 CAS/事务、审批与审计 |
| 待确认草案/候选 | 旅行 Draft、退款提案、RAG 候选 generation | 暂存状态与明确的应用/放弃提交点；不能假成功 |
| 知识与模型资产 | RAG doc/chunk/BM25/向量、评测集、Prompt 版本、模型注册 | 元数据/版本、发布可见性、来源与血缘；不只存文件 |
| 会话/用户记忆 | 会话记录、结构化长期事实、用户画像投影 | tenant/user 归属、有效版本、纠错/失效/删除请求 |
| 审计/账本 | 幂等 Ledger、LLM 用量、额度预占、操作审计 | 不因撤销 UI 状态就抹去必要可审计历史；按保留政策清理 |
| 派生临时 | Redis 缓存、SSE buffer、`tmp/`、Build/pytest 输出 | 必须可再生、可过期；不代替权威实体或不可恢复证据 |

## 写入与发布原则

1. **单一事实源**：哪个领域拥有该实体、主键/tenant/owner 是谁、在哪个数据库、由哪个 Repository 写入，先查 `backend/sql/migrations/`、`scripts/init_db.py` 和当前实际部署配置。
2. **状态与提交点**：明确 draft/pending/active/deprecated/failed 与业务实际含义。RAG 代次发布 CAS 和人工审核可见性为两套状态；旅程的手动/AI 编辑按其当前 V1/V2 版本协议，不能混淆。
3. **并发与幂等**：服务端比对 revision/CAS、用户确认、稳定写操作 key；跨 Redis/PG/Provider 不假定存在单个分布式事务。未知结果采用 durable ledger/补偿，不无条件重投。
4. **删除与保留**：删除用户可见数据与保留法定/审计记录可能不同，须声明依赖传播、隔离删除、备份保留和清理窗口；删除向量、BM25、缓存和摘要时避免孤儿对象。
5. **数据隔离与安全**：所有 read/list/export/search/statistics 按资源级授权；临时文件和备份同样可能有 PII、凭据、文档正文。禁止把 `data/` 或 `tmp/` 统一视作可删除。
6. **迁移**：代码升级用向前兼容迁移、明确库 target，避免直接重写已应用迁移；先在隔离 PG 实测并备份，数据损坏或权限失败拒绝发布。

## 备份/恢复与留存门禁

- 当前仓库有 `docker/pg-backup.sh` 和迁移器，但其存在不代表实际完成恢复演练。备份必须有可用性验证、恢复隔离环境、目标库一致性（多 PostgreSQL 库）、RPO/RTO 目标和密钥/访问控制。
- RAG 不能只备份 PostgreSQL 而忽视向量/BM25/源文件/Generation 指针；任务账本、Prompt 版本、Provider 凭据和用户资料按真实存储分布建立备份对象表。
- 保留期限由产品/法律/隐私政策、实际实现或明确运营决定，不在文档中臆造统一 30/90 天。每个对象的 TTL/删除/归档/追溯策略记录在其领域事实源与管理配置。
- **恢复顺序**：隔离资源 → 确认备份版本/一致性 → 只读核对迁移状态 → 恢复与校验资源 scope → 读写定向回归 → 观测与对账。不能在共享 Docker Volume 上直接做破坏性恢复。

## DL-01～DL-10 验收

| 编号 | 验收 |
| --- | --- |
| DL-01 | 关键实体的数据所有权与库/表/仓储入口可追踪 |
| DL-02 | 读写租户/owner 与审计范围一致，含导出/统计/缓存 |
| DL-03 | 版本 CAS 并发冲突不覆盖已发布的正确状态 |
| DL-04 | Draft/候选发布失败保持正式版，提交后失败可恢复 |
| DL-05 | 删除/软删/失效传播到索引/缓存/派生画像，不越权 |
| DL-06 | 备份覆盖必要 DB、向量、BM25、原件、账本、凭据密钥的合法恢复需求 |
| DL-07 | 隔离环境真实恢复及数据一致性检验通过，RPO/RTO 有报告 |
| DL-08 | 数据迁移目标库、schema_migrations、回滚预案经过验证 |
| DL-09 | 个人数据脱敏、删除、保留与审计例外得到实际合规核对 |
| DL-10 | Git 跟踪的 `data/tmp` 分类出黄金集/再生物/敏感对象后才执行任何清理 |

真实生命周期实现不符本文时建整改任务，不直接改写本文宣称已经完成。
