# 方案 A（JWT 单通道）实施报告 — 2026-09-16

目标：**JWT 是唯一用户身份来源，API Key 降级为纯服务间凭据**（详见
`2026-09-16-auth网关与审计页测试报告.md` §8.2 方案对比）。

## 0. 关键架构事实（决定实施位置）

JWT 验签发生在 **APISIX gateway-auth 插件**（黑名单检查 fail-closed），后端
`api_key_middleware` 只校验 X-API-Key。因此"验签后查会话"的主闸放网关插件，
后端中间件做第二道纵深防御；actor 语义统一放 `deps.py`（身份解析唯一入口）。

## 2. 第二阶段：Redis 会话（jti 闸）

- `security/local_jwt.py`：`issue_access_token` 新增 **jti** claim（16B hex），
  返回值补 `userId`；新增 `session_key(payload)` 帮助函数。
- `routes/auth_local.py`：
  - login / refresh 后写 `auth:session:{userId}:{jti}`，TTL=token 剩余有效期；
  - logout 删会话键（**即时失效**）+ 黑名单（既有，兜 TTL）。
  - 写侧尽力而为：Redis 不可用记 warning 不阻断登录（audit 灰度期无影响；
    enforce 前 Redis 是硬依赖，与黑名单通道同一前提）。
- 会话闸（两道）：
  1. **网关** `gateway-auth.lua` ⑩.2：验签通过后 `EXISTS auth:session:{userId}:{jti}`，
     缺失=已吊销；env `GATEWAY_SESSION_CHECK` = `off`/`audit`（**默认**）/
     `enforce`；Redis 故障与黑名单同语义 fail-closed（session-timeout /
     session-unavailable）；旧令牌无 jti → audit 放行 / enforce 401（重登即得）。
  2. **后端** `middleware/auth.py`：`JWT_SESSION_GUARD_MODE`（off/audit**默认**/
     enforce），透传 Bearer 时验签 + 查会话；Redis 不可用放行 + 告警
     （网关层已 fail-closed，避免双写故障面）。
- 无 jti 的存量令牌：audit 期自然滚动过期（30min），enforce 后重登即新格式。

## 3. 第三阶段：actor kind 统一 + 统一守卫

  **`require_admin_user`**（JWT 用户 + admin），灰度开关沿用
  `SENSITIVE_API_GUARD_MODE`（audit 只记日志 / enforce 403）。
- **observability.py 未迁移**（并发会话正在改该文件，迁移留待其提交后）；
  新敏感端点一律直接挂 deps 里的新依赖。

## 4. 第四阶段：审计字段 + 切换 runbook

- 审计字段：`gateway-access-log` 已记录 `user_id`/`auth_type`(=actor_kind)/
  `status`/IP/路径；会话闸拒绝原因（session-revoked/missing-jti/...）自动进入
  既有 `apisix_gateway_auth_denied_total{reason=...}` 指标。
- **切换步骤**（需协调容器重启，见 §6）：
  1. `.env` 追加 `GATEWAY_SESSION_CHECK=enforce`、`JWT_SESSION_GUARD_MODE=enforce`
     （api 侧已默认 enforce，勿动）；
  2. `docker compose build app && up -d app`（后端新代码 + 新 API_KEY 生效）；
  3. apisix 容器重启（载入新插件 + ROLE_GATE）；
  4. 重启双端 dev server / 重建前端时注入新 API_KEY；
  5. 删除 `.next-smoke`、`.next/cache` 重建（清除旧 Key 产物残留）。
- **监控**：登录成功率、401 reason 分布（重点 session-revoked）、
  `gateway_auth_denied_total` 增量、Redis 健康块（管理端系统健康页）。
- **回滚**：任何异常 → 删掉两个 env 开关（默认 audit）重启即可，会话闸
  完全旁路；SENSITIVE_API_GUARD_MODE=audit 回退端点拦截。
