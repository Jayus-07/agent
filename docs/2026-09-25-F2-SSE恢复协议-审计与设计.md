## 二、协议设计（F2.2，冻结语义）

**原则**：不重构主图（runner/merged_q 零触碰）；改动收敛在 HTTP/SSE 传输层 + 前端 API 层。

### 2.1 事件序号与帧

- 每个流一个进程内注册表记录 `StreamRecord(stream_id=request_id)`；producer 产出的每个事件在入队前获得单调 `seq`（从 1 开始），写入 data JSON（`{"seq": N, ...}`）并以 SSE `id: <seq>` 行同帧输出（双通道兼容：旧解析器忽略 id 行）。
- `ping` 帧无 seq、不入注册表——它是连接保活不是流内容，重放无意义。
- meta 帧携带 `stream_id` + `resume_supported: true`（能力协商，旧后端无此字段）。

### 2.2 断连语义（核心行为变更）

- 客户端断开（GeneratorExit）→ **只脱离订阅，不再 `stop_event.set()`**；服务端继续跑完，producer 把事件持续写入注册表有界缓冲直到终端帧（done/error），然后记录 status=finished。
- 显式中止（`/chat/abort`）与背压截断仍走 stop_event——语义不变。
- 代价披露：断连后的流会烧完本轮 LLM token（原行为是立即省 token）。这是「可恢复」的必要条件，登记为已知行为变更。

### 2.3 resume 通道

```
POST /chat/stream/resume  {request_id, after_seq}
  → 404 STREAM_NOT_RESUMABLE   进程重启/记录过期/游标过老（gap）
  → 403                        身份不匹配（跨用户/跨租户游标）
  → 422                        游标非法
  → 200 SSE：先重放 buffer[seq>after_seq]（含终端帧），未完则无缝切 live
```

- **无丢洞保证**：`subscribe_after` 在注册表追加锁内完成「取重放尾 + 挂 live 队列」两步——重放与 live 之间不可能插入遗漏。
- **缓冲有界**：超限丢最老并置 truncated；resume 命中 gap → 404（诚实失败，客户端整轮重发，绝不静默跳事件）。
- **进程本地**：app 重启 → 注册表清空 → resume 404。跨重启续跑不做（运行已在重启中死亡，诚实披露优于假恢复）。

### 2.4 投递语义

- 传输 **at-least-once**（重放尾与 live 理论上可重复）+ 前端按 `(stream_id, seq)` 去重 = **UI effectively-once**。不构造 exactly-once 传输。

### 2.5 前端

- `streamChat`（frontend + frontend-cs 双端同步改）：记录 last seq；流意外终止（无 done/error）→ 自动 `resume`（退避重试 N 次）→ 续接 yield；消费方（useSSE/useCSChat）零改动。
- 404 STREAM_NOT_RESUMABLE → 上抛既有错误态（用户重发），不静默。

### 2.6 观测（§十八 Release Signals）

`sse_resume_total{result}` / `sse_replay_events_total` / `sse_resume_failure_total{reason}`（低基数 label：result=hit|finished|not_found|forbidden；reason 同源）。

## 三、验收门（F2.5，实机）

- `SSE_RESUME_PROTOCOL_PASS`：单测矩阵（无丢洞并发、游标合法性、身份归属、gap、终止语义）全绿。
- `SSE_100_DISCONNECT_ACCEPTANCE_PASS`：真实驱动脚本经 **APISIX :9080**（JWT 登录）×100 次随机断开/恢复；逐次记录断点 seq、重放数、内容 hash、终端帧一致性；断言 missing_event=0 / duplicate_render=0 / terminal_mismatch=0 / cross_request_replay=0 / cross_tenant_replay=0（含伪造游标 403 用例）。
