# 智能选品体系优化方案评审（2026-09-17）

> 来源：外部提出的《智能选品体系优化方案》（下称"方案"）。
> 本文将其逐条对照 selection_funnel 现有实现（8546ce1 / 04d4cfa / a94f3e7 / 2d28f8e 后状态），
> 给出【已实现 / 部分实现 / 真缺口 / 不建议照搬】四档结论与调整后的落地优先级。
> 结论依据均为实读代码，引用处标注文件与函数/行号。

## 一、总体判断

方案质量不错，方向与既有架构拍板一致（漏斗筛选、决策 workflow 评估单品、RAG/LLM 只增强不替代规则）。
但它是**不看本仓库代码写出的通用最佳实践**：约四成内容已实现，部分与现状重复，
少数属于单机 SQLite + 表格导入场景下的过度设计。不建议按方案原文立项，
按本文第四节调整后的 P0/P1/P2 执行。

## 二、逐条对照

### 2.1 三块体系边界 —— 大部分已实现，缺一份正式架构文档

| 漏斗复用旧评分，不造第二套 | `stages/verifier.py` L15-16 直接 import `selection.scoring.score_product`，注释明示 | ✅ 已实现 |

### 2.2 brief 契约 —— 模型已有，缺入口校验

- 已有：`models/brief.py` `FunnelBrief`（Pydantic，top_n 带 ge/le），`missing_slots()` 驱动 need_info 追问；
  `brief_node.py` funnel_context 显式传值优先于正则（L96-99）。
- **真缺口**：
  1. 价格带 `price_min > price_max`、毛利率越界（如 >1）无校验——现在会静默进建池产空池（空池会如实报告，但属"应在入口拦的错误"）；
  2. platform 未对照 `_PLATFORMS` 枚举校验（brief_node L54 有枚举但只用于抽取）；
  3. 方案的 `warnings` 字段（无法识别内容的披露）没有落点。
- 不采纳：`Decimal` 替换 `float`（项目财务口径全 float，无必要）。

### 2.3 CanonicalCandidate —— 归一化已有，缺身份与质量字段

- 已有：`stages/pool_builder.py` `_POOL_FIELDS`（15 字段）统一映射 import/watchlist；
  `_dedup_key`（L91-93）url 优先 → (title, platform) 兜底，与方案建议的降级顺序一致。
- **真缺口**：`candidate_id` / `source_item_id` / 候选级 `observed_at`（现在只有批次级 `imported_at`，
  `import_pool.py` L227）/ `data_quality` / `provenance`。
- 不采纳：逐指标 provenance（表格导入场景，批次级来源足够）；"不能仅靠标题去重"的批评现状已部分缓解
  （仅无 url 时才用 title+platform），同款不同规格误合并风险真实存在但低频，先记录不立项。

### 2.4 ScreenDecision 四态 —— 语义已有，结构未显式建模

- 已有：REJECT（reasons: {url,title,rule,value}）、UNKNOWN 语义（缺数据保留 + notes/warnings 披露，
  `screener.py` L51-62）、NOT_APPLICABLE 实例（销量代判热度线 L33-36；econ 无利润数据保留披露）。
- **真缺口**：四态没有显式状态字段与独立 `ScreenDecision` 结构（rule_id / threshold / evidence 引用）；
  reasons 里的 value 是散值，无阈值快照。
- 评估：显式建模是合理增量，但优先级中庸——当前淘汰明细已可复算，审计诉求出现前可缓。

### 2.5 评分数据可信度 —— notes 已有，定量指标缺

- 已有：`scoring.py` notes（data_insufficient/single_item_pool/insufficient_history）随分输出、报告披露；
  verify 层不淘汰，缺数据不会被当成低潜力淘汰。
- **真缺口**：`data_completeness` / `data_freshness` 定量化。
- 方案批评"缺数据=50 分与真实中等分不可区分"部分成立，但报告已逐条披露数据缺口，
  读者可见；定量完整度是 P1 改进而非 P0。
- 补一条方案没提的：报告理由里应显式说明"差异度为当前候选池内相对值"
  （代码注释 `verifier.py` L34 已明确口径，报告未转述）。

### 2.6 econ 口径 —— **方案最有价值的一条**

- 现状 `economics.py` L45-48 算的**实际就是贡献利润率**（扣点/物流/推广/退款全扣），
  但全链路（ranker 理由、reporter 推荐表/决策草案）都叫"毛利率"——用户看到"毛利 23.6%"
  会误以为是扣完经营费用的净利水平。**命名与口径必须正名**，报告双口径展示。
- actual/estimated 区分：部分已有（`unit_cost_estimated` 标记 + warnings + 决策草案
  "成本为估计值，先向供应商询价"降级为条件做，`reporter.py` L216）。剩余缺口：
  排序中 estimated 与 actual 同权重（方案批评成立，但决策草案已降级处理，先记录）。
- 公式改写（r_c/r_f/r_a/r_r 系数化）属等价变形，不必动代码，写进注释即可。

### 2.7 rank 分层 A/B/C —— 与决策草案重叠，不建议平行新增

- 现状决策草案（`reporter.py` `_decision_draft_lines` L183-223）已按毛利缓冲/成本估计/痛点
  分"做/条件做/放弃"三档并附条件——方案的 B 层"条件验证"与之高度重合。
- **结论**：不加平行分层结构；把"数据质量可接受/估算成分大"并入决策草案判据即可。
- 排序键方案建议与现状完全一致（分↓毛利↓确定性兜底，`ranker.py` L16-23），无需改。

### 2.8 报告目录 —— 八成已有，缺两段

- 已有：需求口径 / 漏斗计数 / 推荐明细 / 淘汰明细 / 合规 / 市场分析（画像+竞争+痛点）/ 测款 / 决策草案 / 数据缺口。
- **真缺口**：① 执行摘要段（候选数/通过数/Top-N/一句话结论）；② "证据与假设"独立成章
  （现在散在数据缺口+淘汰明细+econ warnings 三处，汇总即可，成本很低）。
- 不采纳：固定十章标准目录（文档洁癖，现有段落已覆盖实质内容）。

### 2.9 LangGraph 工程化 —— 真缺口最大的一块

- 已有：`SelectionFunnelState` TypedDict + 消费纪律（graph_state.py L39-69）；stage_logs 逐层
  kept/dropped/reasons/notes；适配器 trace 埋点 funnel_status/funnel_category/stage_summary
  （`selection_funnel_graph_node.py` L55-69）；异常降级不炸主图（L41-46）。
- **真缺口**：
  1. **终态四分不完整**：现状三态 ok/empty_pool/need_info（graph_state.py L34-36），
     异常走适配器 except 分支只进日志——方案说得对，"系统异常不能伪装成淘空"，
     现状虽未伪装（降级话术不同），但 trace 里没有 FAILED 标记，失败率无法统计；
  2. `run_id` / `config_snapshot`（本次阈值+类目规则版本）未落 stage_logs/报告，
     事后无法回答"这份报告是用哪套阈值跑的"；
  3. 节点耗时未记录。
- 不采纳：`idempotency_key`（漏斗是读型任务；导入通道批次天然隔离可清除）；
  状态结构重排（现状 candidates 逐层累加与方案建议等价）。

### 2.10 数据源与反爬 —— 大部分已拍板已实现

- 已有：import 主源 + watchlist 兜底（拍板记录：协同文档第六节）；批次隔离 + 按批次回滚
  （`import_pool.py` add_batch/clear_batch）；反爬预算收敛在 competitor 侧不由漏斗控制。
- **真缺口（与漏斗准确度直接相关）**：**候选级人工补录源**——现在成本只能是 brief 全局一个
  `max_unit_cost` 或 45% 售价估计（economics.py L40-43），候选级成本是贡献利润率的最大误差源。
  建议支持导入表加"成本"列（canonical 字段补 unit_cost）+ 候选级覆盖 brief 级，成本低收益高。
- 数据过期（stale watched 快照）：报告显示 latest_crawled_at，但无 stale 提示——小缺口并入 P1。

### 2.11 验收标准 / Golden Dataset —— 真缺口且性价比最高

- 现有 81 测试覆盖单元/节点/图/API，但**没有固定候选快照下的业务回归**
  （固定输入 → 固定计数/Top-N/淘汰原因），规则或阈值一改无法量化回归影响。
- 这与项目既有实践同构（RAG 36 例评测基线），建议建立 `selection_funnel` golden dataset：
  宠物零食/服饰/家居三类目 × 正常/淘空/缺成本/缺评价/异常价格/同款重复/缺类目/决策词误触发。
- 前端/e2e 测试：与项目测试文化（后端 pytest 为主）不符，按需不立项。

## 三、方案中正确且无需动作的判断

- "不需要改成 Multi-Agent"——与现状一致，漏斗保持线性图+条件短路。
- 排序键、去重降级顺序、短路保留原则——现状已满足。
- "淘空不是故障，但节点异常也不能伪装成淘空"——表述精准，纳入终态四分改造。

## 五、明确不做（附理由）

| 方案条目 | 理由 |
|---|---|
| Decimal 全替换 float | 项目财务口径统一 float，转换成本>收益 |
| 逐指标 provenance | 表格导入+SQLite 场景，批次级来源已足够 |
| idempotency_key | 读型任务 + 导入批次隔离/可清除已覆盖 |
| 报告固定十章目录 | 现有段落已覆盖实质，按需增段即可 |
| 前端全量测试 | 与项目测试文化不符，关键交互按需补 |
| 状态结构重排 | 现状 TypedDict + candidates 累加与方案等价 |

## 六、验收口径（裁剪自方案清单，可执行版）

1. 路由隔离：选品词进漏斗、决策词进 decision（现有 17+25 测试继续绿）；
2. 非法需求（价格带倒挂/毛利越界）→ need_info 追问而非空池；
3. 同一固定快照重跑：计数、Top-N、淘汰原因完全一致；
4. 每条淘汰可复算：rule + 实际值 + 阈值 + 数字明细（现有纪律保持）；
5. econ 门控判据=贡献利润率，报告双口径展示，estimated 成本候选在草案中降级；
6. 异常运行 trace 中 funnel_status=failed，与 empty_pool/need_info 可区分；
7. golden dataset 回归纳入 CI（选品域测试命令）。
