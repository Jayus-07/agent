# 可上线架构优化任务规划：规则管道 → 统一抽取 + 级联路由

> 持久化日期：2026-09-19｜来源：会话规划稿（用户提供原文照录）
> 本规划只定义任务、验收与停止条件，不执行代码、配置、数据或线上变更。
> 实施状态见文末 §7（随实施进度更新）。

目标：把 metadata_llm.py 统一结构化抽取坐实为唯一主路径，规则链冻结并降级为 LLM 不可用时的 fallback；用"向量检索 + 轻量分类器 + 级联路由"替代 300+ 条硬编码正则与多路 LLM 补丁；建立可回归评估闭环与人审写回闭环，达到可上线标准。

## 3. 总体做法

1. 先评估后替换：先建黄金集与基线，再设计新链，避免"无数字重构"。
2. 双轨影子：规则链与统一抽取链并行跑，影子模式对比，达标才切流。
3. 级联路由：L0 强先验 → L1 嵌入+LR → L2 向量检索+AI 分类 → L3 LLM，先便宜后贵。
4. 单次 schema 抽取：合并三个 LLM 补丁，LLM 调用从最多 4 类降到 ≤ 1.2 次。
5. 规则链冻结：domain_data.py 不再新增正则，只作为 fallback。
6. 人审闭环：pending_review 结果写回标注库，既是评估集也是未来微调数据。
7. 可回滚上线：灰度 1% → 10% → 50% → 100%，每阶段 24h 观察，回滚 ≤ 10 分钟。
8. 监控与告警：准确率、延迟、成本、LLM 调用、fallback 触发率全部看板化。

### 7.1 级联路由决策表（v0，阈值待黄金集调优）

| 层 | 输入 | 判定 | 命中条件 | 超时/失败回退 |
