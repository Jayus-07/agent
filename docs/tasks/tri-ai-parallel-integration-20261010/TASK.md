# 三 AI 并行开发整合任务

## 目标

在不丢失主工作区、脏 Worktree、Stash、不可达提交和原始历史的前提下，将已确认的并行开发成果分批整合到独立集成分支，并留下可追溯的来源、冲突决策和验证记录。

## 范围与约束

- 保全主工作区和 5 个脏 Worktree；未提交修改先以外置快照和补丁留存，不自动提交为业务提交。
- 保留原始提交、分支、stash、reflog；不执行 reset --hard、clean、强推、删除分支/Worktree、GC 或数据库写操作。
- 逐域整合旅游、客服、RAG、SQL、路由/运行时、评测、管理端、基础设施和文档。
- 冲突逐块审阅；迁移、API、前后端契约需核对。未确认的数据删除迁移不得执行。
- 每一批按依赖选择定向测试，并将命令、结果和对应提交记录在 PROGRESS.md。

## 验收条件

1. 每个来源工作区、提交和未提交差异均能映射到救援快照、补丁或原引用。
2. 所有冲突都有人工决策记录；相同补丁不重复应用；没有覆盖文件来消除冲突。
3. 迁移登记、执行顺序、checksum 风险及 API/OpenAPI/前端契约经过复核。
4. 相关定向测试实际执行并绑定到集成提交 SHA；未验证项明确列出。
5. 集成 Worktree 最终状态、原始工作区状态和救援证据都可追溯。
