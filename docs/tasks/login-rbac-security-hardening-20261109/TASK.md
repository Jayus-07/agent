# 登录/RBAC 收尾与安全专项（2026-11-09）

## 目标

在 2026-11-08 安全审计整改之后，收口登录/RBAC 的剩余决策项，并完成审计中未处理的 5 个高风险专项与 PDF/XML 解析资源上限。

## 已确认决策

1. 多租户 UI 登录：先按单租户（default）；系统仍保留多租户模型。
2. 账号标识：新账号默认 11 位数字；管理员建号仅 `ops_` / `svc_` 前缀的运维/系统账号豁免；登录兼容历史非数字账号。
3. 管理端/客服端登录即校验准入；super_admin 按管理员对待。
4. 三端会话独立，不做 SSO。
5. 保留公开自助注册，只产生 viewer；管理端/客服端账号由管理员开通。
6. MFA 暂不做（后续阶段再评估）。

## 范围

- 管理员建号策略、删除 `/ops` 死页面
- 审计 5 个高风险项：
  - SSRF 与 `target_table`
  - RAG 生命周期/租户
  - 未鉴权观测端点
  - SQL CTE 表域
  - 客服多租户（super_admin 操作保护、FAQ 跨租户）
- PDF 解析资源上限（XML 已有节点/深度预算）
- 任务文档与发布前定向回归

## 验收

- 每项独立 PR，CI 全绿后合并 main。
- 安全/权限变化覆盖对应边界测试；真实本机重建验证。
- 正常 PDF 上传解析不受预算影响。

## 不在本任务范围

- 生产 ECS 发布与发布后观察（另行执行）
- MFA、多租户 UI、邮箱登录
- 选品 owner/库存/订单/广告/成本授权（独立项目）
- 审计中其余 `needs_validation` 线索（按风险另行排期）
