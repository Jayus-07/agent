# 企业助手整体质量与回复体验

## 目标

持续优化企业助手的核心问答能力和用户看到的回复，确保回答正确、依据可核查、结果好读、会话状态连续。参考 SQLBot 的数据展示方式，为 SQL 结果提供按数据形态自适应的图表/表格卡片，同时保留自然语言结论和查询上下文。

## 回复展示设计

- 先用简短自然语言回答问题，再展示可核对的结构化 SQL 结果卡；卡片补充证据，不代替回答。
- 单值/多指标用指标卡，适合的时间序列和排名用图表，其余回退明细表；图表不能丢掉分组、指标或精度，返回结果不完整或行数矛盾时不画趋势/排名图，明细始终可切换查看。
- 数值、单位、时间范围和统计口径只能来自查询结果、用户问题或已核实定义。结果未提供时不猜，并在摘要中说明范围不足或让用户补充条件。
- 将“本次 SQL 查询返回行数”和“卡片实际展示行数”分开表达；不要把 LIMIT 后返回的行数说成底层业务记录总数。字段缺失或数字矛盾时标明查询返回数无法确认，绝不据此声称空结果。
- 自然语言与卡片只重复必要结论；相同表格、行数和截断提示仅在能逐项确认一致时折叠。失败、降级、空结果和成功要让用户一眼区分。

## 范围

- SQL 问数：指标和时间口径正确、授权表选择准确、执行结果与版本化 Golden 语义一致；销量或销售额的排名/高低比较统一排除已取消订单，多层排名的每一层都应用该过滤，除非用户明确要求包含；参考 SQL 无法执行时整轮必须是 INVALID，不能用表路由命中冒充结果正确；结果比较保留数值精度并区分 NULL 与空文本；退款率排名排除销售额为 NULL/非正的商品；自然月比较限定完整日期边界；空集合指标按业务语义区分 0 与未知；按实体聚合必须使用稳定主键，避免同名合并；歧义无法安全判定时应追问，不猜口径。候选数据集可通过显式 SQL module 路径执行结果级评估，且必须校验 manifest 内容锁。
- SQL 回复体验：先给自然语言结论；有证据时带单位和时间范围，缺失时不猜。再按结果形态展示单值/多指标卡、趋势/排名图表或明细表；单行有多个指标时逐项展示，保留非数值的时间/分组上下文，不把不同单位放在同一坐标轴比较。趋势图仅在时间列唯一、日期唯一、没有隐藏分组维度、行数完整且展示全部指标时使用，并按日期升序绘制；否则完整展示明细表。支持展开查看、导出和会话历史恢复。只折叠能与结构化卡片逐项确认一致的重复表格/行数/截断提示；载荷不完整时清楚说明实际展示范围。只有后端明确确认本次 SQL 查询返回 0 行时才回复“没有匹配记录”；返回行数缺失或与已展示明细矛盾时，明确显示“查询返回数未确认/无法确认”，不得把它伪装成空结果。
- RAG 回复体验：核验召回是否命中有效资料、引用是否准确完整并能回到来源；正文引用编号须对应同一份参考文献和来源卡，同一文件的不同页/章节要保留各自引用编号和页码，来源卡在登记了版本/生效日期时应展示这些信息，历史恢复也保留；无法对应时明确提示，不得误指到其他资料；无证据、检索故障和正常无结果分别如实反馈。
- Conversation-first：以会话为主要承载，核对新建/切换/历史恢复、追问上下文、停止和异步事件归属；历史恢复需保留 SQL 结果卡、RAG 来源卡及拒答/置信提示。
- 整体回复验收：回答是否直接、清楚，单位和时间范围有依据时明确标出；错误、澄清、降级与成功状态不能混淆；同一错误不要在正文和错误提示里重复，已生成的部分回答仍须保留。

## 验收与停止条件

- SQL：关键语义回归通过；真实 SQL 结果须与相应结果级 Golden 或人工核对一致。静态 SQL 校验、假模型和组件测试不能替代真实数据验收。
- SQL 回复：至少覆盖单值、多指标、趋势、排名、普通明细、截断/大数和历史恢复；答案、结果卡、SSE 和历史记录一致。
- RAG：通过授权账号核查候选来源、有效索引代次、引用段落与用户可见答案；坏资料或检索故障不得通过改共享知识库制造通过。
- Conversation-first：新建、切换、历史恢复、追问、停止和迟到事件均绑定正确会话；API、SSE、Trace 与页面状态一致。
- 用户回复体验：成功、追问、无资料、检索降级、SQL 空结果/失败等主要终态清楚且不编造。
- 每个阶段仅运行与改动相符的定向测试；真实运行未执行时标为 UNVERIFIED，不宣称整体验收完成。
- 展示 Diff、HEAD、实际验证命令和结果、剩余风险；保持未提交，等待用户决定提交/合并。
