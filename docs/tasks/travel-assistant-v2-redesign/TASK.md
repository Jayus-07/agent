# 旅游规划助手 V2 重构

## 目标

在现有 Next.js 项目中交付旅游助手 V2：先让用户看到可操作的新页面，再逐批接入真实规划、结构化编辑和自动保存。页面规则以项目 `docs/design/travel-v2/README.md` 为准；若该目录不存在，则使用用户提供的 `travel-v2-ui-reference` 作为同一份参考。桌面工作台固定为左 AI、中时间轴、右地图；手机独立实现首页、聊天、模板预览、行程详情与编辑模式。

## 批次与验收

### Batch 1：可见 UI

- 首页、模板预览、AI 对话、桌面三栏工作台、手机行程页及编辑/搜索/交通/排序界面。
- 暂未接通的操作明确标注；演示数据明确标识，不能声称已正式保存。
- 提供实际 Next.js 页面、1440px 桌面截图和 390px 手机截图，逐页说明视觉差异、可操作功能和未接功能。
- 完成后报告并暂停，等待用户确认视觉效果。

### Batch 2：真实规划

- 接入现有旅游规划 SSE、澄清/完成/失败状态、已有行程读取和版本恢复。
- 接入真实景点候选、模板预览/个人副本以及真实行程时间轴/地图。
- 复验认证、资源所有权、租户隔离和既有 Agent 链路。
- 完成后报告并等待用户确认再推进下一批。

### Batch 3：结构化编辑

- 复用现有 Trip/Revision CAS 保存路径支持增删天数、安排与景点、替换/删除、排序、跨天移动、停留时长、交通方式及约束检查。
- UI 结构化操作不经过 LLM；AI 明确识别出的修改复用同一编辑路径。
- 锁定项、固定时间、并发冲突和路线/时间/预算事实须按服务契约校验。
- 完成后报告并等待用户确认再推进下一批。

### Batch 4：自动保存与收口

- 不展示用户可见 Draft 确认；校验成功后正式保存并支持撤销。
- 失败时不更新正式行程或显示保存成功；保留 CAS、历史和资源隔离。
- 按风险补齐权限、并发、撤销、网络失败和 Provider 降级验证；真实浏览器复验桌面和手机。
- 仅在用户确认全链路完成后清理废弃 V1 页面状态与过时测试，且不能删除其他业务数据。

## 全程约束

- 不覆盖或丢弃用户已有改动。若目录不是 Git 仓库，记录原因并用文件、服务和既有备份确认环境，不声称工作区干净。
- 不恢复已淘汰的旅游页面数据或历史；不绕过认证、资源归属、租户隔离或网关。
- 保留现有旅游 Agent、Graph、服务和 Provider；不重写七个 Agent，不加无必要 LLM 调用，不建立第二套行程版本系统。
- 查询只读，用户明确选择后才写入；无房态/价格或实时车次证据时必须如实披露，不得伪造成功或事实。
- 共享服务只在用户明确批准的范围内重建。每批完成后暂停，不自行跨批施工。

## 当前状态

Batch 1、Batch 2 与 Batch 3 已完成并留有证据。当前暂停等待用户确认后再进入 Batch 4。详细现状见 [PROGRESS.md](PROGRESS.md)。
