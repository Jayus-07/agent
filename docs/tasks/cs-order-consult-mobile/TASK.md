## 1. 背景与目标

### 背景
- 客服页（frontend/src/cs2/CustomerServicePage.tsx，挂 `/customer-service`）#498 已完成沉浸式改版：胶囊输入栏、快捷入口横滑、头像抽屉；但订单上下文仍只有两条弱通道：
  1. 商城「我的订单」页 `prefillCs`（sessionStorage `cs2-prefill`）预填**纯文本**后跳页；
  2. AI 会话中自己调工具查订单（多一轮交互）；桌面端右栏「最近订单」在移动端隐藏。
- 用户诉求：智能客服要配合商城中心「我的订单」一起用，参考淘宝客服：聊天页一键「发订单给客服」→ 选单 → 订单卡进会话。

### 目标
1. 移动端客服页一键「发订单给客服」：从本人订单中选择，以**订单卡**形式发进会话；
2. AI 与人工坐席都能获得结构化订单上下文（承接既有会话级订单槽 `cs_route.metadata.order_id`）；
3. 商城「我的订单」页「咨询此订单」升级为直达订单卡（保留旧文本预填兼容）。

### 非目标（明确不做）
- 不做优惠券/营销福利位（平台无优惠券模块）；
- 不做商品缩略图（MallOrder 契约无图片字段，补字段属 business-service 另立项）；
- 不改转人工/退款/取消等既有闭环流程，只加「订单引用」入口。

## 4. 数据契约与后端改动（最小化，分两期）

### 4.1 M1 —— 纯前端，零后端改动（可先行上线）

- 数据源：既有 `GET /api/mall/orders?limit=20`；
- 发送动作 = 结构化文本（AI 与坐席均可见可解析）：
  `【订单咨询】订单号 MO-xxx｜商品摘要…｜¥79.00｜已发货`
  后接用户补充问题（可选）。AI 侧订单查询工具有懒种子订单（MO- 前缀），收到含订单号的问题可直接命中；
- 单测：`customer-service-page.test.tsx` 增 3 用例（抽屉开合 / 搜索过滤 / 发送拼接）。

### 4.2 M2 —— 目标态（小改后端，启用预留能力）

1. **ChatRequest 增加可选 `order_no`**（`POST /chat/customer-service/stream`，frontend/src/api/chat.ts `streamChat` 同步加参）：
   - 服务端先 `PermissionChecker.validate_order_id` 归属校验（sandbox 与 http 网关两条路径都要验）；
   - 通过 → 写入 `cs_route.metadata.order_id`（复用 `context/context_manager.py` `resolve_order_slot` 承接回指，与「唯一物流查询」写订单槽同一机制），Agent 本轮起带订单上下文；
   - 校验失败 → 忽略该字段，回系统提示「未找到该订单」（统一口径，不泄漏订单存在性，不 500 不阻断）；
   - **客户端只传订单号引用，不传订单内容**；订单数据由服务端以可信身份经 business_client（X-Internal-Token）读取——对齐「身份只信任服务端验证后的上下文」红线。
2. **消息落库启用预留字段**：`content_type='card'` + `attachments=[{type:'order_ref', order_no}]`（`backend/customer_service/models/message.py:61-65` 已预留 JSONB；`conversation_store.py:108` 写死 `'text'` 处放开）；用户订单卡消息经 SSE 落库，历史会话重放也渲染成卡。
3. **人工态消息带附件**：`POST /api/cs/conversations/my/{id}/messages` 增可选 `attachments`（幂等键照旧）；坐席 WS `message.created` 自然透传（封套 `{type,event_id,seq,ts}` 不变）。

### 4.3 M3 —— 坐席端订单卡

- `frontend-cs` WorkbenchPage `AgentBubble`：`content_type='card'` 且 `attachments[0].type==='order_ref'` → 渲染只读订单卡（订单号/摘要/状态，数据从 Customer360 既有 `customer-context` 对齐，不在卡内新增查询）；
- 桌面用户端右栏「最近订单」行加「发送给客服」小按钮（复用抽屉逻辑，桌面也受益）。

## 5. 商城「我的订单」联动升级

- `MyOrdersPage.tsx` `prefillCs` 升级：新写 `sessionStorage.setItem('cs2-order-ref', orderNo)` 后跳 `/customer-service`；
- 客服页启动读取 `cs2-order-ref` → 自动打开订单抽屉并**预选中**该订单（需用户点「发送」确认，不自动发送，防误触）；
- 旧 `cs2-prefill` 文本通道保留（退款话术场景）。

## 6. 安全与边界

- 订单列表/详情一律服务端按 `identity.user_id + tenant_id` 过滤（既有 `require_identity` + `_require_user`）；
- `order_no` 归属校验失败统一「未找到该订单」口径，不泄漏他人订单存在性；
- 订单卡仅渲染：订单号/商品摘要/金额/状态/时间——不渲染收货人、地址、电话等敏感字段；结构化日志不落订单卡内容；
- 订单卡消息进会话记录，坐席端可审计（Content-Type 真卡后天然带 attachments 证据）。
