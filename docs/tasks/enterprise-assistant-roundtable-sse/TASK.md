# 企业助手 SSE 与回复体验改造

## 目标

修复企业助手因请求内模型调用次数上限而提前报 `BUDGET_EXCEEDED` 的问题；当真实用户模型用量余额不足时，将本轮作为“暂停”终态呈现，保留已收到的部分回答并提示补足余额后重新发送。企业助手继续使用原有 `/chat/agent/stream`、会话与企业助手能力，不接入管理员圆桌 API。

将 `/agent` 的页面展示完整替换为新的圆桌原型视觉语言：真实 SSE 过程条、工具/状态时间线、单一企业助手回复、暂停/错误/完成终态。新页面不得复用原 `/agent` 展示组件。

## 范围

- 请求内调用次数继续记录，但不作为硬拒绝条件。
- 仅用户作用域的额度不足映射为 `paused`；租户额度、预算配置、价格、token 等其他失败仍按原失败协议处理。
- `paused` 作为主 Chat SSE 终态，前后端生命周期一致；客户端保留部分回答和本地过程快照，不宣称从 checkpoint 恢复执行。
- 新建企业助手页面展示组件，保留现有会话、模型选择、发送/停止、预算状态和功能导航能力。
- 按当前事件契约与前端约定同步文档。

## 验收与停止条件

- `request_calls` 不再导致 LLM 调用拒绝；真实 user quota 不足产生 `paused`，部分内容可见且错误态不误报。
- 租户 quota 与其他失败不会伪装成 `paused`。
- SSE `paused` 被视为终态，不续播挂起，也不进入圆桌接口。
- `/agent` 页面不导入旧 `chat/*`、`agent/*` 展示组件，企业助手核心操作仍可用。
- 完成受影响前端构建、后端针对性执行验证；按仓库约定从当前任务工作树重建受影响本机服务并检查健康。未能安全重建时如实标记阻塞。
- 保持改动未提交，交付 Diff、HEAD、验证与风险后等用户决定是否提交。

## 性能验收口径补充（2026-10-27）

- 用户目标：普通解释2–5秒、知识库5–12秒、经营数据3–10秒、联网整理6–15秒。页面约1秒内明确反馈；首反馈、首答案token和完整回答分别记录，系统提示/拒答/权限拦截不算正向查询成功。
- 多来源分析/报告超过20–30秒应转持久后台任务。当前 Chat 尚无超时后执行迁移能力，已有 tasks API 的持久执行与 SSE 重放不能混为一谈；不能用超时后重发原问题模拟续跑。此项仍待实现、授权隔离与端到端验收。
- 本轮按真实业务账号验证；缺少数据权限时保留权限边界，记录待验收，不临时授予权限。测试种子资料造成的条款矛盾与模型拒答分别记录，不删除共享资料或调低证据门槛制造通过结果。

## 后续全部修复计划（用户要求，2026-10-27）

### 完成范围

修复追加实测中的改写误澄清、显式知识库请求被普通直答抢占、联网结果无关、SQL恢复后Trace终态不一致、切换会话卡片残留；同时收尾此前待完成的冷启动归因、联网整理与持久后台长任务。复用现有Router、Tool Governance、模型代理、任务与SSE链路，不扩大账号权限，不删除归档资料。

### 执行顺序与验收

1. 锁定当前任务源码/部署版本，保留未提交修改和10题Trace基线；将真实失败问法转为定向回归，先复现再改代码，不把Trace success当答案通过。
2. 第一批修正确性：调整既有普通对话/业务路由的判定优先级与边界，使明确企业知识查询不被通用写作/信息处理抢占；补礼貌改写/润色等无外部事实依赖的表达。权限拒绝必须有可信授权结果支撑。SQL按同一执行的最终可信结果及恢复关系聚合终态，保留失败尝试/拒绝原因和费用记录；真正未恢复错误、越权仍失败。前端将handoff、clarification等临时态绑定所属会话/请求，切换/新建清理旧态，晚到事件不得写进新会话；历史只恢复自身状态。
3. 第二批修联网：核对搜索参数、真实响应、引擎回退/解析/缓存，定位正确query返回无关内容的来源；在现有工具输出边界实施来源约束与相关性判定，过滤后无合格内容如实无结果；合格来源再经已有Reporter整理，保留真实来源链接，禁止先对无关内容生成总结。覆盖官方项目、中文/英文问题、无结果、异常、来源不匹配及网页不可信指令。
4. 第三批修性能和后台：将入口耗时拆到缓存/Prompt刷新/Guard/会话准备，定位后复用现有启动预热与缓存，分别验证重启首轮和稳定请求；模型生成慢独立归因，不靠缩超时丢弃答案。已知长报告从开始进入既有持久任务链路，20–30秒仍未完成时前端转后台任务卡，离页可查；保留可信产品/租户/用户身份与幂等，不超时重投原问题，不把SSE重放当checkpoint执行续跑。覆盖取消、失败、重启、恢复与重复请求。
5. 每批选择最小充分T1/T2，进行对应授权/RAG完整性/任务并发定向审查；从本worktree重建受影响代码服务并确认健康，再真实页面/API验收。最终重跑原10题与换问法、权限、跨会话晚到/断线恢复边界；按任务类型列出首反馈、首答案、完整耗时、正确性和Trace。原业务SQL权限与管理员样本分开。

### 停止条件

- 原10题均按目标行为正确处理；错误拒答、无关网页结果和旧卡片残留不能按done视作通过。
- SQL修正后实际成功时，页面/任务/Trace终态一致，历史失败可追踪；未恢复或未授权仍阻断。
- 联网整理有可核查的合格来源；无来源不编造。
- 约1秒明确反馈；普通解释2–5秒、RAG5–12秒、SQL3–10秒、联网整理6–15秒为目标。冷/热和供应商耗时分列；有限样本不宣称P95达标，未达项目如实列出。
- 长任务有真实持久化任务号、后台进度/结果与取消/恢复契约，不能依赖内存线程假装持久任务。
- 最新代码部署和对应实际运行验证完成，交付Diff、HEAD、测试/审查与剩余风险；未完成不得标整体验收通过，提交合并沿用仓库授权规则。
