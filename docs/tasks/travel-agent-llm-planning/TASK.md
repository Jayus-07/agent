# 旅游 Agent 规划决策补强

## 目标

针对旅游助手标准审查中的核心缺口，让已验证的真实 POI 候选与用户偏好进入受治理的 LLM 规划决策；保留代码对权限、候选 ID、必去项、日容量和最终行程的确定性校验。自然语言理解在需要时默认尝试统一 LLM 决策，并能在模型不可用时安全回退。

## 范围

- 旅游 Planner 使用统一 LLM 角色、Prompt 注册/默认模板、超时与用量归因，给真实候选分配出行日。
- 对模型输出做严格结构、候选归属、必去项、天数及日容量校验；不合规时回退既有规则排程并记录原因。
- 默认打开受约束的旅游轮次理解和规划模型开关；保留显式关闭配置。
- 更新旅游现状文档并添加覆盖成功、拒绝和回退的定向验证。
- 保留现有 PostgreSQL Trip/Revision、CAS、撤销/恢复路径，以及 Provider 数据来源和降级契约。

## 不在本次范围

- 不为没有凭据或没有上游服务的 Provider 伪造实时数据；不接入未经选择的酒店库存/价格供应商。
- 不开放预订、支付、出票等副作用。
- 不修改主数据库数据、不发布线上 Prompt、不提交或合并分支。

## 验收与停止条件

- Planner 在启用且模型/Prompt可用时能产出候选 ID 组成的逐日安排；行程仍通过既有确定性校验与保存链路。
- 非法候选、重复/遗漏 ID、缺失必去项、容量超限、超时或预算拒绝均不得变成“规划成功”；应记录降级原因并使用既有规则排程。
- 相关定向测试与实际服务运行核验完成；检查 Git Diff，分支保持未提交。
- 对需要真实密钥、外部服务或真实模型的项目标明未验证，不以占位值代替。
