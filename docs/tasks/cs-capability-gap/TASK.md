# 客服能力清单补齐任务

## 目标

以可审计、可人工接管的生产运营能力为目标，完成客服能力差距 B4–B8 的 mock/人工分流闭环，并为 B9 建立独立立项记录。暂不接真实支付、物流、定价、税务或开票系统。

## 边界

- Mock 只用于演示、测试和模拟业务状态；不得把模拟结果表述成真实资金或订单变更。
- 真实客户缺少可信业务数据或真实写接口时，回答“待人工核实/处理”并进入现有客服队列。
- 复用现有 action/audit、确认、幂等和业务 mock；不新建平行 Tool 注册、工作流或审计系统。
- 不触发已保留的 B4 q3 会话 `b4-acc-q3`，不确认、不提交退款。
- 账号注销/删除数据是单独合规项，当前没有保留策略与删除范围，不纳入本批自动实施；作为生产上线前需决策的阻塞项跟踪。

## 范围与验收

- B4：支付流水查询、重复扣款识别；仅在明确申请、严格 mock 候选条件和显式 mock 开关下模拟自动退款；查询请求只读；其他情况走既有人工流程；操作和模拟结果持久审计、幂等。
- B5：催发货/催派送 mock 登记、24 小时去重、物流状态回显；非演示业务不伪称商家已收到。
- B6：价保资格、mock 当前价格、确认前后复核、mock 钱包记账；开关默认关闭，资金模拟标识清楚。
- B7：在途订单级改址 mock 提案与确认；执行时复核物流状态；已派送/签收拒绝；账户默认地址不变。
- B8：抬头/发票 mock 查询、申请与确认、重复开票保护；用户订单页入口不纳入。
- B9：只交付多模态项目立项记录，不实现图片链路。
- 所有新增写操作须覆盖权限/租户、幂等、失败和审计；每批定向测试、受影响服务重建与 mock 验收通过。

## 停止条件

- 出现需确认的退款/资金真实副作用时停止，不通过真实业务端点执行。
- 业务规则（价保窗口、自动退款限额、留存/注销规则）缺少授权值时保持 fail-closed，不自行编造。
- 每批代码完成并验证后先展示 Diff 和证据；依仓库规则等待用户确认后提交/开 PR，不擅自合并。
