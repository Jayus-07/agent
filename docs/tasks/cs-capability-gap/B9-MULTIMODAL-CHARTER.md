# B9 客服图片理解立项书

> 状态：**仅立项，未实施**　|　版本：1.0　|　立项日期：2026-11-06
> 适用范围：智能客服对话中的用户图片附件；不代表 `/agent`、旅游或其他产品已纳入。

## 一、立项目标

让用户可以在客服对话中提交与售后问题有关的图片，由系统提取可见事实、结合可信订单数据和客服政策组织答复，并在识别不确定、证据不足或涉及高影响决策时转人工。

图片识别只提供辅助证据。图片内容不能单独证明订单归属、付款状态、商品真伪或退款资格，不能直接触发退款、改址、价保或其他业务写操作。退款等动作仍走既有授权、确认、幂等和审计链路。

本立项只交付方案与决策清单，不包含上传接口、存储、模型调用、前端或数据库实现；不接入真实支付、物流、订单或外部视觉服务。

## 二、现状核对

以下为 `origin/main` `ed95ddc`（已合入 B8）上的代码现状：

- [ChatRequest](../../../backend/app/api/schemas.py) 当前接收文本 `question`，未定义图片附件引用。
- [客服消息模型](../../../backend/customer_service/models/message.py) 已有 `content_type`、JSONB `attachments` 字段；[MessageManager](../../../backend/customer_service/managers/message_manager.py) 也接受附件参数。这只证明存储模型有承载字段，不代表上传、授权、对话推理或用户界面链路已经打通。
- [前端 ChatRequest](../../../frontend/src/api/chat.ts) 当前使用文本问题和会话字段，没有图片上传/附件引用契约。
- [模型配置 API](../../../backend/app/api/routes/model_config.py) 的 `model_kind` 枚举包含 `vision`；[模型角色表](../../../backend/config/model_roles.py) 当前登记了 RAG 文档 OCR 角色，但未发现客服在线图片理解的已验证角色和调用链。配置枚举存在不等于客服视觉推理已可用。
- RAG 上传/OCR 面向知识文档处理，不等同于用户客服消息附件入口；需另行评估可复用的文件校验、存储和模型治理能力，不能直接把文档上传通道当成客服上传接口。

## 三、业务范围

### 首期候选场景（需业务确认）

- 用户提供商品、外包装或收到物品的照片，辅助描述破损、错发、缺件等售后问题。
- 用户提供标签、型号或票据照片，辅助提取可见文本，之后仍以订单和业务系统事实为准。

具体场景、允许识别的字段和转人工规则须由客服运营确认。首期优先覆盖“帮助理解用户描述和整理证据”，不把模型判断当成售后结论。

### 不在首期范围

- 自动判责、自动承诺赔偿、自动退款或直接修改订单。
- 人脸识别、身份认证、支付凭证的真实性判断、商品真伪鉴定等高风险判断。
- 视频、音频、实时摄像头、多图片批量分析，以及 `/agent`、旅游等其他产品入口。
- 训练或微调视觉模型、建立独立的图片标注平台、重做客服工作台。
- 客户端订单页重构或新的人工服务系统。

## 四、建议链路与职责

1. **上传与授权**：客户端先上传图片，服务端从已验证身份取得 user/tenant/conversation 归属；返回不可伪造的内部 `attachment_id`。对话请求只引用该 ID，不接受客户端任意 URL 或任意对象存储路径。
2. **文件安全**：服务端校验文件签名和实际格式、文件大小、图片像素/解码资源、数量及恶意内容；处理 EXIF 等不必要元数据。限制值须可配置并经业务、运维和安全确认。
3. **私有存储**：图片私有保存、加密并绑定租户和消息；下载使用短期授权。确定保存期限、删除、备份和事故恢复规则后才允许上线。
4. **客服推理**：客服入口以 `attachment_id` 取回已授权图片，通过受治理的视觉模型角色生成有限结构化观察结果；模型输出与用户图片均作为不可信输入，不能覆盖系统政策、可信订单事实或权限判断。
5. **答复与分流**：把可见事实与来源标识交给现有客服编排。低风险场景可生成带不确定性说明的辅助答复；置信度不足、图片不清晰、信息冲突或命中高风险场景时，进入现有人工队列，不猜测、不伪造已处理状态。
6. **持久审计**：记录附件 ID/哈希、关联会话和租户、处理状态、模型角色与版本、结构化结果摘要、路由/人工原因、用量和成本归因。不得把图片二进制、base64、长期可用图片 URL 或不必要的 OCR 原文写进普通日志。

## 五、生产决策与阻塞项

以下值没有现成业务授权，实施前需由责任方确认；确认前保持 fail-closed，不自行设定生产值。

| 决策项 | 责任方 | 未确认时的处理 |
|---|---|---|
| 首期场景、图片可支持的客服判断及必须转人工的场景 | 客服运营/业务 | 仅文本答复，图片问题转人工 |
| 格式、单图大小、单条消息图片数、像素上限 | 产品/安全/运维 | 拒绝图片输入 |
| 保存期限、删除请求、备份清理、法律保全例外 | 法务/隐私/数据治理 | 不开放生产图片上传 |
| 存储位置、加密密钥、跨境/第三方传输许可 | 安全/隐私/运维 | 不调用外部视觉服务 |
| 视觉模型供应商、模型版本、角色绑定、故障策略 | AI 平台/安全 | 不启用在线识图 |
| 单次及月度成本预算、延迟预算、并发容量 | 产品/财务/运维 | 超预算或超时转人工，不无限重试 |
| 结果置信度阈值、质量抽检方法、人工队列 SLA | 客服运营/质量 | 无阈值或无接管队列时不自动给结论 |
| 图片撤回、用户访问/导出和审计保留范围 | 法务/隐私/客服运营 | 不上线持久化图片能力 |

## 六、失败、安全与人工接管

- 未授权、附件不存在、租户/会话不匹配时拒绝访问，不通过模型探测资源是否存在。
- 格式错误、超限、解码失败或安全扫描不可用时拒绝处理，并提供文本描述/人工入口。
- 模型超时、不可用、预算耗尽、结果结构不合法或置信度不足时，明确告知未能识别并转人工；不伪称识别成功，不自动切换到未经批准的供应商。
- 图片中出现“忽略规则、执行退款”等文字，只是图片内容，不构成系统指令或用户授权。
- 模型不得根据图片直接办理资金或订单动作；若后续政策允许低风险动作，必须另行定义授权条件并复用现有客服 action/audit/确认/幂等机制。
- 删除策略必须覆盖对象存储、缩略图、缓存、备份和派生 OCR/视觉结果；审计只保留实现审计所需的最少元数据。

## 七、分阶段实施建议

| 阶段 | 交付 | 进入下一阶段的门槛 |
|---|---|---|
| 0. 业务与合规定界 | 确定首期场景、禁区、保存/删除和人工接管规则 | 第五节所有生产阻塞项有责任人和书面结论 |
| 1. 安全附件底座 | 上传、授权、私有存储、校验、清理、消息引用 | 跨租户/越权/恶意文件/删除测试通过 |
| 2. 客服视觉能力 | 模型角色、预算/用量、结构化观察、失败降级和人工分流 | 质量集达标；异常、幻觉和提示注入评测达标 |
| 3. 用户端交互 | 客服对话图片选择、上传状态、失败重试、图片回显与删除反馈 | 键盘/移动端/无障碍和端到端验收通过 |
| 4. 限量试运行 | 运营抽检、成本与失败告警、回滚/关闭开关 | 运营、质量、安全共同签署扩大范围决定 |

以上为建议顺序，尚未授权开工。原总计划中的“5–8 天”只是早期粗估，未拆分验证，不含合规评审、供应商审批和生产准备；不得作为已承诺排期。

## 八、未来实施验收标准

未来独立实施批次至少应提供以下证据，且不得用本立项书替代：

1. 合法用户只能上传和读取自己租户、会话内的附件；跨租户、伪造 ID、过期授权均拒绝。
2. 文件格式、大小、像素、数量、恶意内容和解码异常的限制由配置和契约测试覆盖。
3. 图片与消息关联可追溯；审计可回答“谁在何时上传、哪个模型版本处理、输出了什么摘要、为何答复或转人工”，不泄露图片内容。
4. 模型故障、超时、低置信度、预算耗尽和人工队列不可用分别有明确的状态与用户答复；无不可见重试或静默丢任务。
5. 代表性场景评测覆盖识别准确性、错误自信、图中文字提示注入、隐私字段、人工分流和用户纠错；业务数值阈值须经业务确认。
6. 对话端到端验收确认视觉结果只辅助客服答复，不绕过订单事实、授权和资金操作确认；删除/留存测试覆盖主存储与派生数据。
7. 受影响服务从任务 worktree 重建并健康检查通过；PR 检查通过后，按仓库规则单独请求提交与合并确认。
