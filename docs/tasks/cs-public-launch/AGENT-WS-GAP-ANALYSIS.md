## 三、缺陷清单（按优先级）

### P0-1：WS 自动派单完全失效（恒态轮询降级）
- 现象：坐席端永远显示「连接中断 · 轮询降级中」；新会话 offer 无法实时推送，坐席只能靠轮询+手动刷新发现新会话。
- 根因：frontend-cs 生产容器为 Next standalone（无自定义 server），`ws://127.0.0.1:3300/ws/cs/agent` 在容器内无路由 → 握手必败。网关侧 `/ws/cs/*` 路由（enable_websocket）已就绪但页面同源是 :3300。
- 影响：转人工等待的会话无人自动接单 → 120s（现 600s）后超时关闭登记留言工单（降级路径工作正常）；人工服务靠"用户端可见的轮询 + 坐席手动认领"支撑。
- 修复方向（需部署形态决策）：①`NEXT_PUBLIC_WS_ORIGIN` 构建时注入网关地址（本机 `ws://127.0.0.1:9080`），前端 ticket.ws_path 拼接该 origin；或 ②frontend-cs 换 custom server 做 WS 代理。方案①改动小、网关链路现成。

### P1-2：待接入队列混入终态会话
- 现象：队列 15-16 条中大量已关闭/超时的历史 handoff，点击认领返回 409。
- 应只列 `waiting_human`/`offered` 可认领状态。小改 queue API 过滤条件。

### P1-3：看板转人工率 >100%
- 现象：近7日转人工率 102%。口径：转人工数=handoffs 行数（同一会话可多次转人工/超时重开），接待量=会话数 → 比率可超 100%。
- 修复：转人工率改按"发生转人工的去重会话数 / 接待会话数"，或 clamp + 口径标注。

### P1-4：坐席绩效接待量失真（关闭即清空归属）
- 现象：今日实际认领并关闭 1 个会话，绩效表接待量 0。
- 根因：conversations 关闭时 `assigned_agent_id` 被清空（P6 已知设计），绩效 join handoffs 依赖归属字段 → 关闭过的会话查不到归属。
- 修复：绩效取数改用 `handoffs.assigned_agent_id + closed_at`（handoffs 行保留归属），或关闭时快照归属到独立列。

### P2-5：共享库测试数据堆积污染运营视图
- 进行中会话 1110（p3-/p8r-/eval_bot/uitest 等测试批次残留）、待接入队列终态条目、工单列表"会话原文缺失"工单。
- 建议：立项一次性治理（按前缀白名单清理），并在评测/压测规范里要求会话终态收尾。

### P2-6：已知降级交付（维持）
- 更多菜单三功能（发送订单卡片/内部备注/转为工单）——无后端能力不做假按钮（P4 决策，REVIEW §4.5 维持）。
- 质检 AI 预填为确定性启发式（非 LLM）——P6 决策。

### P2-7：孤儿组件群
- `Sidebar/NavGroup/TaskSidebar/components/chat` 等无渲染场景遗留（REVIEW §4.5 / TASK §11），牵动 layout.test——清理需整体盘点另立项。
