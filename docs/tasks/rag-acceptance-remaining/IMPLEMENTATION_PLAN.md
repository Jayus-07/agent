# RAG 生产验收收口方案

## 范围

本阶段只关闭 `TASK.md` 与 `PROGRESS.md` 登记的上传/索引指标和延迟观察门禁。其他验收标准继续以 [ACCEPTANCE_CHECKLIST.md](ACCEPTANCE_CHECKLIST.md) 为准；不重新执行已完成的历史批次，不清理或改写生产数据。

## Batch 1：上传与索引指标

1. 核对 app 与 rag-index-worker 的镜像版本、启动时间和指标暴露端点，确认查询的是承载真实上传/索引请求的进程。
2. 从真实上传成功与失败路径检查 `rag_upload_total` 的计数出口、标签和递增时机；成功与失败均须出现带标签样本。
3. 复核 `rag_index_duration_seconds` 的成功/失败分桶和任务队列等待指标，确认指标名称、标签和值与请求一致。
4. 对指标出口改动添加针对性测试；部署后从目标环境 `/metrics` 或 Prometheus 查询验证，并记录查询时间范围。

## Batch 2：延迟观察

1. 先确认被测版本、用户入口、Trace 查询和 SLA 看板均指向同一目标环境。
2. 按 [SLO 定义](../../observability/slo.md) 与验收清单要求运行干净观察窗口；不得用单次请求替代窗口结果。
3. 对窗口内请求核对 Trace 的请求结果、耗时、未归因耗时和引用；同时记录 SLA 聚合数据及错误/无证据率。
4. 将观察窗口的起止时间与新 Trace 分开记录。窗口外的历史超时不可删除或改写，也不能计入新窗口的失败数。

## 关闭条件

- `rag_upload_total` 在目标环境中有成功、失败两类真实带标签样本，索引时长指标可从正确进程查询。
- 干净观察窗口满足 SLO 和验收清单约束，Trace 与 SLA 汇总一致。
- `PROGRESS.md` 和清单状态有当前证据；只有四项门禁公式全部满足才可声明 `RAG_PRODUCTION_READY=true`。

## 执行边界

生产数据写操作、重建索引、重启共享容器或改变发布状态必须先核对目标和影响面，按仓库既有审批/变更窗口执行。无法访问目标环境时记录未实测原因，不得以本地 mock 或旧探针代替生产验收。
