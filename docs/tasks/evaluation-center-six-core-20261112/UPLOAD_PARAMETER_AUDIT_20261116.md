# 上传链路参数与“魔法数字”审计

日期：2026-11-16。范围为三端上传选择/预检与 BFF、FastAPI 上传入口、队列与 SSE、OCR/元数据抽取、清洗/解析/Parent-Leaf 切分、增强与向量写入、缓存和质量记录读取。这里只审查会影响接收上限、处理资源、解析/切分/索引结果或用户进度的参数；HTTP 状态码、数组从 0/1 开始、PDF 72 pt/in 换算和 CSS 尺寸属于协议/单位/展示实现，不当作业务阈值。

## 本轮修正

- 文件 SHA 读取块大小复用 `RAG_UPLOAD_CHUNK_SIZE`；文件魔数只读取所需签名前缀，文本 NUL 检查覆盖整个上传流。
- PDF 入口不再用 20 字符与 Parser 的 30 字符分叉；移除前 10 页预检。仅在 OCR 关闭时，对通过 PDF 资源预算的整份文档做文本层拒绝检查。
- OCR 单次管理员预算不能超过服务级预算；PDF 页数保护不再被误当作 OCR 成本上限。
- BFF RAG 上传上限不能超过 APISIX 64 MiB，也不重复维护后端的 50 MiB 文件上限。
- 删除无来源的固定 16 KiB multipart 余量；三个 BFF 与后端中间件按 64 MiB 限制总包，文件流按 `RAG_MAX_FILE_SIZE` 精确限长。新增 APISIX/BFF/后端值一致的回归检查。
- 进度队列 TTL 从 SSE 最大时限推导；本机队列与 Redis 轮询共用 SSE 心跳配置。
- 锁、GC、SSE、OCR/PDF、切分配置新增非法值校验，避免零并发永久排队、零读块等错误配置进入运行态。
- Embedding 批次/重试/超时、语义切分批次与表格行列/类型切分上限新增正数及退避关系校验。
- 修正 Embedding 缓存 TTL 环境配置被构造器默认值盖过的问题；Embedding/表格描述缓存 TTL 必须为正，元数据规则本地 TTL 必须有限且非负；明确批次 ID 的输入上限并覆盖 64/65 字符边界。
- 元数据 LLM 槽位等待超时不再绕过并发闸门；饱和时记录指标并按规则结果继续。云端 OCR 超时/间隔新增合法范围校验。
- 前端未知处理阶段只显示中文兜底标签；处理耗时改用“毫秒/秒”中文单位。
