# 评测中心六类核心集与运行闭环

## 目标

沿用现有四页签与未提交实现，先完成数据资产盘点，再让已发布数据集版本能够在管理端配置并发布为评测方案，最终进入现有运行、逐题结果与对比流程。基于可核验资料逐类推进六类首期评测集；真实运行结论必须区分质量失败、运行无效和未验收。

## 九阶段实施顺序

| 阶段 | 做什么 | 管理端验收时用户能看到什么 | 完成标准 |
| --- | --- | --- | --- |

| 3. 统一题型和用例契约 | RAG 导入、静态校验、API 使用同一题型清单；区分 Ragas 类型与专用题型。 | 数据集详情逐题显示题型标签；编辑/导入时非法字段有明确错误提示。 | 类型兼容、必填字段和多跳双证据约束有定向测试；RAG 类型不冒充六模块通用 Runner。 |

| 5. 评审生成质量 | 自动检查答案、证据、题型、重复和事实覆盖，再人工核验。 | 候选区显示待审/通过/拒绝数量；逐题显示事实、证据原文、源版本、审核人、时间和拒绝原因。 | 没有可核验来源或不满足题型的候选不能批准/晋升；审批历史可回查。 |
| 6. 建设六类核心集与执行能力 | RAG 每题绑定知识库快照、文件/版本和证据原文；客服绑定政策/会话或订单夹具；SQL 绑定 schema/数据快照；旅游绑定规则与供应商沙箱；Planner/Tool 绑定工具规则和调用记录；E2E 绑定可复位测试数据。 | 数据集页逐模块显示实际用例数/目标范围、来源类型和版本、质量状态、运行能力；草稿、质量 FAIL、运行 INVALID 分开显示。 | RAG/客服 30–50，SQL/旅游/Planner-Tool 20–30，E2E 10–20；每条用例能回到事实来源或受控执行结果，每类有有效运行证据或明确 BLOCKED/UNVERIFIED。 |
| 7. 管理端运行和追溯 | DatasetVersion→Suite→Run→逐题结果/Trace/结果对比闭环。 | 运行页显示 PASS/质量 FAIL/INVALID、模型与数据快照；逐题抽屉分开展示检索和答案评分及证据；Trace 页可按 ID 打开并核对 Span；对比页显示版本差异。 | 固定 Run ID 可复查；逐题 Trace 与 Trace API 的 Span ID/数量/时长一致，权限边界不变。 |
| 8. 验收新基线并安全切换 | 六类新基线通过后备份并准备回滚，再切默认入口。 | 数据集/方案页清楚标出新旧默认状态、版本映射和归档状态；历史 Run/审计可查，并有回滚操作记录。 | 六类门槛全过且回滚验证成功才切；缺归档能力时不改默认入口。 |
| 9. 导出训练/微调格式 | 最后只导出已批准且来源/标签完整的用例。 | 数据集操作区展示可导出条数、过滤原因、JSONL 预览、字段校验结果、来源和导出审计记录。 | 对接目标训练接口字段契约；被拒绝/未发布样本不会混入导出。 |

共享数据库、线上资产的写操作遵循仓库隔离规程；不可安全执行的导入/运行会记录为阻塞，不通过共享环境试错。

## 范围与停止条件

1. 盘点仓库题集、业务原文/规则、接口契约、测试与管理端已发布资产，记录复用、重核、补资料及缺件。
2. 为已发布 DatasetVersion 增加 Suite 配置/发布入口；保留 API/页面既有角色边界和四页签结构。
3. 选择证据完整的少量 RAG 用例，完成来源核对、人工核验、DatasetVersion/Suite 发布、真实 Doubao 运行、逐题检查；分别展示检索证据与答案评分。
4. 增强多知识库生成选择和拆批预览；按 KB 保持候选来源和评测边界。
5. 只有新基线通过后才讨论默认入口切换；不得在没有归档/回滚依据时更改共享默认资产。

停止条件：本阶段可运行闭环和实际验收证据齐全，或明确记录外部服务、数据、权限、模型或上游接口阻塞；提交前展示完整 Diff 和定向验证并等待用户明确确认。

## 设计约束

保留数据集、失败 Trace、运行评测、结果对比四页签，以及现有表格、分页、抽屉和详情行为。沿用评测中心已有中性白卡、细边框、`bg-*`/`text-*`/`accent` 设计令牌与 Drawer；配置步骤集中在现有抽屉模式，动效服从 `prefers-reduced-motion`。不改变权限或把离线契约结果表述为业务质量结论。

## 验收层级

- 文档/差异自查：T0。
- 新增配置、拆批行为：前端定向 Vitest 与类型检查（T1）。
- 发布/权限/运行接口：受影响 V2 契约定向测试及真实授权浏览器链路（T2/T3，按环境可用性）。
- Doubao 评测：真实运行、固定 Run ID、逐题结果与 Gate 证据；一次工程测试通过不替代模型质量验收。
