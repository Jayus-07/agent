# TASK: 旅游预算真实化 + 首页「推荐行程」能力橱窗（travel-value-showcase）

> 创建：2026-11-04 · 状态：**立项（待用户确认命名与地板数字后开工）**
> 用户需求原话（2026-11-03/04）：「目前的行程结果经济还是太贵了 压到最低预算可以是多少钱 很多人不太想花钱 除了交通方式的话」「上一版的首页有推荐行程 这个要加上 用真实的生成行程结果 加一个按照经济 风格 区分」「不能直接说穷游 这个词不好听」；设计补充：「推荐行程区块的功能是让用户最快了解项目的功能」。

## 0. 需求解读（开工前与用户复核一遍）

本任务 = 两个互相咬合的改造，核心是**让"低价真实"成为平台的转化钩子**：

1. **预算真实化（低价供给口径）**：现行费用定额是「城市均值」（餐饮 ¥120-160/人/天、住宿 ¥350-520/晚，`config/travel.py:210`），导致经济档 2 人 2 天地板 ¥830-1,160——远高于真实低价玩法（小吃带 ¥30-50/人/天、经济连锁大床 ¥80-150/晚、免费 POI 优先，rollinggo 直连已有 ¥80/晚真实报价）。要新增一档**展示名「平价」**（内部值 `budget`），把 2 人 2 天总价压到 **≤ ¥400**（3 天 ≤ ¥600），并让用户能说出来触发（"穷游/省钱/花小钱/越便宜越好"等口语全部映射到平价档——**词表宽容收录、展示侧零出现"穷游"字样**）。
2. **首页「推荐行程」能力橱窗**：恢复上一版照片卡区块（大图封面+天数徽章+城市+风格标签+标题摘要+天数/人数/预算行），数据源**只允许服务端真实行程**（`fetchTravelTripsV2`，PR #286 后已入库北京/西安/厦门三条，继续补平价样例），加**档位×风格**筛选（`brief.tier` + `brief.preferences` 真实字段），卡片突出平台能力信号（预算构成/免费门票/评分/诚实披露），点击透传完整工作台。**它不是"最近行程"翻版，而是让新用户 3 秒看懂平台能干嘛的功能橱窗**。

两个改造咬合点：预算真实化之后，橱窗里才有「2 人 2 天 ¥400 玩福州」这种最有说服力的真实低价样例——**先做预算，再做橱窗，最后补样例**。

## 3. 硬性红线

1. **真实数据唯一**：橱窗只渲染 `fetchTravelTripsV2` 返回的已保存行程；任何组合筛空 → 如实空态（「还没有这类行程」+ 去规划入口），**禁止种子/演示数据垫**。
2. **展示侧零"穷游"**：档位展示名「平价」（完整标签「平价出行」）；「穷游」只作为**输入触发词**收录进词表。卡片预算照旧标注「预估 · 未核验」口径。
3. **定额改动连带同步**：改 cost 常量 → 同步 cost 单测断言、金标/评测集涉及金额的期望（DATA-01 合规路径）、缺口卡文案、validator 阈值——一处改漏即假行程风险。
4. **既有档位零回归**：economy/comfortable 行为与数字不变（budget 是新增档，不是改 economy——用户"经济还是太贵"由**新增更低价档**解决，不拉低已验收口径）。
5. 服务端写状态机/幂等/SSE 契约零改动；橱窗筛选是纯前端过滤。

## 5. 决策点（开工前用户拍板）

1. ✅→**待确认** 低价定额实现口径：**(a) 独立低价定额表（推荐）**——budget 档用绝对低价（餐 40/住 120 级别），语义直白、验收数字硬；vs (b) 按城市均值打折乘数——复用现有模型但数字随均值漂移。
