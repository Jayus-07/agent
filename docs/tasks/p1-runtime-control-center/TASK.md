## 1. 目标与固定边界

以仓库现有 `frontend-admin/`、页面、后端路由、Runtime 与业务治理服务为基础，加快桌面端第一轮管理端交付。保留现有产品结构，不重新设计管理端，不建立第四套管理端。

- 六组侧栏导航沿用 PR #54：运营总览、业务运营、内容与质量、运行监控、能力治理、安全运维；已有路由和详情返回关系继续兼容。
- 已合并、已有或正在 PR 中的能力只对账、修复、整合和接入，不重复开发。
- 前端页面与确有必要的 API 适配同批交付；只有源码证据证明现有 API 不足且权限可验证时才改后端。
- 不新建第二套 Runtime、Tool/Capability Registry、Prompt 发布状态机、统计系统或费用账本；不直接重构共享 Runtime。
- 读操作和敏感写操作分开验收；前端隐藏入口不能替代服务端认证、角色、租户和资源级授权。
- 未覆盖、过期或失败的数据必须呈现 UNKNOWN/STALE/ERROR，不把 HTTP 成功、Tool 传输成功、Run 完成和业务成功混为一谈。
- 本轮要求桌面端 1280x900、1440x900。移动端适配不阻塞本轮，发现的既有权限或安全问题仍须修复。
- 不要求灰度、影子双跑；管理端变更不成为重构共享 Runtime 的理由。无关 RAG/Travel 测试不作为管理端施工门禁。

## 3. 数据、权限与页面契约

页面继续使用现有 Admin API Client、认证刷新和后端契约。`/api/admin/runtime/*` 等旧设计稿中的路径只是目标命名建议，不是要求新建的 API；先查现有 Router、Schema、鉴权和调用方。

- 每个数值可追溯到唯一现有事实源，显示范围、样本、币种/结算口径和观测时间；来源不可用时呈现原因。
- Trace 只显示实际发生的 Span；保留业务终态、执行终态、Tool 执行状态和审批状态的区别。取消后物理结果未知时显示 UNKNOWN/IN_DOUBT，不自动重试副作用。
- 全局日志或聚合须有管理员授权；Trace、租户和资源读取须服务端执行资源级授权及租户过滤。Viewer、Editor 的无权请求应返回 403/404，而不依赖前端隐藏按钮。
- Prompt、预算、价格、Tool 策略和审批写入只走已存在的服务端权限、CAS/幂等、确认、审计及回滚流程。缺少可验证写路径时保留 BLOCKED。
- 不展示密钥、原始自由文本错误、隐私提示词、完整 SQL/Tool 参数或未授权租户数据；展示诊断码仅接受安全的结构化标识。

## 5. 本机真实 API 验收入口与等级

统一复用现有 `frontend-admin` 本机入口、登录流程、API Client 和本地网关/后端：启动现有服务后访问 `http://127.0.0.1:3200/login`，以用户正常持有的本机登录态浏览页面，并在浏览器 Network 中记录调用路径、状态码、角色、租户、页面截图和时间。若环境以其他端口/启动方式配置，以仓库当前配置为准。

- 不复制、读取、打印或提交 API_KEY、Cookie、Token 等私密凭据；不为验收新建账号或改共享数据库。无现成登录态时停止真实 API 验收并标 BLOCKED，列出需要服务/管理员会话恢复后补的页面和请求。
- **L1 展示**：组件/页面测试覆盖 loading、empty、error、stale、诊断码脱敏、导航和 UI 角色入口。可在无真实 API 会话时完成。
- **L2 只读接口**：用正常浏览器登录态验证读取 API 的角色、租户和资源授权；管理员按权获得预期数据，Viewer/Editor 通过 UI 和直接请求均得到规定 403/404；核对数据来源、新鲜度和权限过滤。
- **L3 敏感写入与权限**：仅对当前已存在的写路径，在隔离租户/可回滚数据上验证允许/拒绝矩阵、参数校验、CAS/幂等、审计、结果查证和回滚。禁止用 UI 隐藏代替 API 检查。不存在或不可安全隔离的写路径标 BLOCKED，不制造写操作。

PR #63 本轮不包含敏感写 API；因此不能报告 L3 写入 PASS。现有定向后端权限测试只证明被覆盖路由的管理员与非管理员守卫行为，不代替真实租户资源验收。

### 管理端专属 CI

新增 `.github/workflows/frontend-admin.yml`：仅管理端前端、观测管理员权限路由/测试、相关 Python 依赖或该 workflow 变化时运行。前端 job 使用 Node 20 与 `package-lock.json` npm 缓存，执行锁定依赖安装、依赖漏洞门禁、Vitest、TypeScript 和 Next 构建；后端权限 job 使用 Python/pip 缓存并运行观测只读端点管理员守卫测试。CI 不依赖 RAG/Travel 全量测试。

main 的历史官方 npm audit 基线为 **15 项（1 critical、9 high、5 moderate）**，包含 Next.js 14.2.29。安全 PR #68 已升至受支持的 Next.js 15.5.28。锁文件修复 `85edd1b` 后，CI run #6 的 `npm ci`、Vitest、TypeScript、Build、High/Critical audit 均 PASS，secret-scan 与 RAG PR Smoke 也 PASS。修复在合并进入 main 前仍属候选；未豁免安全门禁。
