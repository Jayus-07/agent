# 旅游助手 V2 Batch 3：正式行程结构化编辑

## 目标

把 V2 工作台当前不可保存的编辑入口接入既有 Trip Revision CAS，实现真实、可撤销的结构化编辑。继续使用 V2 Trip/Revision，不引入第二套行程版本系统。

## 本阶段范围

- 编辑行程项时间、停留时长和说明；添加餐饮、休息、自由活动等活动。
- 删除、排序、跨天移动行程项；增删行程天数并同步 `brief.day_count` 与日期。
- 修改相邻行程项间的交通方式；切换后清除旧路线数值，除非已有对应模式的真实路线事实。
- 每次确认编辑后用现有 `saveTravelTripDocumentV2` 和 `expected_revision` 自动保存；显示成功、失败和版本冲突；保存成功后可恢复前一 Revision。
- 桌面与手机均可操作；保持地图/时间轴选中状态同步及窄屏布局。
- 保留锁定项、固定出发时间、文档模型校验、身份授权、租户隔离和幂等契约。

## 边界

- 不修改正式行程前不得展示保存成功；CAS 冲突时不得用旧快照覆盖新版本。
- 不伪造 POI 坐标、路程、耗时、价格或 Provider 查询结果。
- 不重写旅游 Agent，不添加无必要的 LLM 调用，不恢复 V1 历史或存储。
- 自然语言 AI 改行程、真实地点搜索/替换与首页模板空数据治理不在本阶段提交；完成结构化编辑后再按 README 和现有 Provider 契约处理。

## 验收标准

- 工作台真实编辑会产生新的 V2 Revision；撤销会追加恢复 Revision，不回退版本号。
- 锁定/固定项边界、CAS 冲突、验证失败和保存失败均不会伪装成功或覆盖正式内容。
- 编辑项可在桌面与手机使用，浏览器刷新后仍以服务器返回的正式 Revision 为准。
- 定向测试、类型检查和必要构建实际通过，命令与剩余风险记录在 [PROGRESS.md](PROGRESS.md)。
