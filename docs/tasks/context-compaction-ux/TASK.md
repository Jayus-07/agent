# TASK：三端上下文压缩状态与质量验收

## 目标

让企业助手、智能客服和旅游助手准确显示上下文裁剪/摘要的实际状态，并验证 L5 摘要不会被 UI 误报、跨请求串流或丢失重要业务约束。

## 范围

- 从现有 Context Budget Manager 发出 L5 摘要开始、完成/延后状态。
- 主 Chat 与旅游 V2 SSE 只传递安全元数据，按可信产品、租户、用户、会话和请求隔离。
- 三端消费端显示开始、完成、回退和未确认状态；终态后不残留“进行中”。
- 扩充 Travel/Customer Service 的压缩保真评测样本，并按现有评测契约执行定向验收。
- 对照 OpenAI Responses API 的服务端压缩模式做设计参考；阈值、状态文案与触发策略以本项目实现为准。

## 边界

- 不更换供应商、模型角色或 L5 提示词，不改生产模型配置。
- 不读取、迁移或删除用户/业务数据；真实模型评测只能使用明确标记的合成测试会话。
- 不把问题原文、摘要正文、用户标识或租户标识放进 SSE 状态事件。
- 未经用户确认不提交、推送、合并或部署到云端服务器。

## 验收条件

1. L5 开始事件只能在摘要任务真实启动后发送；结束状态对应实际采用、回退或下一轮生效结果。
2. Context event 的作用域隔离、字段 allowlist 和 SSE 序号顺序有针对性验证。
3. 企业、客服、旅游三端的 reducer/UI 对开始、完成、回退、未确认状态一致；done/error/paused 等终态均清理 pending 状态。
4. 前端生产构建通过，相关后端和前端定向用例通过；三个空态页面无控制台错误。
5. 在合成会话上运行受限的真实 L5 评测，记录事实/约束保留结果、供应商调用和测试数据清理情况；若未执行，明确保持 `UNVERIFIED`。
