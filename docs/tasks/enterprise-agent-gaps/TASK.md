# 企业 Agent 项目全范围缺口整改

## 目标

依据当前代码、配置、迁移、CI、文档和实际运行证据，持续补齐企业 Agent 项目标准中的缺口。每个独立任务必须有定向验证和独立 PR；未运行真实模型、Provider、部署或端到端链路时，不得把离线契约通过写成 Live 质量或上线验收通过。

## 范围

- 对齐实际能力与评估结论，优先修复 Planner 完整 Plan 评分、样本有效性、输出授权校验和降级分类。
- 分模块检查 Planner、客服、RAG、SQL、旅游、E2E、记忆、多 Agent/办公等 Golden、Live、恢复和发布门禁；复用现有 Runner、Registry、Workflow、权限与审批能力。
- 验证超时、重试、降级、幂等、断点恢复、SSE 断开、租户/资源权限、并发与任务调度边界。
- 补齐模型、Prompt、Tool、数据集、Commit、环境、Trace、Token 与成本归因，以及 BadCase 分类回流。
- 对照 Python、LLM、后端知识清单核实现有 Demo；缺少时建立可单独运行的最小验证 Demo。
- 更新与代码冲突的现行文档，维护已完成、未完成、证据、修复方式、风险和下一步清单。
- 最终准备本任务 Worktree 的构建、健康检查、回滚和发布验收；离线限制解除前，真实模型与生产发布保持未验收。

## 验收条件

- 所有结论由当前代码、配置、测试、Live 报告、PR/CI 或运行健康证据支撑，并明确证据等级与环境。
- 各项通过正确的状态类别记录：质量错误为 `FAIL`；数据、Provider、预算、运行环境或证据缺失为 `INVALID/BLOCKED/UNVERIFIED`。
- 权限、副作用、状态恢复和调度变更覆盖相应边界；安全与恢复问题不能被平均通过率掩盖。
- 每个独立任务从最新 `main` 的专用 Worktree 完成、定向验证、提交并经 PR 合并；不得整体提交旧的脏 Worktree。
- 后端变更在本任务 Worktree 构建受影响服务并验证健康身份；共享栈资源不足时记录 `UNVERIFIED` 和可执行的下一步，不误报部署。
- 总任务清单中没有未解释的缺项、未验证项或发布阻断项。

## 任务顺序

1. Planner 输出契约、完整 Plan 评测、降级样本和 Run Validity。
2. 核对检查点启用策略及需要图级恢复的链路，修正文档或实现。
3. 按模块补齐 Live 入口、真实来源标记、错误/跳过有效性和 Release Gate。
4. 补齐可靠性、权限隔离、断点恢复、SSE、并发/调度和人工确认验证。
5. 补齐观测、版本归因、评测结果发布、成本和 BadCase 迭代机制。
6. 对照学习清单完成缺失 Demo；最后执行安全的构建、部署健康及上线验收。
