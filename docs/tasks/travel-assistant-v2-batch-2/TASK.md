# 旅游助手 V2 Batch 2 验收

## 目标

完成 Batch 2 的真实 API 与浏览器验收，记录可复核证据、与参考设计的差异及仍未接通的功能。验收报告后暂停，等待用户确认；不得自行开始 Batch 3。

## 范围

- 核查 3220 预览、认证刷新、前端代理、APISIX 与后端权限链路，修复 V2 真实 API/SSE 调用问题。
- 使用现有登录态验证首页、模板、聊天、桌面工作台、手机行程，以及酒店、美食和动车查询。
- 确认行程保存、资源归属和租户隔离；查询只读，只有用户明确选择后才写行程。
- 按参考 README 与三张设计图记录页面差异、可操作功能和未接后端功能；保存 1440px 桌面与 390px 手机截图。
- 运行相关定向测试、类型检查和生产构建，并如实记录环境限制。

## 约束

- 不恢复旧版旅游页面数据或旧版历史，不用演示数据冒充真实保存。
- 不绕过认证、资源授权或租户隔离；保存失败不得显示成功或改动正式行程。
- 酒店商户结果不代表房态或价格；TRAIN_MCP 不可用时不得展示模拟车次。
- 不重写旅游 Agent、不增加无必要的 LLM 调用、不建立第二套行程版本系统。
- 只在用户明确批准后替换共享服务；已批准范围仅为 `agent-app-1`。
- 本任务结束后等待用户确认，不启动 Batch 3。

## 验收标准

- 登录态下 V2 API 可真实读取和保存用户行程；未登录请求仍受认证保护。
- 浏览器覆盖目标页面与三类查询，并将成功、无结果、Provider 不可用、网络错误按实际证据区分。
- 两张截图为真实 V2 页面，尺寸分别为 1440×1000 和 390×844。
- 参考设计差异、未接功能、测试命令及未验证限制均记录在 [PROGRESS.md](PROGRESS.md)。
- 不把未实测项目写成通过；完成 Batch 2 报告后暂停。
