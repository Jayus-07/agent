# 部署清单

> 每次发版/换环境时按序核对。✅ 为一次性初始化步骤，🔁 为每次发版步骤。
> 命令速查见 [命令文档.md](命令文档.md)，架构细节见 [docs/architecture-overview.md](docs/architecture-overview.md)。

## 0. 部署方式速选

| | 方式 A：本地开发 | 方式 B：Docker 完整栈 |
|---|---|---|
| 适用 | 日常开发调试（改代码热重载） | 发版 / 完整链路验证（APISIX 网关 + 微服务） |
| 启动 | `start_py.bat` + `start_frontend.bat`（见 §3.2） | `docker compose up -d --build` |
| 依赖 | 本机 Python/Node/PostgreSQL + **apisix/app/redis 容器** | 仅 Docker Desktop |
| RAG | 进程内加载（`RAG_MODE=local` 默认） | 独立 rag-service，app 走远端代理 |
| Java 服务 | — | 已退役移出 compose（SCG 由 APISIX 替代，2026-09-15 起） |

> ⚠️ **前端 dev 默认走网关**（2026-09-16 起）：rewrite 目标是 APISIX `127.0.0.1:9080`，
> 网关 enforce 模式验签 Bearer 后注入身份头，后端 `IDENTITY_SOURCE=header` 只认身份头。
> 本地开发前先 `docker compose up -d apisix app redis`；确需绕过网关直连后端调试：
> `API_URL=http://localhost:8000 npx next dev`（此时 chat 身份一律 guest）。

端口总览（避免冲突）：

| 端口 | 服务 | 说明 |
|---|---|---|
| 9080 | APISIX 网关 | 统一入口（仅绑 127.0.0.1）：gateway-auth 验签/黑名单/限流 + 身份头注入 |
| 3100 | 用户端前端 dev（frontend/） | 仅本地开发 |
| 3200 | 管理端前端 dev（frontend-admin/） | 仅本地开发 |
| 8000 | app（FastAPI AI 服务） | `/docs` Swagger、`/health`、`/metrics`；仅绑 127.0.0.1 |
| 8090 | rag-service | 仅绑 `127.0.0.1`，`/healthz` + `/readyz` |
| 8091 | mcp-service | 仅绑 `127.0.0.1`，标准 MCP 协议 |
| 5432 | PostgreSQL | 本地开发用本机 18；容器栈**不对外暴露** |
| 5433 | obs-postgres | 可观测性分析库（独立栈，可选） |
| 6379 | Redis | 容器栈；本地按 `.env` 的 `REDIS_ENABLED` |
| 9094 | Kafka 外部监听器 | `--profile java-loop`，默认不启动 |
| 9090 / 3001 | Prometheus / Grafana | `--profile observability`（可选） |
| 11434 | Ollama | 可选（`--profile local-llm`） |

## 1. 环境要求

- [ ] **本地开发**：Python 3.11+（项目用 `.venv`）+ Node.js 18+ + 本机 PostgreSQL 18（服务名 `postgresql-x64-18`）
- [ ] **容器部署**：Docker Desktop（镜像内为 Python 3.10-slim，注意本地与容器 Python 版本差异）
- [ ] **本地调试 Java 代码**（可选）：系统默认 JDK 1.8，构建 Java 工程用 `scripts/mvn17.ps1`（PowerShell）/ `scripts/mvn17.sh`（Git Bash）临时切 JDK 17

## 2. 环境变量（.env）

项目根 `.env`，缺必填项时后端 **fail-fast 直接起不来**：

- [ ] ✅ 必填（两种方式）：
  - PG 连接：`PGHOST` / `PGPORT` / `PGDATABASE`（记忆库，读写）
  - LLM：`DEEPSEEK_API_KEY`、`LLM_MODEL`
- [ ] ✅ 容器部署额外必填：`PGPASSWORD`、`PG_READONLY_PASSWORD`（compose 无默认弱密码，缺失 `docker compose up` 直接报错）
- [ ] 认证链路（2026-09-16 起，网关与后端配套）：
  - `JWT_SECRET`（≥32 字节）：APISIX 验签与后端签发同源；轮换时旧值设 `JWT_SECRET_PREVIOUS`
  - `GATEWAY_AUTH_MODE`：默认 `enforce`（fail-closed）；灰度观测才显式设 `shadow`
  - `IDENTITY_SOURCE`：默认 `header`（只认网关注入身份头）；生产禁 `legacy`（启动校验拒绝）
- [ ] 常用可选（按需核对）：
  - 业务库只读账号：`BUSINESS_PGDATABASE` / `PG_READONLY_USER` / `PG_READONLY_PASSWORD`（SQL Agent 查询走只读账号）
  - `API_KEY`：未配置时业务端点 fail-closed 拒绝服务；容器 mcp-service 同样用它鉴权
  - `REDIS_ENABLED` / `REDIS_URL`：本地开发启用时需本机或容器 Redis
  - `EMBEDDING_MODEL_PATH` / `RERANKER_MODEL_PATH`：默认 BGE 系列，模型缓存落 `.cache/`
  - `RAG_MODE` / `RAG_SERVICE_URL`：本地默认 `local`（进程内）；容器 compose 已配好 `remote`，无需手改
  - Kafka / WhatsApp / DashScope 等：容器栈由 compose 注入，本地不配即关闭
- [ ] 🔁 新增环境变量需同步三处：`.env` / `docker-compose.yml` / CI

## 3. 方式 A：本地开发（Windows 宿主机）

### 3.1 ✅ 首次初始化

```powershell
# 1. Python 虚拟环境 + 依赖
python -m venv .venv
.venv\Scripts\pip install -r requirements-lock.txt

# 2. 数据库迁移（见 §5，先跑记忆库）

# 3. 前端依赖（用户端 + 管理端）
cd frontend && npm install
cd ../frontend-admin && npm install
```

### 3.2 日常启动 / 停止

一键脚本（推荐，双击即可）：

| 操作 | 命令 |
|---|---|
| 启动后端 :8000（uvicorn --reload） | `.\start_py.bat`（`stop_py.bat` / `restart_py.bat` 同理） |
| 启动用户端前端 :3100 | `.\start_frontend.bat`（停止 `.\stop_frontend.bat`） |
| 启动管理端前端 :3200 | `.\start_frontend_admin.bat`（停止 `.\stop_frontend_admin.bat`） |
| 拉起前端依赖容器（网关 + 后端 + 缓存） | `docker compose up -d apisix app redis` |

> **请求链路**：前端 rewrite → APISIX:9080（验签 Bearer / Redis 黑名单 / 限流）→
> 注入 `X-User-Id` 等身份头 → app（`IDENTITY_SOURCE=header` 只认头）。
> 本地 dev 必须先起 apisix 容器，否则前端所有 `/api/*` 请求失败。
> 改后端代码走容器时：`docker compose up -d --build app rag-service mcp-service`。

手动启动（等价命令）：

```powershell
# 后端（--app-dir backend 或先 cd backend，注意模块路径是 app.server:app）
.\.venv\Scripts\python.exe -m uvicorn app.server:app --app-dir backend --host 127.0.0.1 --port 8000 --reload

# 前端开发（用户端 :3100 / 管理端 :3200）
cd frontend && npx next dev -p 3100
cd frontend-admin && npx next dev -p 3200

# 前端生产
npx next build && npx next start -p 3100
```

- 本地 RAG 为进程内模式（`RAG_MODE` 默认 `local`），首次启动预热加载 embedding + 索引
- 前端 `/api/*` 转发到 `API_URL`（next.config.js 默认 `http://127.0.0.1:9080` 网关），
  绕过网关直连后端调试时 `API_URL=http://localhost:8000 npx next dev`

### 3.3 🔁 启动确认

- [ ] 预热日志出现 `[MultiAgent] 预热完毕，就绪`（Router / RAG 预热失败只告警不阻断）
- [ ] `GET http://localhost:8000/health` 返回正常
- [ ] 打开 `http://localhost:8000/docs` 能看到 Swagger

## 4. 方式 B：Docker 完整栈（微服务模式）

### 4.1 启动

```bash
docker compose up -d --build    # 首次或代码有变更时加 --build
docker compose logs -f app      # 跟踪应用日志
docker compose down             # 停止
```

### 4.2 服务清单（compose 定义 10 个服务，prometheus/grafana 属 observability profile）

| 服务 | 端口 | 要点 |
|---|---|---|
| apisix | 9080 | APISIX 统一入口（standalone 声明式 `apisix/apisix.yaml`，改完 `restart apisix` 生效）：gateway-auth 验签/黑名单 + 限流 + 身份头注入 |
| app | 8000 | Python AI 服务（RAG/Agent/LLM）；`RAG_MODE=remote` 走 rag-service |
| rag-service | 8090 | RAG 独立服务，独占 embedding + Chroma + BM25 索引；与 app 共享 `app_data` / `app_cache` 卷 |
| mcp-service | 8091 | 标准 MCP 协议（供 Claude/Cursor 等），RAG 同样代理 rag-service，不重复加载索引 |
| postgres | — | pgvector:pg16，不对外暴露（本地调试见 compose 内注释） |
| kafka | 9094 | KRaft 单节点，`--profile java-loop`（默认不启动） |
| redis | 6379 | 缓存/限流/黑名单只读（`auth:blacklist:*`） |
| ollama | 11434 | 可选本地 LLM：`docker compose --profile local-llm up -d` |
| prometheus / grafana | 9090 / 3001 | `--profile observability`（可选） |

### 4.3 ✅ 首次启动行为（重点）

- [ ] **数据库自动初始化**：`docker/init-dbs.sh` 仅在数据卷为空时执行一次——建 `agent_business` 库（schema + 种子 + 加固 + 只读角色）+ 初始化 `agent_memory`（schema + 种子），全部幂等
  - ⚠️ 只读角色 `004_readonly_role.sql` 里是 dev 默认密码，生产环境启动后立即 `ALTER ROLE` 修改
- [ ] **rag-service 首次全量索引同步可能数十分钟**：`/readyz` 就绪前 app 的 `/ask` 返回 503，属正常；看进度用 `docker compose logs -f rag-service`，就绪判断 `curl http://127.0.0.1:8090/readyz`
- [ ] 镜像构建：Python 双阶段（builder 编译 / runtime 最小化，非 root）；Java 在容器内 Maven 多阶段构建，**不需要本地装 JDK 17**

### 4.4 常用运维

```bash
docker compose ps                                    # 服务状态
docker compose logs -f rag-service                   # 单服务日志
docker compose restart app                           # 重启单个服务
docker compose exec postgres psql -U postgres -d agent_memory   # 进数据库
docker compose down -v                               # ⚠️ 连数据卷一起删（含 PG/Kafka/索引数据）
```

## 5. 数据库迁移

迁移现状（P1-13 起）：**alembic 统一管理**，旧的 `backend/sql/migrations/00N_*.sql` 已冻结为基线。
权威指南见 [docs/alembic-migrations.md](docs/alembic-migrations.md)。

| 迁移线 | 目标库 | 说明 |
|---|---|---|
| `business` | agent_business（业务数仓） | 订单等，应用走只读账号 |
| `memory` | agent_memory（会话/记忆） | 会话标题/摘要/L1-L3 记忆 |

- [ ] 🔁 推荐（本地开发，仓库根执行，连接串由 `.env` 驱动）：

```bash
alembic -c alembic.ini -n business upgrade head
alembic -c alembic.ini -n memory   upgrade head
```

- [ ] 容器部署：首次启动由 `init-dbs.sh` 自动完成基线；后续增量迁移进容器执行或 `docker exec`
- [ ] 手动 SQL 方式（与 alembic 基线等价，老环境仍在用）：

```bash
psql -h localhost -U postgres -d agent_memory -f backend/memory/migrations/001_init.sql
psql -h localhost -U postgres -d agent_memory -f backend/memory/migrations/002_session_title.sql
```

  - ⚠️ 不跑 002 会导致后端报 `UndefinedColumn: title`（ORM SELECT 带 title），接口全部 500
  - 002 为 2026-09-11 新增：`chat_sessions` 增加 `title` 字段（标题与 L2 摘要分字段），含旧数据回填；幂等可重复执行
- [ ] 旧库无版本表时先打基线标记：`alembic -c alembic.ini -n memory stamp 0001`（不重放 SQL）

## 8. 故障排查

| 症状 | 处理 |
|---|---|
| 端口 8000/3100/3200 占用 | `.\stop_py.bat` / `.\stop_frontend.bat` / `.\stop_frontend_admin.bat`，或 `netstat -ano \| findstr :8000` 后 `taskkill /F /PID <pid> /T` |
| 后端起不来（fail-fast） | 检查 `.env` 必填项（§2），缺失时启动直接报错退出 |
| 网关 401 `未认证：<reason>` | enforce 模式的正常拒绝；排查 `JWT_SECRET`（≥32 字节、与后端同源）、token 是否过期/被拉黑，reason 含 `blacklist` 看 Redis |
| chat 身份全是 guest | 前端没走网关（rewrite 直连 8000）或网关是 shadow 模式不注入头：确认 rewrite 目标 9080 + `GATEWAY_AUTH_MODE=enforce` + `IDENTITY_SOURCE=header` |
| 接口全部 500 + `UndefinedColumn: title` | 记忆库没跑 002 迁移，见 §5 |
| 容器 `/ask` 503 | rag-service 未就绪（首次全量同步数十分钟），看 `/readyz` 和日志 |
| `PGPASSWORD is required` | compose 启动时 `.env` 未加载或变量缺失 |

## 9. 已知注意事项

- PostgreSQL 认证为 scram-sha-256，改 `pg_hba.conf` 后需重启服务（`Restart-Service` 需管理员权限）
- Windows 本机编译的 `.pyd` / `.dll` 不能进 Linux 容器，依赖必须在容器内重装（Dockerfile 已处理，勿从宿主机 COPY 编译产物）
- `chat_sessions.summary` 只存 L2 自动摘要，标题一律走 `title` 字段；不要再用 rename 写 summary
- 会话消息持久化唯一入口是后端 `end_turn`；前端不要再调 `/chat/messages` 双写（历史教训见 git log 2026-09-11）
- 容器栈中 PostgreSQL 默认不暴露端口；本地调试需取消 compose 中 `postgres.ports` 注释（仅绑 127.0.0.1）
